## Purpose

多标的多日组合做T回测能力：把 Agent 选股建仓（t_build 规则）纳入历史回测，一次验证"选哪些标的建仓 → 各自做T回转 → 组合收益"，并提供前端页面配置发起与查看报告。

## ADDED Requirements

### Requirement: 组合回测任务
系统 SHALL 支持创建多标的多日组合回测任务。任务参数 MUST 包含：候选标的列表（symbols，空则使用做T候选池 candidate 层）、起止日期、监控条件（条件模板或表达式）、建仓开关（build_mode: on/off）、组合净值、单标的仓位上限与底仓参数、review_mode。任务状态与并发控制 SHALL 复用现有 t_backtest_tasks 机制。

#### Scenario: 创建组合回测任务
- **WHEN** 用户提交组合回测任务（symbols=[A,B,C]，2026-07-01~07-31，build_mode=on，净值 20 万）
- **THEN** 任务创建为 pending，worker 领取执行；完成后状态 completed，结果含组合与每标的分项

#### Scenario: 候选池缺省
- **WHEN** 任务未提供 symbols
- **THEN** 系统取做T候选池（t_pool candidate 层，可T质量打分达标标的）作为候选列表，并在报告中注明来源

### Requirement: 建仓模拟（规则历史化，防前视）
系统 SHALL 在回测窗口期初对每个候选标的执行建仓规则模拟：复用 `build_score`（可T质量+趋势+风险惩罚）与 `trend_gate` 判定，达标者按 `build_sizing` 规则（单笔 ≤ 净值 5%、总底仓 ≤ 净值 55%）分配建仓资金与股数，建仓价 = 窗口首日开盘价。建仓规则 SHALL 只使用回测日期截止（T-1 及以前）的历史日线，MUST NOT 引用未来数据。被否标的 MUST 记录否决原因（打分不足/趋势闸门/资金上限）。

#### Scenario: 达标标的建仓
- **WHEN** 候选标的 A 的 build_score ≥ 0.55 且 trend_gate 通过，且组合资金未超上限
- **THEN** 该标的以窗口首日开盘价建底仓，记入组合账本，进入做T阶段

#### Scenario: 建仓防前视
- **WHEN** 回测窗口 T 日评估建仓
- **THEN** build_score/trend_gate 的日线输入只含 trade_date < T 的数据

#### Scenario: 资金上限约束
- **WHEN** 已分配建仓资金达到净值 55% 上限
- **THEN** 后续候选标的建仓被拒绝并记录"资金上限"，即使打分达标

### Requirement: 组合做T回放
系统 SHALL 对每个已建仓标的执行多日做T回放（复用单标的 TBacktestEngine：m5 tick 触发 → 复核 → 撮合 → T+0 闭环），条件缺省时按建仓成本自动生成（对齐 `auto_gen_conditions_for_build`：低吸=成本×0.98 / 复归+0.4% / 高抛+1.5% / 止损-3%）。组合权益 SHALL 每日汇总（现金 + 各标的总持仓市值），组合内标的的做T互不影响。

#### Scenario: 建仓后自动生成做T条件
- **WHEN** 标的建仓成功且任务未显式提供条件
- **THEN** 引擎按建仓成本生成低吸/高抛条件并参与做T回放

#### Scenario: 组合权益汇总
- **WHEN** 回放每日收盘
- **THEN** 组合权益 = 现金 + Σ(各标的持仓 × 收盘价)，落每日快照

### Requirement: 组合报告
系统 SHALL 生成组合报告：组合级指标（总收益/胜率/最大回撤/触发与成交统计/买入持有基准对比）+ 每标的明细（是否建仓/建仓价/成本/做T盈亏/触发统计/否决原因）+ 建仓决策审计（打分/趋势/资金分配）。报告 MUST 继续标注做T口径差异声明（m5 vs 30s、量比口径、regime 近似、成交假设），并新增建仓口径说明（建仓价=首日开盘、规则模拟 Agent 决策）。

#### Scenario: 报告含组合与分项
- **WHEN** 组合回测完成
- **THEN** 报告包含组合总览与每标的明细，被否标的列出否决原因

### Requirement: 前端回测页面
系统 SHALL 提供做T回测页面（路由 /t-backtest）：配置表单（候选标的多选/手填/自动候选池、日期范围、条件模板、建仓开关、净值、review_mode）、任务列表（状态/进度/指标摘要）、任务报告视图（指标卡、权益曲线、事件流、成交与建仓明细）。页面 SHALL 通过 t_backtest API 创建/查询/取消任务。

#### Scenario: 页面发起组合回测
- **WHEN** 用户在页面选择候选标的与参数并提交
- **THEN** 任务被创建，列表显示运行中状态；完成后可查看组合指标卡与权益曲线

#### Scenario: 候选池选择
- **WHEN** 用户选择"自动候选池"
- **THEN** 页面从候选池查询接口加载可选标的（含可T质量分），供确认后提交
