## Context

当前系统有 `concept-fund-flow`（概念板块排行）和 `check_entry_filters`（单股深度分析），但缺少跨行业的龙头股横向对比视图。110 个申万一级行业，每行业取市值前 3 名候选（约 330 只），通过五维加权评分模型 → 全排行榜，5 分钟刷新，帮助快速识别"哪个行业的龙头正在走强"。

数据基础：
- `stock_pool.db` 已有 `stock_pool` 表，含 `symbol`/`name`/`industry`（申万一级）/`market_cap`/`is_st`，市值数据已修复（5526/5547 只有效市值）
- Tushare `stk_factor_pro` 支持批量 ts_code 查询，返回 MA/MACD/RSI/ADX 等 200+ 技术因子
- Tushare `daily` 支持批量 ts_code 查询，返回 OHLCV 日线数据
- 腾讯 `qt.gtimg.cn` 支持多股同时查询，返回实时价格/涨跌幅/换手率
- 东方财富实时资金流向接口（已有 `get_moneyflow` 端点）返回主力净流入/净占比/5日累计
- 前端已有 Tailwind CSS + Recharts + Zustand 技术栈

## Goals / Non-Goals

**Goals:**
- 后端：`GET /api/v1/market/industry-leaderboard` 端点，全量 3 次批量 API 调用 + Top10 10 次实时 HTTP 调用
- 评分：五维加权模型（趋势综合/资金持续性/量价配合/行业相对强度/价格残差），两轮评分（全量 4 维 → Top10 补资金维）
- 硬过滤：排除 ST/退市、日成交额 < 1 亿、一字板涨停
- 缓存：60 秒服务端缓存（含资金数据）
- 前端：排行表格页面，行业筛选 + 排序切换 + 5 分钟自动刷新

**Non-Goals:**
- 不接入盘中实时 KDJ/RSI 估算（后续迭代，首版用昨日确认值）
- 不覆盖概念板块排行（已有 `concept-fund-flow`）
- 不提供个股深度分析（已有 `check_entry_filters`）
- 不做服务端推送（WebSocket），前端轮询即可

## Decisions

### Decision 1: 龙头识别 — 市值前 3

**选择**：每个申万一级行业取 `market_cap` 字段最大的 3 只股票作为候选。

**理由**：(1) 没有可靠的"龙头"标签数据。(2) 市值排名是客观可复现的标准。(3) 取 3 只候选而非 1 只，让评分模型自己挑出最强的那只。(4) 同一行业可能 3 只都进前 20，也可能一只都进不了，反映了行业轮动的真实状态。

### Decision 2: 评分模型 — 五维加权 + 两轮评分 + 市场状态自适应

**选择**：

#### 核心维度（趋势市 / 震荡市双权重）：

| 维度 | 趋势市权重 | 震荡市权重 | 计算范围 |
|------|:---:|:---:|:---:|
| 趋势综合 (Trend Composite) | 28% | 22% | 全量 330 只 |
| 量价配合 (Volume-Price) | 15% | 18% | 全量 330 只 |
| 行业相对强度 (Industry Relative Strength) | 17% | 20% | 全量 330 只 |
| 价格残差 (Price Residual) | 15% | 18% | 全量 330 只 |
| 资金持续性 (Capital Persistence) | 25% | 22% | **仅 Top10** |

**两轮评分流程**：

```
Round 1: 全量 4 维评分（~330 只，3 次批量 API）
  ├─ 趋势综合 + 量价配合 + 行业相对强度 + 价格残差
  ├─ 资金维度临时取中性分（满分 × 50%）
  └─ 排出 Top 10

Round 2: Top10 补资金维（10 只，10 次实时 HTTP）
  ├─ 东方财富实时接口获取 main_net / main_pct / d5_main_net
  ├─ 计算资金持续性得分
  └─ Top10 重排序（排名 11+ 不变）

非 Top10 股票：资金维度固定为满分 × 50%（中性分），不影响全量排序公平性
```

#### 趋势综合 (28/22 分)：

| 子指标 | 趋势市 | 震荡市 | 评分逻辑 |
|--------|:---:|:---:|------|
| MA 多空排列层级 (5/10/20/60) | 0-10 | 0-8 | 4线多头=满分，3线=80%，2线=50%，死叉=0 |
| MACD 柱状体力度 + 金叉位置 | 0-10 | 0-7 | DIF>DEA 且柱状体放大=满分，DIF<DEA=0-3 |
| ADX 趋势强度 | 0-8 | 0-7 | ADX>40=满分，25-40=线性 |

趋势市额外加成：ADX>25 且 MACD 金叉≤5日 → +2 趋势启动加分
震荡市折扣：ADX<15 → 趋势综合总分 ×0.6；ADX 15-20 → ×0.8

#### 资金持续性 (25/22 分，仅 Top10)：

| 子指标 | 趋势市 | 震荡市 | 评分逻辑 |
|--------|:---:|:---:|------|
| 当日主力净流入 / 流通市值 | 0-10 | 0-8 | 市值归一化，>0.3%=满分 |
| 主力净占比 | 0-8 | 0-7 | main_pct>10%=满分，负值=0 |
| 5日累计主力净流入 / 流通市值 | 0-7 | 0-7 | >0.5%=满分 |

数据源：东方财富实时接口（已有 `get_moneyflow` 端点），字段 `main_net` / `main_pct` / `d5_main_net`

#### 量价配合 (15/18 分)：

| 子指标 | 趋势市 | 震荡市 | 评分逻辑 |
|--------|:---:|:---:|------|
| 量价趋势匹配度 | 0-7 | 0-8 | 近10日上涨日均量 / 下跌日均量，>1.5=满分 |
| 突破放量比 | 0-5 | 0-6 | 突破关键均线日成交量 / 20日均量，>2.0=满分 |
| 缩量回调健康度 | 0-3 | 0-4 | 回调日成交量 / 20日均量，<0.7=满分 |

#### 行业相对强度 (17/20 分)：

| 子指标 | 趋势市 | 震荡市 | 评分逻辑 |
|--------|:---:|:---:|------|
| 相对行业超额收益（1日） | 0-7 | 0-7 | (个股涨跌幅 - 同行业候选股均涨跌幅)，>2%=满分 |
| 相对行业超额收益（5日累计） | 0-6 | 0-7 | 5日累计超额，>5%=满分 |
| 个股成交额 / 行业候选股总成交额 | 0-4 | 0-6 | >50%=满分 |

v1 行业基准用候选股互比近似（同行业 3 只候选互相比较）；P1 增加夜间全量行业收益率预计算写入 DB。

#### 价格残差 (15/18 分)：

| 子指标 | 趋势市 | 震荡市 | 评分逻辑 |
|--------|:---:|:---:|------|
| MA20 乖离率（倒 U 型） | 0-6 | 0-8 | 趋势市 3-10%=满分，震荡市 2-8%=满分，>15%趋近0 |
| 相对行业超额涨幅（替代绝对涨幅） | 0-6 | 0-7 | 个股当日涨幅 - 同行业候选均涨幅，>2%=满分 |
| 非尾盘拉升 + 非竞价异动验证 | 0-3 | 0-3 | 14:55后涨幅贡献<30%总涨幅=满分 |

#### 市场状态判别（评分前执行）：

```
ADX > 25 且 MA5 > MA20 → 趋势市 (trending)
ADX < 20 → 震荡市 (ranging)
20 ≤ ADX ≤ 25 → 过渡态，权重取两种市场的均值
```

判别基于上证综指 `000001.SH` 的 ADX，而非单只股票。

#### 硬过滤层（评分前执行）：

| 条件 | 动作 |
|------|------|
| is_st=1 或已退市 | 排除 |
| 日成交额 < 1 亿 | 排除 |
| 一字板涨停（开盘价=最高价=收盘价且涨幅>9.5%） | 标记"不可交易" |
| PE(TTM) > 200 | 标记"高估值风险" |

#### 惩罚系数（评分后执行）：

| 条件 | 惩罚 |
|------|:---:|
| 任一维度得分 < 该维度满分 20% | 总分 × 0.7 |
| RSI6 > 90 且乖离率 > 15% | 标记"过热预警"，价格残差扣 3 分 |

**设计原则**：
- 删除了 KDJ_K（与 RSI6 相关系数 > 0.8，冗余）
- 合并了 MA 多头排列 + MACD 方向 → "趋势综合"（消除同类因子重复计分）
- 当日涨幅从 15 分砍到 6 分且改为"相对行业超额涨幅"（消除单日噪声压倒趋势信号的结构性颠倒）
- 新增量价配合维度（趋势交易的核心信条——量价配合）
- 新增行业相对强度维度（"龙头排行"必须有领涨性指标）
- 资金维度仅计算 Top10，避免 moneyflow_dc 不支持批量查询的问题

### Decision 3: 数据获取 — 两轮架构

**Round 1 — 全量批量（3 次外部调用，~4 秒）**：

```
stock_pool.db (本地查询，<10ms)
  → 110 行业 × 3 候选 = ~330 只股票去重

腾讯 qt.gtimg.cn (1次HTTP)
  → 实时价格、涨跌幅、换手率、成交额

Tushare stk_factor_pro (1次API)
  → ts_code 批量逗号分隔，limit=候选股数量
  → fields: ma_qfq_5/10/20/60, macd_dif_qfq, macd_dea_qfq, macd_qfq,
            rsi_qfq_6, dmi_adx_qfq, dmi_pdi_qfq, dmi_mdi_qfq,
            close_qfq, pe_ttm, vol, amount, turnover_rate, volume_ratio

Tushare daily (1次API)
  → ts_code 批量逗号分隔，近20个交易日
  → fields: open, high, low, close, vol, amount, pct_chg
  → 用途：量价匹配度计算 + 行业候选均涨幅计算
```

**Round 2 — Top10 资金补算（10 次实时 HTTP，串行 ~3-5 秒）**：

```
东方财富实时资金接口 × 10（已有 get_moneyflow 端点）
  → 串行 HTTP 请求（逐只调用，避免触发反爬拦截）
  → 每只返回 main_net / main_pct / d5_main_net
  → 用途：资金持续性维度得分
```

总计：3 次批量 API（全量）+ 10 次实时 HTTP（Top10）。Tushare 调用仅 2 次（stk_factor_pro + daily），不受 1 req/s 限制影响。

**备选方案**：Tushare moneyflow_dc 批量获取——已否决，该接口不支持批量 ts_code 参数。

### Decision 4: 缓存策略

**选择**：后端 60 秒内存缓存 + 前端 5 分钟轮询。

- 服务端 `_leaderboard_cache: Dict[str, tuple]` — key 为当日日期 + 市场状态，value 为 (timestamp, response_dict)
- 60 秒 TTL：同一分钟内多个前端请求命中缓存
- 前端 `setInterval(fetchLeaderboard, 300000)` 每 5 分钟刷新
- 首次加载、手动刷新时跳过缓存走实时查询
- 资金数据缓存在排行榜缓存中，不独立维护（60 秒内 Top10 排名被冻结）

### Decision 5: 技术指标使用昨日确认值

**选择**：首版 MA/MACD/RSI/ADX 使用 Tushare stk_factor_pro 昨日盘后确认值。

**理由**：(1) stk_factor_pro 支持批量查询，330 只股票一次调用。(2) 盘中估算需逐股计算，延迟不可接受。(3) 对于 5 分钟级别排行，昨日确认值的精度足够——价格涨跌幅和资金流向是实时的，综合评分已能反映当前方向。

### Decision 6: 行业基准收益率

**选择**：v1 用候选股互比近似，P1 加夜间全量预计算。

- **v1**："行业收益率" = 同行业 3 只候选股的平均涨跌幅。零额外成本。
- **P1**：夜间调度任务从 `daily` 表拉全行业成分股涨跌幅均值写入 DB。

## Risks / Trade-offs

- **[Risk] Tushare 频率限制**：每轮刷新仅 2 次 Tushare 调用（stk_factor_pro + daily），5 分钟间隔 + 60 秒缓存，不受 1 req/s 限制
- **[Risk] 腾讯接口不可用**：价格/涨跌幅/换手率降级为 Tushare `daily` 表当日数据，标记 `data_source: "tushare"`
- **[Risk] 量价分析 daily 超时**：量价配合维度降级为仅用当日 `volume_ratio` 估算，标记 `volume_data: "degraded"`
- **[Risk] 东方财富接口不可用**：Top10 资金维度取中性分（满分×50%），标记 `capital_data: "unavailable"`
- **[Risk] 行业基准不准确（v1）**：候选股互比在小行业中样本不足。P1 夜间全量预计算解决
- **[Trade-off] 非 Top10 无资金分**：排行榜核心价值在前 10 名的精度，11 名以后资金中性分不影响"谁是最好的龙头"这个核心问题
