## Context

当前 `check_entry_filters` 的 Layer 3 超买过滤位于 `backend/app/api/indicator.py:2284-2358`，仅检查 RSI6 和 KDJ-J 两个指标，且阈值宽松（RSI6 正常上限 85，KDJ-J 正常上限 105），CCI 完全未纳入。2026-07-22 紫金矿业建仓时 RSI6=83.9/KDJ-J=102.8/CCI=250.2 三重极端超买，系统全部判为"正常"。

技术指标数据源来自 `get_technical` 接口（Tushare stk_factor_pro），已返回 CCI 字段（`cci`），无需新增数据拉取。

## Goals / Non-Goals

**Goals:**
- Layer 3 新增 CCI 超买过滤，设定分档阈值
- 收紧 RSI6 和 KDJ-J 阈值，消除"正常→禁止"之间的断崖
- 新增多指标共振检测：≥2 个指标处于警告或更高级别时，联合降级
- 保持 API 返回结构兼容（`LayerResult` 字段不变）

**Non-Goals:**
- 不修改 Layer 1（技术面）和 Layer 2（主力行为）
- 不调整硬拦截的豁免逻辑
- 不修改 `candidate_pool_monitor.py` 等下游消费者
- 不在本变更中引入 CCI 超卖判定（超卖仅影响卖出，不影响入场过滤）

## Decisions

### 1. 新阈值表

| 指标 | ✅ 正常 | ⚠️ 仅试探仓 | 🚫 禁止建仓 | 🔴 硬拦截 |
|------|---------|-------------|-------------|-----------|
| RSI6 | < 75 (原 < 85) | 75-85 (原 85-90) | 85-95 (原 90-95) | ≥ 95 (不变) |
| KDJ-J | < 95 (原 < 105) | 95-105 (原 105-110) | 105-120 (原 110-120) | ≥ 120 (不变) |
| CCI | < 150 (新增) | 150-200 (新增) | 200-300 (新增) | ≥ 300 (新增) |

**理由**：RSI6>75 在 A 股历史上对应 3 日内回调概率显著升高；CCI>150 是加速末端的早期信号。硬拦截阈值保持不变（或新增），因为极值仍具有强禁止意义。

### 2. 共振检测算法

三个指标各有一个 severity 等级（0=正常, 1=仅试探仓, 2=禁止建仓, 3=硬拦截）：

- 取最高 severity 作为**基础判定**
- 若 ≥2 个指标 severity ≥ 1（警告及以上），**基础判定降一级**（如从"正常"→"仅试探仓"，"仅试探仓"→"禁止建仓"）
- 硬拦截（severity 3）不参与降级，始终阻塞

**理由**：紫金矿业 RSI6=83.9 和 KDJ-J=102.8 都在旧版"正常"区间内，但二者同时偏高应视为危险信号。共振检测让 Rule 在单个指标触线前就发出预警。

### 3. 实现方式

在 `indicator.py` 的 `check_entry_filters` 函数中重构 Layer 3 判定为一个独立函数 `_eval_overbought(rsi6, kdj_j, cci)`，返回 `LayerResult`。前端 tools.ts 和 API 响应模型不变。

**理由**：改动集中在单一文件中约 70 行代码，独立函数便于单元测试。下游仅消费 `LayerResult` 对象的 `passed`/`grade`/`downgrade_multiplier`，无需感知内部规则变化。

## Risks / Trade-offs

- **伪阳性增加**：阈值收紧后，更多标的会被标记为"仅试探仓"或"禁止"。这是预期行为——宁可错过机会也不在高位建仓。可通过回测验证
- **CCI 数据可用性**：Tushare `stk_factor_pro` 返回 CCI，盘后数据始终可用。盘中通过 `get_realtime_indicators` 获取时 CCI 为估算值，需在 Layer 3 响应中标注数据来源
- **阈值选择**：新阈值基于经验判断（紫金案例 + A 股波动特征），后续可通过回测优化具体数值
