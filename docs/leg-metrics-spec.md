# 腿度量规范（阶段 0「换尺子」的尺子本身）

> 目的：把"一次买卖动作怎么算、赢怎么定义、跟谁比、多少样本才算数"写成明文，
> 让后续所有兑现/退出机制（plan §5 阶段 1–3）在同一把尺子上比较。
> 脚本：`jobs/eval_leg_metrics.py`；产出：`docs/leg-metrics-baseline.md`（本尺子量出的基线表）。
> 起因：checklist **B7**——回测用"持 T+5 收盘"量做 T 腿得 47%，而生产**已实现卖出腿**是 63.6%，
> 口径不同 → 之前所有兑现层结论都不可比。

---

## 1 两把尺子（同时报，不混用）

| 尺子 | 定义 | 用途 | 数据 |
|---|---|---|---|
| **生产实际口径（主）** | 腿的**已实现盈亏**：`paper_trades.profit`（含费）÷ 该腿成本（FIFO 配出的买入加权价×数量） | 回答"我们实际做得怎么样" | PG `paper_trades` |
| **规则模拟口径（对照）** | 以**真实成交价**为入场价，按规则（持 T+5 / +3% 止盈 / −3% 止损）在日线上模拟离场 | 回答"换一条兑现规则会怎样"（阶段 1 的变体对照） | 日线（见 §4） |

> 老尺子（"买入后持 T+5 收盘"）**保留为对照**，但不得单独用来给机制下结论。

## 2 腿的定义（从流水配对）

1. **数据源**：PG `paper_trades`（账户 `t` / `stock` / `golden_pit`）。`golden_pit` = 黄金坑 DCA，**单列不混入**策略腿。
2. **剔除撤销**：`voided=1` 的行不入账本（生产 void 时会回滚持仓）。
3. **FIFO 配对**：按 `(account_id, symbol)` 分账本、`created_at` 升序；**卖出从最早的未平买入扣**。
4. **一条卖出 = 一条腿**；跨 lot 时合成一条，入场价 = 被扣 lot 的**加权成本**；`entry_date` = 被扣 lot 的 `trade_date`。
5. **未平腿**：买入没有对应卖出的 lot 单独列（`open_lots`），只做标记，不进已实现口径。
6. **`profit=0` 的卖出腿**：生产口径下这是"未平/等量换手/**手工平账**"，**不计入胜率**（与 blueprint §5.2 一致）。
   ⚠️ 但实测其中若干笔**从价格看是真亏损**（例：SH603678 08-28 买 48.51 → 08-31 卖 46.48 = −4.18%，DB 记 profit=0）
   → 明细留在 JSON 的 `flat_legs`，这是**生产尺子的已知盲区**（见 §7）。

## 3 腿型分类（四类，决定性规则）

| 腿型 | 判定 | 度量层级 |
|---|---|---|
| **做T低吸** | `account='t'`（做 T 专用账户，plan §10.6）的每一条卖出腿 | 腿级 |
| **低位埋伏** | `account='stock'` 且**卖出后无持仓**的回合 → 用**回合级**（首次买入 → 清仓/最新一根日线）度量 | 回合级 |
| **确认加仓** | 买入时**该标的已有持仓**（同账户）的加仓动作；度量 = 加仓价 → 回合结束（或 +5 日） | 动作级 |
| **逃顶/减仓** | 卖出后**仍有持仓**的部分减仓（只看卖出前已存在的持仓，不含之后新买的 lot） | 腿级 |

> 为什么"低位埋伏"必须用回合级：FIFO 下 stock 账户的仓位是**分批建→分批减**，
> 用腿级会把减仓动作全吃掉（实测腿级会归零）。回合级口径同时给出**区间收益 / 最大回撤 / 持有天数**，
> 与 blueprint §6 的主指标一一对应。

## 4 行情与基线

- **行情来源**（按优先级，全部本地缓存）：`data/bars_2026.csv.gz`（2026 股票日线，含 OHLC/额）→
  `data/mkt_bars_local.db`（2024-11→2025-12 股票）→ `.dsh-tmp/wolfbt/bt_pit/daily/*.json`（股票，仅 close/low/额）→
  `<cache>/etf_daily.json`（**ETF** 与缺失股票，走 `core/tushare_relay` 的 `fund_daily`）。
  ⚠️ 生产 PG `mkt_bars_daily` **不含 ETF**（实测 515880.SH 等 0 行）→ ETF 腿必须另取。
- **同主题同日基线**：该腿标的所属主题（`.dsh-tmp/wolfbt/bt_pit/theme_universe.json`）的**全部成分股**，
  在同一入场日**收盘**买入、持有到**同一窗口**（腿的 `exit_date`；无则 +5 日），等权平均。
  ETF 用脚本里的**代理主题映射**（`ETF_THEME`，宽基 ETF 无主题 → 不计入基线，覆盖率要报）。
- **超额 = 腿收益 − 同主题同日基线**；**绝对与超额两个口径都要给**（plan §5 阶段 0）。
- 口径差异（须知）：腿的入场是**盘中真实成交价**，基线的入场是**当日收盘**；两者不可完全对齐，但在同一时点上可比。

## 5 统计纪律

- **n < 100 只作探索**，不得写进验收（plan §9 L8）。
- **重叠样本**：同一时点的多条腿高度相关 → 关键结论必须给**块状 t**（按 ISO 周分块，块内先取均值再算 t），
  日度 t 只能作参考。脚本对每张表同时输出日度 t 与块状 t。
- **分段（H1/H2）**：按样本中位日切两段；变体要"两段都不劣"才允许进入接线（阶段 1 验收条件）。
- 主指标事前固定：**胜率 + 均值/中位 + 盈亏比**；其余（分位、最大回撤）标为副指标。

## 6 三个既有开关的复算口径

| 开关 | 复算口径 | 样本 | 结论（2026-09-13） |
|---|---|---|---|
| `WOLF_BOLL_MID_EXIT` | 顶部阶段（上证 120 日区间分位≥0.8）∧ 放量（额≥前日）∧ 收盘破 BOLL(20,2) 中轨 ∧ 浮盈>0 → **全止盈** | 428 触发腿（规则模拟） | 命中 43 笔；胜率 47.4%→50.0%（Δ+2.6pp）、均值 0.29%→0.29%（Δ0.00）、H1 1.19 / H2 −0.61 → **两段不一致，暂无增益证据** |
| `WOLF_WEEKEND_HEDGE` | 周五（持有窗口内）缩量（额<前 5 日均）∧ 未拉升（涨幅<+0.30%）→ **收盘减半、下周一收盘拿回**（未计成本） | 同上 | 命中 156 笔；胜率 47.4%→45.8%（Δ−1.6pp）、均值 0.29%→0.69%（Δ+0.40pp，块状 t=2.01，**H2 仅 +0.05**）→ **均值方向为正但两段不一致，且胜率下降** |
| `WOLF_CUSHION_CAP` | cap_mult = 1 + 0.5×累计已实现 / 本金；**只放宽上限** | 生产账户 | t: +2,828.5/200,000 → **1.0071**；stock: −2,538.6/250,000 → 0.9949 → 量级 <1%，**单笔口径无影响**，账户级增量需 cap 触顶才有，样本期内**无法判定** |

> 三个开关都是"已上线但未按尺子复验"（plan §5 阶段 0 交付物 3 / §10.5）。以上是**规则模拟**口径，
> 不是生产已实现口径——结论只到"没有证据支持它有效"，不足以判定有害（n 与分段都不够）。

## 7 已知数据缺陷（必须随结论一起读）

1. **`paper_trades.profit=0` 的卖出腿**：股票账户 8 笔，其中若干实为亏损平账（§2.6）→ 生产胜率被轻微高估。
2. **ETF 无 PG 行情**：ETF 腿的 T+5/规则模拟依赖 relay 拉取的 `fund_daily`（口径已比 PG 更全，但需注意复权）。
3. **样本极小**：策略腿 t=22 / stock=11（2026-08-23 → 09-11，~14 个交易日）→ 所有生产侧结论**只作探索**。
4. **旧尺子样本（428 腿）来自已删除的 `mainline_gate` 链**（`_bt_pit/trades.jsonl`，2025-07-10 → 2026-08-31）：
   仅作"口径可比参照"，**不代表当前方向层（结构池）选出的腿**。
5. **规则模拟用 legacy 口径**（TP 用 close、SL 用 low，沿用既有 `_bt_exit.py`）→ 为的是能复现 47%/53%/39%；
   若换更严格的日内口径，数字会变（阶段 1 需固定一种并声明）。
6. **`bt_pit/daily` 只有 close/low/额**：没有 open/high → BOLL 上轨类规则不可算，中轨（只用 close）可算。
7. **当日 14:30 价格用收盘代理**（周末避险）→ 会高估"减在半山腰"的收益，需在阶段 1 用 m5 复核（G6 覆盖待查）。

## 8 复现

```bash
# 本地跑（禁止在 512MB 生产容器内跑）
.venv/bin/python jobs/eval_leg_metrics.py --refresh     # 重拉 paper_trades / ETF 日线 / 上证
.venv/bin/python jobs/eval_leg_metrics.py               # 用缓存
# 输出：.dsh-tmp/wolfbt/legmetrics/eval_leg_metrics.json + docs/leg-metrics-baseline.md
```

依赖的本地数据（都不在 git 里，需从生产拉一次）：
- `paper_trades`：脚本内经进程内 SSH 隧道直读生产 PG（`.dsh-tmp/wolfbt/local_pg.py`）；
- 旧尺子样本：生产 `/opt/marcus-platform/data/_bt_pit/{trades.jsonl,theme_universe.json,daily/}` → `.dsh-tmp/wolfbt/bt_pit/`。
