# C2b 避险回补腿设计（wolf_hedge_refill）

> 状态：**已实现并上线**（2026-09-14）。代码：backend/app/services/wolf_hedge_refill.py（纯状态+判定）
> + t_monitor._check_hedge_refill()（执行）；单测 backend/tests/test_wolf_hedge_refill.py（8 项）。
> 关联：G9 周末/长假避险（狼大 2026-08-21，卖出腿在 t_monitor._check_weekend_hedge）。

## 1 为什么需要它（他的原话，四句）

| 原话 | 日期 | 对设计的要求 |
|---|---|---|
| 「…先把这两天T进去的仓位出来一半 防止周末出利空 **这样周一再拿回来**。」 | 2026-08-21 14:20 | 有卖就必须有**买回**，否则仓位单向下漂 |
| 「…等**周一确认安全**再说 **万一低开 那就等于做了个反T** 万一高开 那**没吃到就没吃到了 不纠结**」 | 2026-08-21 14:43 | ① 时点=**下一个交易日**；② **低开可补**（更好）；③ **高开不追**，追不上就放弃 |
| 「你出于什么原因出去避险 **那这个避险逻辑结束后 是不是应该补回来** 在**个股逻辑没变**的情况下」 | 2025-09-24 | 前提是**个股逻辑没变**（负事件 → 不补） |
| 「以后是节假日出今日 甭管当时指数什么行情，尽量做到 **早盘卖 尾盘买的反T**」 | 2025-04-29 | 时点可调成"尾盘买"（参数） |

## 2 状态机

    周末 14:30  G9 避险卖出（T 仓减半）
        │  record_sell(symbol, price, volume, account, date)   ← 只登记**等量**额度
        ▼
    data/wolf_hedge_refill.json  {account:symbol → {sell_date, qty, sell_px, buy_qty, done}}
        │  每个交易日（09:35 起，可配）由 t_monitor._check_hedge_refill 评估
        ▼
    refill_decision() → buy / wait / expire
        │
        ├─ buy    : gateway_execute(side='buy', qty=剩余待补) → mark_done（可部分成交多次）
        ├─ wait   : 未到下一交易日 / 未到时点 / 价格高于不追高上限（还有窗口）
        └─ expire : 负事件（逻辑变了）/ 超窗 / 窗口最后一天仍追不上 → 放弃（"不纠结"）

## 3 判定口径（纯函数 refill_decision）

| 条件（按优先级） | 动作 | 依据 |
|---|---|---|
| 负事件（wolf_early_stop.negative_event） | **expire** | 「在个股逻辑没变的情况下」2025-09-24 |
| 交易日 elapsed < 1（还没到下一个交易日） | wait | 「周一再拿回来」2026-08-21 |
| 交易日 elapsed > 窗口（默认 2 个交易日） | **expire** | 同上（不无限等） |
| 当前时刻 < 起始时点（默认 0935，可设 1400） | wait | 「尾盘买」2025-04-29（可选口径） |
| 价格 > 卖出价×(1+不追高上限，默认 1%) 且仍在窗口内 | wait | 「万一高开…没吃到就没吃到了」 |
| 价格 > 上限 且 已是窗口最后一天 | **expire** | 同上 |
| 价格 ≤ 上限（含低开） | **buy** | 「万一低开 那就等于做了个反T」 |

## 4 参数（env，全部可回退）

| 变量 | 默认 | 含义 |
|---|---|---|
| WOLF_HEDGE_REFILL | 1 | 总开关（0=完全不回补，只减不加） |
| WOLF_REFILL_CHASE_MAX | 0.01 | 不追高上限：回补价 ≤ 卖出价×(1+1%) |
| WOLF_REFILL_DAYS | 2 | 回补窗口（交易日），从卖出后第 1 个交易日起算 |
| WOLF_REFILL_FROM | 0935 | 起始时点；设 1400 = 他 2025-04-29「尾盘买」 |

## 5 护栏（为什么不会乱买）

1. **只补等量**：额度来自实际卖出量，补满即出列 → 仓位回到避险前的水平，**不放大**；
2. **走唯一买入通道**：gateway_execute(side='buy') → 仍受 **L5 准入闸（WOLF_DECISION_GATE）**、
   资金/成本比校验约束（与他"确认安全"的语义方向一致）；
3. **账户口径**：只读 stock（与 2026-09-14 的持仓口径一致），t 账户不参与；
4. **100 股整数倍**，剩余不足 100 股不买；
5. **有到期**：超窗自动 expire，避免长期挂着的"僵尸买腿"。

## 6 已知边界（诚实留档）

- 「**确认安全**」（2026-08-21 14:43）在语料里**没有可算化定义** → 本设计**不新造"安全"判据**，
  只用两条**他有明确原话**的代理：**不追高**（高开=没吃到）＋**个股逻辑没变**（负事件）。这是代理，不是他的原话口径。
- 只处理"G9 避险卖出"的回补；**其他类型的减仓（板上减半/小赚兑现/中轨全止盈）不回补**——
  他在那些场合说的是"卖完换方向"或"完全止盈"，不是"拿回来"。
- 若卖出后个股直接停牌/跌停，买入会被网关拒绝 → 本轮 wait，继续到窗口结束。
