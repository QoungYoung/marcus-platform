# 低仓试仓档设计（Trial Tranche）— t_only 下按狼大方式低吸建底仓 2026-09-07

> 需求：用户仓位低想建一点，但 wave=t_only 拦截"新建主升仓"。
> 狼大 t_only 期做法：不追高，但低位方向"找辨识度最高老龙头**低吸埋伏(试仓)**、强的留弱的丢"，
> 留子弹等右侧；4-4 打底约 1 个月，目标 4000-4020 未完成前分批低吸，突破主升确认才真正加仓。
> 故 t_only 不是"零新建"，而是"只允许低吸试仓档、禁止追高建仓"。

## 一、试仓档触发（仅低吸类，禁追高）
标的满足（全部）：
1. 触发来源 ∈ 低吸信号：**custom_prevlow(254 触前低+缩量≤0.9) 或 custom_m5dump(253, 大盘5min急杀≥0.4)**；
2. 标的属主线候选方向（fusion **TOP1∪TOP2**，与 wolf no-T 门同锚——覆盖系统-狼大滞后一档）；
3. wave.operation ∈ (t_only, side)；operation=defense/exit 不试仓（防守/兑现期）。
→ 通过则按试仓档买入（可作底仓沉淀，非纯 T 仓）。

## 二、试仓额度（分批，可配置）
- 单次上限 = min(可用资金 × TRIAL_SINGLE_PCT, 计划仓 × TRIAL_CAP_PCT / 预期批次数)
- 默认 TRIAL_SINGLE_PCT=2%（单次≤净值2%）、TRIAL_CAP_PCT=30%（试仓累计≤计划仓30%）、批次上限 3~5 次
- 全部 env 可调（不硬编码）；累计由"该方向试仓买入(未卖出部分)"记账（沿用 paper_trades 净额即可近似，试仓只增不减至升级）。

## 三、试仓 → 正常建仓的升级（**动态结构信号，不写死点位**）
禁止硬编码 4000-4020（那是 wave reasons 对当前行情的描述，点位随行情变）。
自动升级(each 盘前/盘中判定)当满足 **其一**：
- **wave 升级**：wave_state.operation 变更为 build（wave_agent 结构判定，动态）；
- **结构主升确认**（全部满足, 指数=上证000001）：
  - close > MA200（动态均线）
  - 且 MA20 > MA60（均线多头）
  - 且 当日放量：vol ≥ 1.2 × 20日均量
  - 且 close ≥ 近60日箱体上沿 × 0.995（上沿 = max(high[-60:])，**随行情滚动**）
→ 升级后：该方向试仓额度解锁为正常建仓（TRIAL→NORMAL，按主线建仓上限），原 t_only 只做T限制解除（build 档）。

## 四、风控/边界
- 升级未触发前：试仓只经低吸触发（254/253），**绝不因追高买入**；若回踩失败/继续下跌：单标亏损 ≤ -X%（默认-5%）→ 试仓止损出场（可配 TRIAL_STOP_PCT，缺省沿用 T 风控）。
- defense/exit：不试仓、不加仓（纪律优先）。
- 与 no-T 门(G3 板块收敛)关系：试仓买入不受 G3 拦(那是卖腿门)；但属收敛板块的试仓宜更小/延后(可选)。
- 记账：试仓买入计入 paper_trades；floor(累计×0.5) 语义不变——未卖部分自然沉淀底仓，T 出规则对该批若升级前触及 high_sell 照常可 T 出高抛降成本（狼大低吸埋伏+做T降成本并存）。

## 五、实现落点（待用户确认后动码）
- 状态与判定：apps/main_line/trial_gate.py
  - read_trial_mode(symbol/wave) -> 'trial' | 'normal' | 'none'
  - escalate_signal() -> bool（wave=build 或 结构主升确认, 上证日线, 无硬编码点位）
  - trial_cap_left(symbol) -> 剩余试仓额度(净买入累计与 TRIAL_CAP_PCT 比)
- gate 接入：TMonitor 低吸买腿(253/254 触发) → 若 trial 且达标试仓档 → 放行买入(额度约束)；
  追高型 custom buy / 非主线 → 仍按 wave gate 拦截；升级后放开正常建仓。
- 报告：盘前/复盘输出 trial 状态(哪些方向可试仓、剩余额度、升级信号是否成立)。
