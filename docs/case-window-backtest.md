## 2. B/C/I 为什么错

三条都是同一个问题：**他说的触发位在现价上方、且已经破了；agent 却选了下方最近的“当前支撑”。**

- B/C：他的 3922 在 14:55 价上方 2.3%；agent 选了 **3835.36**（10/17 swing low，离现价 0.01%），因为它看起来像“当前最近的支撑”。
- I：他的 3761 在 14:30 价上方 0.7%；agent 选了 **3733.34**（今日低点，离现价 0.05%），因为它是“还没破的最近支撑”。
- 但狼大的 3922/3761 是 **“跌破它就触发减仓”的破位线**，不是“下方下一道支撑”。

**这是 break_trigger 与 next_support 的混淆，不是窗口错。**

## 4. 结论

1. **窗口协议有效**：agent 10/10 能正确识别窗口，不再把 14:55 当收盘。
2. **选点仍差一层**：对“破位触发线”与“下一道支撑”没有分开。
3. 下一步：在 prompt/schema 里把 `risk_trigger` 明确成 **break_trigger**（可以是现价上方、已破位），`next_support` 单独输出；B/C/I 应回到 3922/3922/3761。

## 7. B/C 为什么还是错

B/C 的 break_trigger 都选了 **3835.36**（10/17 swing low），不是 3922：

- 3835.36 离 14:55 现价 3834.97 只有 0.01%，是“刚跌破的最近结构”；
- 3922 在现价上方 2.3%，也是破位线，但离得远；
- setup_context 只说“收盘跌破某个关键结构位”，没有告诉他“第一档是 3922”；
- 候选里 3922 存在（neckline/swing_low/measured），agent 却认为 3835 更像“当前这条关键位”。

**这不是 break_trigger/support 混淆，而是“哪条已破位线才是他的第一档”的优先级问题。**
数据里 3835 和 3922 都合理，只有他的叙事能定 3922 在前。

## 8. 结论

- B/C 是“第一档优先级”问题，不能再靠数据规则硬猜；
- 生产上：agent 输出 `break_trigger` 候选（3922 与 3835 都列），由 **case 库第一档/人** 定最终；agent 不能单独决定 3922 优先于 3835。

## 10. 5min 候选加了，为什么 E 还是 3844.13

- 候选里已经有 `m5_prev_pm_high 3856.25`（8/27 13:55 的 5min 反抽高点）；
- 但 agent 的 `break_trigger` 仍选 **MA5 3844.13**，理由写的是“收盘门槛取 ma5”；
- 它把 3856.25 当成“5min 微观枢轴”，没有当成“收盘位”。

所以 E 的 12 点差**不是候选缺失**，是 agent 不认为 3856.25 是“收盘位”。
要它选 3856.25，不能只加候选，还要告诉它：**这类 setup 的门槛可以是前一日午后 5min 反抽高点，不是只看 MA5/日线结构。**
