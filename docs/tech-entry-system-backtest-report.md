## 3. 核心结论

1. **系统“该不该建仓”的浪型/主线门基本能对齐 Wolf 的 big-buy 窗口**：E01(8-21 build)、E03/E04(10-28/30 build)、E07(1-5 build) 主线 rank 前 2 + 浪型 build，链路放行——与 Wolf 在这几个时点回补/主做科技一致。
2. **Wolf 更频繁的“底仓低吸/回补/T 积累”时点系统大多不放行**：E02(t_only)、E05(t_only)、E06(exit)、E08(exit)、E09(exit)、E12(defense)、E13(defense) 都被浪型 gate 拦下；Wolf 是在已有底仓前提下的低成本回补/切换，不是新主升追仓，属于**现有 wave gate“新建”口径之外的 T/内部调仓动作**。
3. **内部主线切换**（E10 海外→国算、E11 设备→材料、E14 调仓 ETF）有 rotation_gate B3/主线路由兜底，与 Wolf “主线内已出货链→未出货链”一致；但 B3 需要候选 rel-low + 资金流入，E11/E12 用东财整概念（半导体/光刻机 HIGH、B反）实测不满足 → **概念聚合粒度把 Wolf 买的低位细分（封测/材料/存储低吸位）盖住了**。
4. **拥挤/rotation 回放**：把芯片/光/存储等标成“拥挤无空间”的时段几乎覆盖 2025-12~2026-07（用 Q4/Q2 基金持仓近似，非严格 PIT）。若按当前 crowding_blacklist 硬过滤回放，E06/E07/E08/E09/E12/E15 的 Wolf 操作会被硬拦——但 Wolf 买的是“拥挤大板块里的低位补涨/未出货链”，说明**拥挤过滤必须下探到个股/细分，不能按整概念硬拦**。
5. **系统整体比 Wolf 保守**：15 个事件里，完整链路明确“会”的约 4 个（E01/E03/E04/E07），内部调仓可放行的约 3-4 个（E09/E10/E11/E14），其余为“不会/部分”。缺口不在“主升该不该买”，而在 **Wolf 的“底仓内低成本吸筹/主线内低吸轮动”没有对应的历史逐股回测通道**。

## 4. 系统缺口与改进建议

1. wave gate 目前只有“新建 vs 只做T”二元；建议增加 **底仓回补档（t_only 内已有底仓的加 T 仓/回补位）** 与三仓档位模型衔接（P3 已列）。
2. position/rotation 都吃“整概念指数”粒度；Wolf 的科技细分（封测、半导体材料、国算低位、存储未起爆分支）需 **stock_concept_map 个股级 + 公募拥挤 PIT 回放** 才能验证“同样进场”。
3. concept_hist 从 2025-08-20 起，60 日窗口使 2025-08~10 的概念级 position 无法回放；要验证 E01-E04 个股级，需回补 2025 上半年概念/行情历史或按个股直接回测。
