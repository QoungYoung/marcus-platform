### 2.1 修正后的实际影响（逐消费点，改前 → 改后）

| 消费点 | 改前（`exit`）| 改后（`defense` ＋ `mode=自救`）| 方向 |

| 布腿/方向资源 `wave_alloc.WAVE_ALLOC.invest` | 0.70 | **0.30** | **收紧** ✓（这就是「熊市不做」的量化）|

**留待拍板（未做）**：`position_tier` 的 `op_to_total` 把整个 `defense` 当「有风险 30%」，分不出 rung2（失败4-5，真防御）与 rung3（下跌1浪·自救）。
若要严格：`mode == 自救` ⇒ 「下跌 0%」，否则 `defense` ⇒ 「有风险 30%」。该表默认 `P3_TIER_PROFILE=legacy` 未启用，故暂不阻塞 ✓。

**建议的修正（依据最充分的一条）**：下跌1浪应拆成两件事 ——

- **新建仓闸 = `defense`**（禁新建仓、目标仓位 30%，对齐原表 down + 「熊市什么都不做」）；
- **存量处置 = `mode: "自救"`**（借反弹/放量分批减 —— 他 10-15 的原话：「要出来光靠硬割不行，需要创造条件才能割肉」「我没有兴趣增加仓位，别人拉起来给我走我更开心」）。

即：`defense` 说的是**不进**，`自救` 说的是**怎么出**；把两者压成一个 `exit(0.70)` 既比原表松、又丢了"自救"的执行语义 ✗。

## 4.1 B 的执行结果（2026-10-15 补档：3-3 已做、3-2 证明**不能**接管）

**已实现（`wave_ladder.py` 叠加档，`main_up` 字段）**：

- **3-3 主升**：判据 = 「连续 ≥3 日收盘 > 前 20 日最高」（他 2025-10-29「**站稳 4006 三天**」的量化）∧ 量能不缩（当日额 ≥ 20 日均额）
  ⇒ 输出 `level=d3 / sub_level=3-3 / operation=build`（原表：3-3 = 重仓追 ✓），invest 走 `wave_alloc` 的 build=1.0 ✓。
- **实测（2016-2026，7 段，共 32 天）**：2018-01 / 2019-03 / 2019-09 / **2020-07（+11.6%）** / 2021-01 / **2024-09-26~10-08（+16.3%）** / 2025-07。
  ⚠️ 注意 2018-01、2021-01 两段**恰在顶部区**（随后转熊/大跌）⇒「3-3 确认」是**追**不是抄底；这条已写进 `MAIN_UP.expect`。

**证明不能做的（重要负结果）**：

- **3-2 不能接管 level/op** ✗：它与「4 浪调整」在价格上**不可区分** —— 实测 2026-07-31 他明确叫「整波为调整浪 / 4-2→4-3」，
  若按 3-2 就会给 `side`，而链给的是 `t_only`（他只吃反抽 ✗）。这是「等级不可分辨」问题的又一次实证 ⇒ 只保留信息字段 `main_up_pb_info` ✓。
- **叠加档必须看「上锁后的档」**：首版用当日档（raw）判断 ⇒ 2026-10-09 那种「上锁 defense」的日子被放宽成 `side` ✗，
  已改为 `idx <= 成功4-5` 才允许叠加（单测 `test_main_up_33_respects_latch` 锁死）。
- 判据里的「**三大指数同时**化解顶背离」（他的原话）我们**还做不到**：本地只有上证 000001（+中证1000 000852），
  没有深证成指/创业板日线 ⇒ 记为向量化 TODO ⛔，当前只用上证 ✓。
