# I/J 全新留出验证：模式+粒度仍然没有泛化

> I/J 没有参与 G/H 的规则修改；输入仍是完整候选（日线+15min）、无狼大具体点位。
> I = 2025-09-04，他的第一档 3761（2:30 破位止损）。
> J = 2025-08-01，他的第一档 3560（快速放量下破→减半）。

## 1. 结果：0/2 精确，J 仅近位

| case | 他的第一档 | agent risk_trigger | 偏差 | 判定 |
|---|---:|---:|---:|---|
| I | 3761.00 | **3732.84**（当日低点/前一日低点） | **-0.75%** | ❌ |
| J | 3560.00 | **3550.04**（当日低点/3550 整数） | **-0.28%** | ⚠️ 近位，不是同一档 |

- 动作模式 2/2 都判成 `intraday_confirmation`；
- 但第一档都没选他说的数：
  - I 选 3732.84（比 3761 低 28 点），不是 3761；
  - J 选 3550.04（比 3560 低 10 点），3560-3563.5 被它当成了 `reclaim_threshold`，不是 risk。

## 2. 为什么还是错

### I

- 他的 3761 是 **8/28 摆动低点 + measured_move 3761.42**，收盘 3765.88 只高 0.12%；
- agent 选了 **3732.84**（9/4 当日低点/前一日低点），理由是“确认跌破的资金会在这里割肉”；
- 它把“割肉位置”理解成当日最低点，而不是他说的 3761 结构位。

### J

- 他的 3560 是 **整数关 + 前一日低点附近**；agent 把 3560-3563.5 归为 `reclaim_threshold`；
- risk 选了 **3550.04**（当日低点 + 3550 整数），比 3560 低 10 点；
- 它优先“当日低点+整数”的盘中位，而不是他说的 3560 关口。

## 3. 这说明什么

1. **模式分类是对的，但“第一档是谁”仍然不是数据唯一决定。**
   - I 的 3761 和 3732 都是盘中位；J 的 3560 和 3550 都是整数+低点；数据上都能自洽。
2. **继续加“优先最近/优先整数/优先 m15”只会换一批 case 错。**
   - G/H 加 m15 粒度后 2/2；I/J 立刻 0/2。
3. **他的第一档依赖他的叙事**：
   - I 他明确说“2:30 破位止损位 = 3761”，这是**他选定的止损位**，不是数据自动选出的最低点；
   - J 他明确说“不能快速放量下破 3560”，3560 是**他盯的关口**，不是 3550。

## 4. 结论

**agent 可以做：模式判断、候选带、合流、角色、区间、分歧提示；不能单独决定第一档。**

生产口径应该是：

- 第一档来自 **case 库里的他原话点位**（3761/3560/3922…）或人确认；
- agent 输出“我选的替代位 + 理由 + 与 case 库的偏差”；
- 偏差 >0.5% 时报警“分歧”，不自动采用；
- 不再用 agent 的 risk_trigger 直接下单。

一句话：**G/H 的 2/2 是拟合；I/J 的 0/2 说明“模式+粒度”仍不足以替代他的叙事优先级。**

## 5. PIT 审计：I 的 3732.84 是未来数据

- 他的动作时点：**14:30（2:30）**；
- 2025-09-04 的最终低点 **3732.8403 出现在 14:35 的 5min bar**；
- 14:30 bar 的低点是 **3734.0078**，收盘 3735.3562；
- 9/4 首次跌破 3761 是在 **10:35**，所以 14:30 时 3761 已被跌破，是已知的；
- 但 **3732.84 在 14:30 还不存在**，它是 5 分钟后才创出的低点。

我们的输入用了 **9/4 全天日线**（low 3732.84、close 3765.88）来算候选，等于把收盘后才知道的低点/收盘价给了 agent。
所以 I 的 3732.84 是 **lookahead**，I 这轮结果不能用来评价 agent。

正确的 PIT 输入应该是：

- 日线：9/4 只给 **截至 14:30 的 O/H/L/C**（low 3734.01、close 3735.36），不给最终 low/close；
- 15min：只给 14:30 及以前的 bar；
- `today_low` 用 14:30 前的最低点，不是全天最低点。

J 也要按同样口径查：如果动作是 13:15 首次跌破 3560，13:40 才创 3550.04，那 3550 也是未来数据；如果动作是 14:30/收盘，则 3550 已知。

## 6. PIT 重测（只给到 decision_time）

- I：14:30 快照 low 3733.34（不是 14:35 的 3732.84），close 3735.36；
- J：13:15 快照 low 3559.24，close 3559.25。

| case | 他的一档 | agent risk | 偏差 | 判定 |
|---|---:|---:|---:|---|
| I | 3761.00 | **3733.34**（14:30 今日低点） | -0.75% | ❌ |
| J | 3560.00 | **3559.25 / 3560 带**（成本区+整数+今日低点） | -0.02% | ✅ |

- 模式 2/2 仍是 `intraday_confirmation`；
- J 已修好：13:15 快照下 3559.25 与 3560 整数同带，正确；
- I 仍错，但**不再是 lookahead**，是语义错：
  - 3761 在 10:35 已破；14:30 时它在上方且已破；
  - agent 认为“已破位不能当触发线”，于是选了下方**还没破的今日低点 3733.34**；
  - 但狼大的 3761 是“**确认跌破的资金止损位**”，它本来就是已破的触发线，不是下一道未破支撑。

**新结论**：`intraday_confirmation` 的 `risk_trigger` 应该是“**哪条线被跌破确认了这笔止损**”，可以是已破位；不是“下方下一道还没破的支撑”。
