> 本轮变化：候选补了 `today_high/today_low/ma20/round10`，dedup 改成只合并同类型；role 用 `support_holding/support_broken/reclaim_threshold/resistance`。

## 3. 关键结论

### 3.1 3370 的问题修好了

- 旧候选 dedup 把 `today_high 3370.80`、`ma20 3372.40`、`round10 3370` 合并进 `neckline 3361.74`；
- 现在只合并同类型，A 的 risk 直接选了 **ma20 3372.40**，距 3370 只 0.07%；
- 3388.78 不再是替代答案。

### 3.2 B/C 的问题是“优先级”，不是“没候选”

B/C 候选里其实有：

- `swing_low 3922.58`
- `neckline 3922.58`
- `measured_move 3922.58`

但 agent 的 `risk_trigger` 选了 **MA60/3900 一带（3898.66/3898.85）**。
它把 3922 归到了 `resistances`（上方压力），而不是 `support_broken/reclaim_threshold`。

原因：3922 在现价**上方**，agent 看到“上方 + 前低”就归为压力；它不知道“这个前低是**刚刚被跌破的支撑**，应该按 reclaim 处理”。
**角色分类还是差一层：上方 ≠ 普通压力，可能是已跌破的支撑。**

### 3.3 D 的问题仍是“候选缺 3888”

D 的候选里：

- 有 3885.31（neckline）
- 有 3890.72（MA5）
- 有 3896.08（MA13）
- **没有 3888.33（12/2 前低）**
- **没有 3888.89-3890.95（12/1 缺口）**

所以 agent 选 3912.01（gap）不是“不想选 3888”，是候选里没有 3888。
这说明候选生成还缺两类：

- `prior_day_low`（前一日低点）；
- `filled_gap`（已回补缺口，仍有角色意义）。

## 4. 一句话

**A 修好了（3370 → ma20 3372.4）；B/C 是优先级问题（有 3922 却选 3900）；D 仍是候选生成问题（没有 3888）。**

下一步：
1. 给 `prior_day_low` 和 `filled_gap` 补候选；
2. 给角色加一条规则：**上方 + 曾是支撑 + 刚被跌破 ⇒ `support_broken/reclaim_threshold`，不是普通 resistance**；
3. 再跑同一盲测，看 B/C/D 的 risk 是否回到第一档。
