## 3. 结论

### 3.1 role 修对了

- v2 的 risk 全在下方（3316/3800/3800/3816），语义是“跌破下一档支撑”；
- v3 的 risk 全在上方（3388/3885/3885/3912），语义是“站不回破位线”。
- **说明上一轮 0/4 有一半是 task schema 的错，不全是 agent 的错。**

### 3.2 但点位还是选不到他的

- A：他 3370，agent 选 3388.78（高 0.56%）；
- B：他 3922，agent 选 3885.31（低 0.94%）；
- C：他 3922，agent 选 3885.31（低 0.94%）；
- D：他 3888，agent 选 3912.01（高 0.62%）。

agent 选的是“**结构上更强/更近的已破位**”，不是他的“第一道触发位”。它没有他的**优先级**。

### 3.3 根因：候选里没有他的精确位

完整 `point_engine` 在这些日期：

- A 没有 3370/3375 的 MA20/MA34/round，只有 3361.74/3388.78；
- B/C 没有 3922 的前低/缺口/round，只有 3936.58/3899.96/3885.31；
- D 没有 3888 的前低/缺口/MA5，只有 3885.31/3912.01/3936.58。

所以 agent 不是“选错一个存在的答案”，而是**从一组缺少他那个点的候选里，选了最强的替代**。

## 4. 下一步

1. **先补候选生成**：
   - 他常说的 MA20/MA34；
   - 11/5 前低 3922.58、12/2 前低 3888.33 这类 swing_low；
   - 缺口上下沿（3912-3929、3888-3891）；
   - 整数关（3370/3900/3920/3850/3890/3930）。
2. **再加 priority**：
   - 不是按 confidence 排，而是按他的“第一档/第二档/第三档”；
   - A 第一档 3370，B 第一档 3922、第二档 3900，D 第一档 3888、第二档 3850、第三档 3816/3922-3930。
3. 补完后重跑同一盲测；如果 risk 还是选“最强替代”，再考虑让 agent 看他的 case 优先级（但那时已经不是盲测）。

## 5. 一句话

**role 修对了，语义从“跌破下方”变成“站不回上方”；但候选缺他的点、agent 缺他的优先级，所以 risk 还是 0/4 命中第一触发位。**
