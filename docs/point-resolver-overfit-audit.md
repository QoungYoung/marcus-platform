## 2. 哪些规则过拟合

| 规则 | 过拟合程度 | 证据 | 处置 |
|---|---|---|---|
| **`structure_rank` 硬优先级（3>2>1）** | **高** | v4 失败后按案例手工给类型定级；A/B/C/D 4/4，但 F（3950）被 MA20 3979.7 抢走，偏差 +0.75% | 降级为描述字段，不做硬门 |
| **排除 rank=1（缺口/当日高低）** | **高** | 直接为 B/C 的 3839 缺口定制；F 的 3950.31 正好是 rank=1 缺口，被排除后选错 | **删除**（本次结论） |
| **rank > confluence > distance** | **高** | in-sample 4/4；holdout F 失败；C 与 F 不能同时满足 | 不作为唯一规则 |
| `filled_gap` / `prior_day_low` 候选 | 中 | 为 D 的 3888 补的；概念通用，但“已回补缺口仍算位”的阈值是后加的 | 保留候选，标注 source=proxy |
| `today_high` / `ma20` / `round10` | 中低 | 为 A 的 3370 补的；但 `max_confluence` 原本也能选到 prior_high 3370.8 | 保留，属通用候选 |
| `state=broken` + `broken_days<=5` | 中 | 5 日是任意阈值；3922/3888 在 1-2 日内，换别的节奏可能失效 | 保留为事实字段，不做动作门 |
| dedup 只合并同类型 | 低 | 修复真实 bug（3370 被 3361.74 吃掉），不是为答案定制 | 保留 |
| `max_confluence` | 中 | 5/6，C 仍被 3840 缺口骗；confluence 会把同价多类型堆高 | 作为 baseline，不做唯一裁判 |

## 3. 结论

1. **v5 的 4/4 是 in-sample，不能当泛化。**
   去掉 rank=1 排除后，B/C 会重新被 3839/3840 缺口拉走；保留它，F 的 3950 又会被排除。**C 和 F 不能同时被一条硬规则满足。**
2. **没有一条单规则能 6/6。**
   最高是 `max_confluence` 和 `rank>confluence` 各 5/6，但失败点不同。
3. **真正稳的是“候选事实层”**：
   - `state=broken`（价格在上方、最近 5 日还在上方）；
   - `confluence`（同价多结构）；
   - `type`（摆动/颈线/缺口/均线）；
   - 这些是事实，不是“选谁”的结论。
4. **“选谁”仍然需要他的优先级/行情段位**，数据本身给不出“3922 是第一档、3900 是第二档”。
   用硬 rank 去猜，就会在 C 和 F 之间二选一，必然过拟合。

## 4. 建议的下一步

- **删除**：`排除 rank=1`、`rank 硬优先级`；
- **保留**：`state`、`confluence`、`type`、`distance` 作为事实字段；
- **不做**：让 agent 单独决定 `risk_trigger`；
- **改成**：agent 输出 **候选排序 + 理由 + 不确定性**，由 case 库里的“他的第一档/第二档”或人来定最终 risk；
- 用 **R05/R09/F** 做留出验证，不再用 A-D 调规则。

一句话：**过拟合的不是某个候选，是“用 structure_rank 硬猜他的优先级”这件事。**
