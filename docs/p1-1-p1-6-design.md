## 零、共同前提：**大盘浪 ≠ 主题浪**（本设计的第一原则）

本仓存在两套**互相独立、可能相反**的浪型判断，任何"按语境动作"的设计都必须指明用哪一套：

| | 大盘浪 | 主题浪 |
|---|---|---|
| 判的是什么 | 上证指数 000001.SH | 某个主线主题（板块）自身 |
| 产出位置 | `wave_state.json`（`wave_agent.py`，喂指数日线） | `trend_confirm_<date>_long.json` 的 `themes[*].track_a`（机读）<br>+ `mainline_gate_<date>.json` 的 `verdict`；文案见 `main_line_state.json` 的 `wave_structure` |
| 语义 | 系统性环境（是否全市场风险） | **这个方向**能不能做 |
| 用于 | 系统性护栏（仅拦"最后一跌/防御等企稳"） | **方向判据主体** |
| 取值 | `level` / `sub_level` / `operation` | `stage` ∈ confirmed / suspect / not_confirmed / window_limited |

**本仓已有的明文原则**（`backend/app/services/trade_graph.py:675`）：
> ⚠️ **主线自身浪型（重要: 主题浪, 不同于上方大盘 wave_context）**：
> → 该主线为主升 3 浪运行中(已确认), **不因大盘 t_only(4-2) 一刀切禁建**。

**狼大原话的参照系同样指向板块**：2025-06-05「…但是**主线板块筑底行情**…急杀可以买，缓跌不买」。

> ⚠️ 教训：P1-3 的第一版（commit 16a68aa）用大盘浪做判据，在大盘 `4-2/t_only` 时会把**所有 253 一刀切禁掉**，
> 正是上述原则警告之事。**本设计的两项均以主题浪为准，大盘浪仅作系统性护栏。**

## 一、P1-1 设计：风向标死时的"跑"（离场动作）

### 1.1 狼大依据与语义边界

原话（2026-01-12）：
> 「我做的几个卫星组网和卫星材料补涨 没去中国卫星 能不能继续做很简单 **龙头风向标死了就不能做了**
> 那个时候**千万不要想高切低**，**麻溜的跑就行**」

拆成三条可执行语义：
1. **停止新买**（已完成）；
2. **不要高切低**——风向标死后，不许把仓位换到同主题的后排/低位票（与 W09「后排不能去」一致）；
3. **麻溜的跑**——对相关持仓执行离场。

补充边界（2026-01-13）：「说的是**主线题材** 题材 题材」→ 风向标 = **主线题材内辨识度最高的龙头**，
不是全市场任何一只强势股。因此死掉的影响面是**该题材的持仓**，不是单只票。

### 1.2 判据（已落地，复用即可）

`wolf_confirm_pick.pick_v2` 已产出：
- `wind` = 等待池第一（`leader` 最高的成分，辨识度最高龙头）
- `wind_broken` = 该龙头**收盘**跌穿其**前一交易日最低** 0.5% 以上（收盘口径，与狼大「看收盘」一致）
- 审计 json `pick_wolf_<theme>_<AS>_v21.json` 的 `wind_flag` 已含 `symbol/name/broken/dist_prevlow_prev`

### 1.3 触发时点（关键设计选择）

`wind_broken` 是**日线收盘口径**，天然是"一次性、盘后可得"的信号，而不是盘中撮合信号。
因此**不放在 TMonitor 每轮扫描**，而放在 **09:20 的 `rotation_switch_arm`**，与既有卖腿同一入口。

**范围是"该主题"而非"该个股"**（依狼大 2026-01-13「说的是主线题材 题材 题材」+ 2026-01-16「龙头和核心都救不起来 那其他后排还要死」）：
风向标死 → 该**主题**的持仓都在离场范围内，不只是风向标那一只。这也是**主题浪**层面的信号，与大盘浪无关（见 §零）。

```
09:20 rotation_switch_arm
  ├─ 既有: 持仓落在 crowded_top / holdT_top → 布 quote.vwap_break 卖腿
  └─ 新增: 持仓所属主题的"风向标已死" → 布卖腿(P1-1)
```

**建议这样做的理由**：①判据天然日频，放盘中会产生"用旧数据反复触发"的假信号；
②复用既有卖腿管道（`EXP_*` → TMonitor 执行），不新增执行路径；③与 `wolf_dip_254` 等腿的
"非消费式持续腿 + 冷却"语义一致。

### 1.4 卖出范围（两级，需你拍板）

狼大说「跑」，但「底仓不动」也是他的核心原则——两者只在**健康主线**下不冲突：
风向标死 = **主线被证伪**，此时底仓的保护前提消失了。故建议分两级：

| 级别 | 触发 | 动作 | 依据 |
|---|---|---|---|
| **L1 立即减 T 仓** | 风向标死（当日） | 布卖腿，卖出**可卖部分**（保留 100 股工程底仓），并**禁止补仓/高切低** | 「麻溜的跑」+「千万不要想高切低」 |
| **L2 清底仓** | 风向标死 且 **次日收盘仍未收复** 前低（连续 N=1 日确认） | 清该主题**全部**持仓 | 狼大「**收盘**跌破我才出」（2026-01-29）+ W17 收盘确认破位 |

- L1 走既有 `SELL_EXPR = quote.vwap_break`（黄线破位走人）——**复用已对齐狼大的卖出口径**，
  不新造"市价砸出"。
- L2 提供两种可选实现（**待定**）：
  - (a) 收盘确认 → 次日开盘市价清（贴合「收盘跌破我才出」，但有隔夜跳空风险）；
  - (b) 收盘确认 → 次日用 `vwap_break` 腿执行（留一次盘中反抽机会）。
- 开关建议：`WOLF_WIND_EXIT=0/1/2`（0=关，1=仅 L1，2=L1+L2），默认先 **1** 观察。

### 1.5 与现有机制的交互（必须处理，否则会打架）

| 机制 | 交互 | 处理 |
|---|---|---|
| 底仓保护（100 股 floor） | L1 只卖可卖部分，floor 生效 | 无需改动 |
| `auto_exit` / 破位腿 | 可能同时命中同一持仓 | 复用**同一 `_wolf_done` 当日去抖**，避免重复卖 |
| `wolf_253_build.refill_253` | 风向标死后**必须禁止回补** | 在 `refill_253` 入口加 `wind_broken` 检查（读链状态里的 theme） |
| P1-3 语境闸门 | 两者独立：P1-3 管 253 买，P1-1 管该主题离场 | 建议在 `wolf_context` 增 `theme_wind_broken` 字段供两者共享 |
| `crowded_top` 卖腿 | 同一持仓可能同时被两个理由布腿 | 布腿时按 (symbol, trigger_kind) 去重；理由合并记日志 |

### 1.6 数据依赖与缺口

- 需要在 `rotation_switch_arm` 里**按持仓主题**取 `wind_broken`。现状：`pick_v2` 是按**主题**跑的
  （arm 已经对 `confirmed` 主题逐个调用），所以主题→风向标状态的映射**顺手可得**，只需把
  `wind_broken` 从 `pick_v2` 的返回值里透出（现在只在审计 json 里）。
  → **接口改动**：`pick_v2` 的 `status_out` 增加 `wind_broken` / `wind_symbol`（低风险，纯新增字段）。
- `wolf_253_chain.json` 目前按 symbol 存，无 theme。若要精确做"该主题持仓"，需从
  `stock_concept_map`/`THEME_CONCEPTS` 反查（arm 已有 `theme_of_chain`）。

### 1.7 验证方案

1. **规则层**：构造"风向标收盘破前日低" → 断言卖腿被布、且 `refill_253` 被禁；
2. **去重层**：同一持仓同时满足 crowded 与 wind_broken → 只布一条腿，理由合并；
3. **回归**：`test_p11.py` 现有 4 例须仍全过（买侧不受影响）；
4. **离线不可验部分**：真实卖腿成交与账本（本机 PG 不可达）→ 需在服务器 dry-run。

### 1.8 待你拍板的点

1. L2 是否要做、以及用 (a) 隔夜市价 还是 (b) 次日 vwap_break；
2. 默认开关取 1（仅 L1）还是直接 2；
3. "该主题持仓"的判定：按 `THEME_CONCEPTS` 反查是否够（还是会漏掉跨主题持仓）。

## 二、P1-6 设计：持仓层"去弱留强"

### 2.1 狼大依据与语义边界

原话：
- 2026-04-23：「你们一定要记住一点 **反弹的时候卖弱的 留强的 不要搞反了**
  **不要觉得哪个反弹多就卖 留那种没波动的**。」
- 2025-02-06：「…然后按之前的分类做不同的线，指数票 容量票做通道，其他做轮动 **去弱留强**」
- 2025-07-11（换票阈值）：「低于换后的票 3%…直接割肉换过去」

**关键反直觉点**：他明确说「不要觉得哪个反弹多就卖」→ **反弹幅度大的是"强"，要留**；
很多人会本能地卖掉涨得多的、留"还没涨的"，狼大说这是**搞反了**。

**重要反面提示**（必须写进设计，否则会误用）：
- 2026-05-26：「机构目的就是**逼大家趋弱留强** 能不能理解？这是**明牌**」
  → 去弱留强在某些阶段是**机构设的局**。故不能无条件每日执行，需限定语境与阈值。

**执行层没有的**：狼大说「反弹的时候」——这是一个**语境条件**，不是"每天做一次"。

### 2.2 目标与形态

新增**持仓纪律模块**（建议 `apps/main_line/position_discipline.py`，纯函数 + 只读数据），
产出"建议卖出/换票"清单，交既有卖腿管道执行；**不直接下单**（与 `wolf_discipline` 同风格）。

```
position_discipline.evaluate(positions, wave, as_of)
   → {"sell": [{symbol, rs, reason}], "swap": [{from, to, gap_pct, reason}], "directive": "..."}
```

### 2.3 强弱判据（与 P0-2 保持同一口径）

**用 `rs`，不用绝对涨幅**——理由：
1. 与已落地的 P0-2 选择层闸同口径（`rs = 个股20日涨幅 − 所属主题20日涨幅`），**一套口径两处用**，
   避免"选股看 rs、卖出看别的"这种新的不一致；
2. 狼大「卖弱的」是**相对**概念（同主题内比较），他 2026-05-26 说的"先选板块，再板块内比个股"也是这个意思；
3. 绝对涨幅会把"主题整体强、个股中庸"误判为强。

辅助判据（建议作为**次级**排序键，不作主判）：`rs` 相差 < 阈值时看 **反弹幅度**（狼大说的"反弹多的留"），
即用 `r5`（近 5 日涨幅）作 tie-breaker。

### 2.4 触发语境（限定，防误用）—— **按持仓各自的主题浪，不看大盘**

**关键**：每只持仓按其**所属主题**的浪型/结构单独判定（见 §零），**不用大盘浪**——
否则大盘 `4-2` 会禁掉一条正在主升的主题里的持仓优化；反过来大盘筑底也不能替一个 `not_confirmed` 的主题背书。

只在**该主题的反弹/筑底语境**触发（数据源与 P1-3 相同：`trend_confirm` 的 `track_a.stage`）：
- 允许：该主题 `stage == confirmed`（低点抬高+2浪不破前低+再创新高），即狼大说的"反弹/筑底成立"
- 禁止：`not_confirmed` / `suspect`（疑似V反、等结构确认）—— 此时卖弱 = 在**下跌途中**割肉

叠加**大盘系统性护栏**（仅此一项看大盘）：大盘 `level=down` 或 `sub_level ∈ {C杀, 衰竭浪, 双头/M顶, 4-5, 失败5}`
→ 全部不做（狼大: "最后一跌/防御等企稳"）。

- **禁止理由**（必须保留在代码注释里）：狼大 2026-05-26 说「机构目的就是**逼大家趋弱留强**…这是**明牌**」
  → 在下跌段执行等于替机构接盘；在**结构未确认**的主题里执行同理。

参数建议：
- `min_positions ≥ 3`（持仓太少不做，避免把底仓换掉）
- `rs_gap_pct ≥ 3.0`（狼大 2025-07-11 的 3% 阈值）
- 每次最多卖 1~2 只；单日最多 1 次

### 2.5 两种动作

| 动作 | 说明 | 建议 |
|---|---|---|
| **卖弱**（不换） | 卖出 rs 最低的持仓 | 默认动作，先落地 |
| **换票** | 卖弱 → 买同主题 rs 最高的**非持仓**标的（走 `pick_v2` 的 leader+位置闸） | 二期；需与资金闸/仓位纪律联动 |

风险：换票会引入"卖飞+追高"的双重错误（狼大 2026-04-23 原话的反面）。故二期需先回测。

### 2.6 与现有机制的交互

| 机制 | 冲突点 | 处理 |
|---|---|---|
| **底仓不动** | 去弱留强可能动到底仓 | 建议**只作用于 T 仓（可卖部分超 100 股的部分）**；底仓由 L2 级（风向标死/破位）处理 |
| 破位腿 / auto_exit | 同持仓可能重复卖 | 复用 `_wolf_done` 当日去抖 + 理由合并 |
| P1-1（风向标死离场） | 两者都可能卖同主题票 | 优先级：P1-1（主题证伪）> P1-6（持仓优化）；P1-1 命中时 P1-6 跳过该主题 |
| `board_half` / `profit_take` | 多条卖出理由叠加 | 统一走卖腿管道；同一标的当日只执行一次（取最优先理由） |
| 拥挤黑名单 | 已用于选股 | 卖出侧可复用（拥挤度高的优先卖） |

### 2.7 验证方案

1. **规则层单测**：构造 3 只持仓、rs 已知且相差 >3% → 断言只卖 rs 最低那只，且不卖底仓部分；
2. **语境门单测**：`4-2`/`C杀` 语境下 → 断言不产生任何卖出（防"替机构接盘"）；
3. **优先级单测**：同主题同时命中 P1-1 与 P1-6 → 断言只走 P1-1 且不重复卖；
4. **历史回放（需数据）**：用 `buy_point_log.jsonl` + 日线，比较"执行/不执行去弱留强"的 T+5 收益差
   —— **这是决定是否上线的关键证据**，因为狼大自己也提示该动作可能是陷阱。

### 2.8 待你拍板的点

1. 作用范围：仅 T 仓（推荐）还是含底仓；
2. 判据主键：`rs`（推荐，与 P0-2 同口径）还是"反弹幅度"（狼大字面更接近后者）；
3. 是否要做"换票"（二期）；
4. 上线前是否必须完成 §2.7 第 4 项的历史回放（我建议**必须**，否则违反狼大自己的警告）。

## 三、两项的共同原则（本仓已犯过的坑）

0. **先分清"哪个浪"**（见 §零）：方向判据一律用**主题浪**；大盘浪只做系统性护栏。
   本仓已因此踩过一次坑（P1-3 第一版用大盘浪，会把大盘 `4-2` 时所有 253 误禁），且 `trade_graph.py:675` 早有明文警告——
   任何新设计开口前先 grep 一遍是否已有同类原则，避免重复犯错。
1. **单一定义处**：rs 口径、风向标判据、语境标签都只定义一次，两边引用同一函数（避免 S7 那种两套并行规则）。
2. **删除/新增都要配"保留清单"**：本设计明确不动 `dist_prevlow`（位置闸口径）、不动底仓保护、不动 P1-3 的 253 闸门。
3. **fail-closed 的边界**：语境类判据缺失时倾向不动作（P1-3 已如此）；但**代码级故障**（import 失败）不应封死买路。
   注：P1-3 更正后，**主题浪数据缺失改为放行**（数据缺失是运维问题，不该封死买路）；仅**大盘系统性下跌**才拦。
4. **每项都要有可回退开关**，且默认值取保守侧，待 dry-run/回放后再放开。
