# 逐事件买点一致率 · 统一评测口径（v1）

> 生成：2026-09-03 · 脚本 apps/main_line/score_buy_point_alignment.py · 数据 data/buy_point_alignment_score.json
> 目的：回答“我们和 Wolf 买点一致率是多少/怎么提高”，先统一口径、给出诚实基线，再逐通道验证提升。

## 1. 三个口径（分层回答，不要混用）

| 口径 | 定义 | 当前基线 | 用途 |
|---|---|---|---|
| A. 严格同日（盘口） | 系统 254/253 触发与 Wolf 买入同一天 | **254 同日 4.2%（1/24）**；并入 253 约 29%（5min 回放） | 衡量“盘口触发是否同构”——Wolf 多数买点不是 254，不是主要差距 |
| B. 事件级 ±5 交易日 | Wolf 事件日 ±5 交易日内，系统有同类动作（新建/回补/加仓/切换/T） | **254 子集（E05/E06/E08/E12/E13，24 行）：±5日内 9/24=37.5%（触发样本内 9/13=69.2%）**；全 15 事件逐日对齐需要候选/执行历史重放，当前数据不足 | 用户选定的主口径；需逐步补齐每日系统动作回放后才能完整打分 |
| C. 动作通道覆盖率 | E01–E15 每个 Wolf 动作，系统是否有对应 intent 通道（不看时点） | 旧（建仓=新开）**43.3%** → P3 v0+probe **93.3%**（14/15，仅 E06 无通道） | 结构性差距的代理指标——不是一致率，是“可能性上限” |

## 2. 为什么没有一个数字能回答“一致率是多少”
- Wolf 语料是**自述**不是对账单（含计划/未成交），系统是模拟盘；缺少同口径的逐日系统动作序列。
- 不同模块各有口径：主线重放 81% / 浪型 75-83% / 高低位 79% / 宏观 10/10 / 轮动案例 20/20——不能简单加权。
- E01–E15 事件级旧审计“加权约 57–60%”用的是同向/部分/不同的人工分类（含 rotation B3 等部分匹配），与 C 口径（43.3%）不能直接比，需统一到同一张判定表。

## 3. 提高路径（每项都要回填到本基准再算数）
1. **P3 三仓档位（已完成 v0 + probe，P3_TIER_MODE=1）**：把 C 从 43.3%→93.3%（通道层）；把 B 中“回补/加厚”类事件变成可执行通道。
2. 253 全护栏 + 分步链（254 后 3 日小额回补）：目标把 A 从 29% 抬向 40-50%（±3 日内）。
3. 个股趋势线/前高回补触发（E05/E08 站上 20/60 日线回补）。
4. 主线内切换下沉个股级（E09/E11/E12 rotation B3 rel-low 逐股）。
5. ETF 执行通道（E08/E14）。
6. 记录系统每日实际动作（新增 buy_point_log）→ 未来可直接算 B 口径，不再依赖人工回放。

## 4. 数据缺口（要补齐才能测 B）
- 每个 E 事件前后 ±10 交易日，系统候选链/自动通道**实际触发日**（254/253 已有部分：data/crowding_pit/wolf_dip254_backtest.json）；
- E01-E04/E07/E09-E11/E14 的“放行/部分”目前只有 wave/quadrant 判定，无每日系统买卖序列。

## 5. 第一批通道实验（2026-09-03）：个股“站上20日趋势线回补”触发 v0

- 脚本 apps/main_line/backtest_wolf_trend_refill.py · 数据 data/trend_refill_backtest.json（E05/E06/E08/E12/E13 同 24 只代理股）。
- 触发定义（日线近似“站稳趋势线才加”）：close>MA20 且 MA20>MA60 且 前收≤前MA20（由下重新站上）。
- 结果：触发 18/24；同日 0；±3 日 4/24（16.7%）；±5 日 6/24（25%）。按事件：**E12 低吸型 5/6**（±5日内），E08 1/6，E05/E06/E13 全 0。
- 结论：这个触发只对 **E12 式“破位后站回/低吸”** 有效；E05/E13 是**趋势内继续加仓**（价格一直未跌破 MA20），需要另一类触发：上升趋势内缩量回踩 MA10/MA20 企稳再加仓（待下一轮实现并回填本评测）。
