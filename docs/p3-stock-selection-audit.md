## 2. 高位/低位两套相反规则

2026-09-04 15:07 长帖：

> 高位方向：大科技这些，**避开公募重仓**，**卖强的、留弱的**，拉升后都走；
> 低位方向：**避开暴雷 ST**，找**辨识度最高的老龙头**埋伏，**留强丢弱**。

我们之前的 `stock_select.py`：

- 只有 ST 过滤（低位规则的一半）；
- 没有高位“避开公募重仓 / 卖强留弱 / 拉升后都走”；
- 没有低位“老龙头 / 留强丢弱”；
- 没有位置分层，直接按 5 日涨幅排。

这是**把两套相反规则混成一套**。

## 3. 自设规则清单（之前代码）

| 自设规则 | 问题 | 狼大对应 |
|---|---|---|
| 把 theme YAML 的 `leader/ladder` 当核心/龙头 | 这是我们 agent 复核的“选源/核心”，不是他的板块内分层 | 核心/风向标/龙头/龙2/杂毛要按板块内辨识度、绑定关系、人气判 |
| 按 `ret5` 排序 | 单因子动量；把“辨识度”代理成“涨幅” | 他看核心绑定、风向标、筹码、量价、位置 |
| `theme_verdict=trial` 才选股 | 把主题 gate 直接当个股许可 | 方向只是前提，个股还要过核心/龙头/位置/筹码 |
| `--max 8` | 任意上限 | 他说同板块尽量找 **2-3 支**（2026-01-26） |
| `leader` 优先 | leader 不等于核心；有时做二供 | 2026-04-13 龙头不做做二供；2025-12-06 核心≠龙头 |
| ST 过滤 | 只覆盖低位规则 | 高位还要避开公募重仓、卖强留弱 |

## 4. 单因子机械判定清单

| 单因子 | 之前怎么用 | 为什么不对 |
|---|---|---|
| 5 日涨幅 | 候选排序主键 | 涨幅是结果，不是辨识度；高位追强、低位抄弱要分开 |
| 主题 verdict | 直接决定候选域 | 主题 gate 只解决“做不做这条线”，不解决“买哪只” |
| 市值 | 只作为展示 | 他的核心是“板块内总市值前 5 + 绑定板块 + 营收拐点”，不是单纯市值 |
| leader/ladder | 直接当层级 | 他的层级是核心/风向标/龙头/龙2/杂毛，leader 只是其中一个标签 |

`docs/wolf-buy-gap-audit.md` 已明确列过三处结构性冲突，其中一条就是：

> **辨识度代理做成动量因子**；机构式“先板块后个股” vs 他的游资式；选股域与可执行域不一致。

这次 `stock_select.py` 正好又踩了第一条。

## 6. P3 正确形态（下一步）

1. **事实层**：主题 focus/trial + 个股事实（已做）。
2. **分类层**：按 B1 规则判核心/风向标/龙头/龙2/杂毛；
   - 核心：板块内总市值前 5 + 绑定板块 + 营收拐点；
   - 风向标：情绪/机构风向标，先看它；
   - 龙头/龙2/二供：按板块内辨识度、涨幅/成交额/人气；
   - 杂毛：排除。
3. **场景层**：高位/低位两套相反规则；主线的 regime；同板块 2-3 只。
4. **执行层**：P2/P3 gate → `calc_position`（带 theme_id）→ caps → 5 天持有复核（只列每日涨幅）。
5. **验证**：case-based，不用单因子回测定阈值；引用 B1 191 条和 A11 29 条买入规则审计。

## 7. 不做

- 不再用 5 日涨幅/市值/主题 verdict 单独决定选股；
- 不再把 `leader/ladder` 叫核心/龙头；
- 不再用单因子回测调阈值；
- 不新增“看起来合理”的自设规则，除非有原话/判例支撑。
