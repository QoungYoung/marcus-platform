# 计划：退出/兑现层对齐（G3 尺子 → 兑现口径）

> **给执行 agent 的完整交接**：目标是让系统的**卖出/兑现行为**与狼大一致。本文自包含：背景、现状、狼大原语料、开发计划、验收标准、环境红线、以及**明确不要做**的事。
> 写于 2026-09-13。作者上一轮已完成"方向层（主线判定）"的对齐，本文是**下一步**。
> 术语：**腿** = 一次买卖动作；**t 账户** = 做 T 专用模拟账户；**PIT** = 只用当日及以前的信息。

---

## 1. 背景

**项目**：`marcus-platform`（A 股交易辅助系统，Python + FastAPI + APScheduler + PostgreSQL）。
**目标**：复刻一位交易者（下称"狼大"）的做法——不是复刻收益数字，而是复刻他的**判据与动作结构**，并用他本人的语料原话作为设计依据。

**已完成的上一阶段（方向层/主线判定）**：用"**池 = 主题近 5 日成交额占比 topK ∩ 近 5 日相对强度>0 → 池内 r5 top1**"取代了旧的 `mainline_gate`。
- 与他"股票主线层"口径对齐：**recall 75%**、他方向落我们 top1 **54%**（随机 7.7%）、top3 **85%**（随机 23%）；
- 收益：2026 后 5 日超额 **+1.03%（t=3.37）**、2025 **+0.34%（t=3.01）**；相对"全主题对照"的两年超额一致（+0.35pp / +0.30pp）；
- 生产开关：`WOLF_MAINLINE_SELECT=1`、`WOLF_MS_POOL_K=3`、`WOLF_MS_USE_GATE=0`；每日 18:55 产出，次日 08:00/08:25 消费。
- 详见 `docs/wolf-structural-pool.md`、`docs/wolf-behavior-blueprint.md` §16。

**为什么下一步是"退出/兑现层"**（三条证据，全部为既有实测）：
1. **买点被证明是"中性"的**：254/253 触发条件的后 5 日胜率 **47% ≈ 同池同日随机买入基线 49%**（n=428 vs 23,512）——**买点不是胜率来源**；
2. **兑现方式才是**：全部样本 T+5 收盘胜率 47% → 加 **+3% 小止盈 → 53%**；加 **−3% 止损 → 39%**（+5%/−3% 组合 36%）；
3. **我们现在的尺子是错的**：评估做 T 腿时用"买入后持有 T+5"，量出 **47%**；而生产**已实现卖出腿**（`paper_trades` 中 `direction='卖出' and profit<>0`）是 **63.6%、+2,828.5**。
   → **在错的尺子上下任何结论都无效**，所以本计划的**第一阶段就是换尺子**。

## 3. 狼大原语料（设计依据，带日期）

> 规则：**每条判据都要能指回下面的原话**；找不到原话的机制不要做（用户红线）。

### 3.1 仓位两分法（底仓 vs 做 T 仓）——所有兑现规则的前提

- 「所以我这里**仓位不会低于 65% 收盘，日内做 T 仓位 20%**」（2026-09-03）
- 「所以我一直说 **做 T 套利的仓位是做 T 套利的 底仓是底仓**。」（2026-08-05 10:38）
- 「**分不清做 T 仓位和底仓的区别就是『贪』**。」（2026-08-05 13:30）

### 3.2 做 T 的目标幅度与出场（本计划核心）

- 「**2 点到了 力度不够**…今天**目标 3%-4% 实际 2% 结束今天半导体做 T 操作**。」（2026-09-02）→ 达到目标幅度即兑现；**力度不够也收工**
- 「做大科技方向**最低套利 3 个点、最多 10 个点**，红利做不到这个数字。」（2026-08-05 09:58）
- 「**这半小时内日均线那条黄线绝对不能破，突发跌破直接走**；没跌破就找这半小时的高点。」（2026-08-05 10:48）→ **破黄线离场 + 不破则找分时高点出**
- 「**做 T 的前提是自己判断能执行：做错会撤、涨上去舍得卖**。」（2026-08-04）
- 「光和半导体都只是 B 反预期，**不做 T 死拿是回不了本的**。」（2026-08-06 15:33）
- 「**我今天没抄底 没有资格 T。**」（2026-08-25）→ **做 T 必须先有低吸仓位**

### 3.3 高位做 T / 低位不动（分类型分工）

- 「**高位方向是要 T 的，低位方向（他下半年最看好的方向）是不动的**。」（2026-08-05 10:03）
- 2026-09-04 15:07 长帖（分类型总纲）：**高位**＝**卖强留弱、拉升后都走**；**低位**＝找**辨识度最高的老龙头**埋伏、**留强丢弱**；超短＝按链条走、要快。

### 3.4 退出判据（"什么时候算走完")

- 「（为什么不做卫星）因为**十字星后第二天没有突破，上面卖单一点没撤 还加大了**…然后**板块没有带动效应**。」（2026-02-12）→ 三个条件：不突破 + 卖单加大 + 无带动
- 「**诱空一般最多三次。之后很容易短期买不回来。**」（2026-09-07）→ 影响卖出节奏（不要被诱空骗出）
- 「大光拔估值 3 天后 → 二线光 2-3 天 → 光纤 3 天 → 光上游 3 天 → 光边缘 2 天。然后结束。继续等下一波」（2026-05-29）→ 链条节奏（兑现时点的自上而下顺序）

### 3.5 周末/事件前避险（已上线，需按新尺子复验）

- 「**2 点半 如果还是缩量 还是不拉升 我会先把这两天 T 进去的仓位出来一半**…**65% 仓位过周末**。」（2026-08-21）

### 3.6 尾段规则（**当前系统没有"尾段"状态**）

- 「就等吃最后一段 不管吃不吃得到我都不会加仓 **顶多做 T 然后最后一段撤掉**」（2026-09-04）

### 3.7 止损口径（与我们的六层止损不同）

- 「**顶多就是指数破位后的止损**…哪怕止损就是我的技术策略抗不住这个波动而已。」（2026-08-25）
  → **他的止损以指数破位为准，个股不止损**；我们的六层止损里"个股级止损"需按此复核（缺口 G8）。

### 3.8 其他相关硬参数

- 关键整数位：「在指数**第一次接近 4000** 的时候我第一次把**底仓**给减了」（2026-08-26）／「4000 收费站」（2026-09-01）
- 黄金（事件驱动兑现）：「沃十讲话 解读偏鹰 黄金跌 — 数据出来，不及预期 黄金涨…」（2026-08-31）／「黄金股要**舍得卖**」（2026-09-03）

## 5. 开发计划

### 阶段 0（**必做第一步**）：换尺子 —— 分类型度量 + 生产实际离场口径

**为什么**：现有评估用"持 T+5"量做 T 腿（47%），与生产实际（63.6%）口径不一致 → 后续任何结论都不可信（checklist B7 原文）。

**交付物**：
1. `jobs/eval_leg_metrics.py`（新）：从 **`paper_trades`**（`direction='卖出' and profit<>0`）与买入侧成交流水重建**每条腿**（做 T / 低位埋伏 / 确认加仓 / 逃顶），逐腿计算：
   - 做 T 腿：**成功率 + 盈亏比 + 持有分钟/天数分布 + 兑现幅度分布**；
   - 低位埋伏腿：**区间收益 + 最大回撤 + 持有天数**；
   - 确认加仓腿：**延续率 + 加仓点超额**；
   - 逃顶腿：**避开的跌幅**（对照未减仓反事实）。
   - 每组都要有**同池同日基线对照**，并给绝对与超额两个口径。
2. 一页**度量规范**（写进 `docs/`）：腿的定义（如何从流水配对出腿）、口径、样本期、最小样本量（n<100 只作探索）、以及**重叠样本的处理**（同一时点的多腿高度相关 → 关键结论要做**块状/分批 t 检验**，不要只报日度 t）。
3. 用新尺子**复算**尚未验证的机制：G9 周末避险（`WOLF_WEEKEND_HEDGE=1`）、`WOLF_BOLL_MID_EXIT=1`、`WOLF_CUSHION_CAP=1`。

**验收**：①同一批腿用"持 T+5"与新口径分别量 → 复现"47% vs 63.6%"的口径差（证明尺子修对了）；②给出四类腿的基线指标表；③把三个既有开关的增量收益/胜率影响量化出来。

### 阶段 1：兑现口径对齐（R1–R5）

**做法**：**先离线验收、后接线**。
1. 在 `jobs/eval_d12_vol.py` 基础上扩展为 `jobs/eval_exit_rules.py`：在同一批腿（阶段 0 重建）上做**规则变体对照**：
   - 基线：现状（今日生产规则）
   - V1：+**3% 目标幅度**兑现（R1）
   - V2：+**破分时黄线**离场（R2）
   - V3：V1+V2
   - V4：**做 T 前置**过滤（无低吸仓不做 T，R3）
   - V5：高位/低位分类型（R4/R5）
   输出：每变体的胜率、盈亏比、期望、最大回撤、以及**分档**（高/低位）表现。
2. **只有**当某变体在**两年样本**（2025/2026）与**分段（H1/H2）**都优于基线，才进入接线。
3. 接线方式：改动集中在 `wolf_discipline.py`（`profit_take()`/`board_half()`）与 `t_monitor` 的卖出腿参数；**一律带开关**（默认关），并在 `daily_decision` 的 L6 退出层登记。

**验收**：做 T 腿胜率**不低于**现状 63.6%（不劣化），且"胜率/盈亏比/最大回撤"至少一项显著改善；给出前后对照表与样本量。

### 阶段 2：退出判据与尾段（R7、R9、R10）—— 视阶段 1 结果决定是否做

- R9（不突破+卖单加大+无带动）与 R10（诱空三次）需要**分时/盘口数据**；先确认数据可得性（`t_monitor` 快照里有什么），**数据不足就不做**（不要用日线近似硬凑）。
- R7（尾段状态）需要定义"尾段"的**可识别条件**；若只能用事后信息识别 → **不做**（前视）。

### 阶段 3：止损口径复核（R8 / 缺口 G8）

- 对照实验：现状六层止损 vs「**只在指数破位止损**」（个股不止损）；
- 指标：**最大回撤、亏损分布尾部、被止损后 N 日的反事实收益**（判断"割在最低点"是否成立）。
- 若证据支持他的口径 → 把个股级止损**降级为提示**（不是直接删，需与用户确认）。

## 6. 环境与红线（**必读**）

1. **重任务一律本地跑**：`marcus-backend` 容器 cgroup 只有 **512MB**，在里面跑大 pandas/多进程会把 uvicorn 一起 OOM 掉、**导致生产容器重启**（本会话发生过两次）。
   - 本地已有：全套依赖（requests/psycopg2/sqlalchemy/pandas/numpy/paramiko）、promax 直连；
   - 需要读生产 PG 时用**进程内 SSH 隧道**：`.dsh-tmp/wolfbt/local_pg.py`（`ensure_tunnel()` + `DSN`）；**不要**依赖后台常驻隧道进程（会被 shell 重置杀掉）；
   - 大数据先落**本地 SQLite**（`data/mkt_bars_local.db`），再一次性 `COPY` 进 PG。
2. **改 `.env` 必须重建容器**：`cd /opt/marcus-platform/docker && docker compose up -d --force-recreate --no-deps backend worker`（`docker restart` 不会重新读 `.env`）。
3. **传文件进容器**：`docker cp`（宿主顶层目录不映射到 `/app`）；**只往新建子目录传数据**，覆盖 `/app/data` 根目录同名文件前必须备份+比对（曾覆盖过生产黑名单）。

### 9.2 取证方法（**要新增判据时按这个流程**）

**通道**：dsh 网关 `POST http://marcus-dsh:3001/chat`，body `{"message": "...", "session_id": "..."}` → `{"reply": "..."}`
- ⚠️ **该地址只在容器网络内可解析**（本地跑不了）→ 脚本要在 `marcus-backend` 容器里执行；
- 现成调用封装：`jobs/wolf_d12_evidence.py` 的 `call_dsh()` / `_extract_json()` / `slices_for()` —— **直接复用，不要重写**。

**标准流程**：
1. **按时间切片**：把逐日/逐期文档切成"月"或"季度"片（单片 ≤ ~40KB）。`slices_for()` 已支持两种版式：
   - 版式 A（`### YYYY-MM-DD` 日块，如 `xls2026`、NGA）；
   - 版式 B（**动作分类表**，日期在行尾**全角括号**里，如 `xls2122`/`xls2025`）→ 按**行内日期重组**到季度。
2. **写 prompt（要点）**：
   - 明确**唯一任务**与输出 JSON schema（例：`{"items":[{"date":"","kind":"","quote":"","criterion":""}]}`）；
   - **强制要求逐字原话**，并写"**找不到就不输出，绝不编造或用你自己的话冒充**"；
   - 要求**日期**；按需加 `scope`（`long_term`/`conditional`）、`role`（主线/支线/超短…）等字段；
   - **禁止泛泛总结**（"不要输出泛泛的交易道理"）。
3. **跑 + 落盘**：每片一次调用，结果按片累积写入 JSON（**保留 raw reply 便于复核**），断点续跑（跳过已完成片）。
4. **人工复核**：抽读 10–20 条，确认 `quote` 是**原文**（不是改写）、`date` 正确。
5. **写进文档时**：每条结论**附原话与日期**；若同一主题有冲突表述，**按时间列出来**，不要只挑一条。

**发现新语料源时**：先更新 §9.1 的表，再开始抽取（避免多份互相矛盾的口径）。

② 可算化                     → 把判据翻译成 PIT 可算量（例："光+半导体占市场50%成交量" → 主题近5日成交额占比）

⑤ 上线                       → 开关默认关 → 影子模式（只记录）→ 经用户批准才开启

### 10.4 用户的工作原则（比技术细节更重要）

1. **"真删不要停用"**（用户原话）：已证伪的机制要**删代码**，不要留一个"默认关的开关"——否则后续 AI 开发会误以为我们还在使用，行为会被它污染。
2. 每项改动 = **一个可回退开关** + **定向单测** + **独立 commit**（不要混在一次大提交里）。
3. **生产变更（尤其改 `.env`、开启开关）必须经用户明确批准**；先影子模式（只记录）再启用。
4. **不做没有语料支撑的自造机制**；且必须把""他这么说"与"这么做有效"**分成两步验证**——语料给出**假设**，数据给出**结论**，两者都不能省。
5. **否定结论也要留档**（写进 `docs/wolf-alignment-checklist.md` §F），不要只留一句"试过了"。
6. **语料绝不手打转写**（曾污染产物，已删）；要结构化就**用 dsh 子代理逐条精读**，**明确拒绝关键词提取/正则**。
7. 输出里要区分**他的原话**与**我们的代理指标**，不能混为一谈。
