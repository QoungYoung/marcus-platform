## 5. 为什么 risk_level 全错

这次任务把 `risk_level` 定义成“收盘跌破它就减仓”。但狼大的 3922/3900/3888 在当天**已经在收盘价上方**——它们不是“下方支撑”，而是：

- **已跌破的位**；
- **站不回就确认破位**；
- **反抽减仓/失效线**。

agent 按字面选了“下方下一档支撑”：

- B/C 选 3800.11，而不是 3922；
- A 选 3316.45，而不是 3370；
- D 选 3816.58（他其实把 3816 当“企稳加回”的支撑，不是风险触发）。

**这不是 agent 不会算，是 task schema 少了 `broken_support / reclaim_threshold / failure` 这些角色。** 用“跌破下方支撑”的语义去问他“上方已破位”，必然答错。

## 6. 这次真正证明了什么

1. **候选覆盖不是最大问题**：完整引擎候选里，他的 10 个点位都有 ±0.5% 内的近位（10/10）。
2. **精确点位仍选不中**：10 个里只有 3816 精确命中；其他都偏移 0.07-0.41%。
3. **角色/触发语义是最大问题**：agent 把“已跌破的位”当压力，把“下方下一档”当 risk；4/4 风险位错。
4. **不能再说“agent 能找到他的点”**：它找到的是“附近的结构”，不是“他的那个点 + 他的角色”。

## 7. 下一步

1. 把 role 枚举改成：
   - `support_holding`（还在下方、未破）
   - `support_broken`（已跌破、等反抽）
   - `reclaim_threshold`（站不回就确认）
   - `resistance`（上方压力）
   - `invalidation`（失效线）
2. 重跑同一盲测，问法改成：
   - “哪些位是已跌破、站不回就确认的？”
   - “哪个位一旦收盘站不回，最应该减仓？”
3. 仍然只读，不接交易；先看角色是否 4/4 对，再看点位精度。
