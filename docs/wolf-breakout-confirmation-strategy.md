# 突破确认：与狼大策略的对照与落地方案

> 目标：回答两个问题——① 现有的“突破确认”实现是否符合狼大的策略？② 如果不符合，应该怎么改。
> 依据：① 狼大 2016-2026 语料（25,807 条）+ NGA 楼主 2026-07~10 发言；② 现有代码 `confirm_chain` / `trend_channel` / `trend_breakout_monitor` / `wolf_volume_gate` / `stock_confirm_judge` / `switch_builder`；③ `docs/ai-agent-lessons-from-b-rebound.md` 的方法论；④ `docs/wolf-buy-parameter-ledger.md` 的参数出处纪律。
> 结论先行：**骨架像，执行不像。现有实现更像“低位埋伏确认”，不是狼大的“突破确认”。**
>
> **2026-10-30 更新：C 类纯自设规则已全部移除，实际执行以 [v2 规则](wolf-breakout-rules-v2.md) 为准；本文只保留对照与方案，旧公式中的 N=20/1.005/z≥1.5/0.97/0.8/3% 均已废弃。**

---

## 0. 结论

现有系统把“突破确认”拆成了四套互不一致的东西：

| 实现 | 本质 | 与狼大的关系 |
|---|---|---|
| `confirm_chain` S1-S4 | 低位埋伏链：缩量止跌 → 结构到位 → 放量突破 → 站稳 3 日 | **骨架符合**，但只覆盖“低位突破”，且 `突破候选`（未站稳）也放行 |
| `trend_channel` T1/T2/T5 | 趋势突破链：带量破 20 日高 → 3 日内站稳 → 高位放量否证 | **最接近**，但默认关、只在回测/影子，且 T3/T6/T7/T8 未做 |
| `trend_breakout_monitor` | 资金 TOP-N + 放量破 20 日高 + MA20 上 → 长期池 | **买了就进池，没有站稳/回踩/失败处理**，且未启动 |
| `wolf_volume_gate` | 指数级 2WE/3WE + 关键位真假突破 | **方向对**，但只管大盘、默认关、数据停在 9/15 |

狼大的突破确认不是“一个信号”，而是**位置/段位 → 选板块资格 → 突破 → 站稳 → 回踩 → 加仓 → 破线止损**的一条链。现有系统只做了中间两段，而且把“突破候选”当成“确认”来用。

## 1. 狼大原话里的“突破确认”

### 1.1 完整链条（他自己给过的最完整版本）

> “下跌，缩量，止跌，企稳，反抽，压力位补量，反弹，过颈线，加强，新高，反转，这是一套完整体系流程。”——2026-02-03

> “3-2 的结束确认条件是什么：日线级别 W 底后的红三兵表现，突破颈线的加速，4006 站稳三天后量能的暴涨，吃技术流和踏空资金的进场溢价。”——2026-01-12

> “放量过 3936 的压力是 3-3 的左侧，站稳 3 天 4006 是确认。”——2025-12-19

这三句把“突破”拆成了**左侧（放量过压力）**和**右侧（站稳 3 天）**两个不同阶段。现有很多实现把两者混成一个 `stage`。

### 1.2 四个层级，不能混

| 层级 | 狼大的判据 | 作用 |
|---|---|---|
| **市场/段位** | 4-3 / 4-4 / 4-5 / 下跌 1 浪；4006、3764 等关键位；2WE 地量 / 3WE 突破级 | 决定“能不能做”，不是“买什么” |
| **主题/板块** | 量能活跃（近一周 ≥2/3 天数在 10 日量能上）+ 资金没有 5 日连续流出；主线响应；避险不抢戏 | 决定“做哪个方向” |
| **个股/ETF** | 突破压力位/颈线、放量、收盘位置、站稳 3 天、3 个 15 分钟、回踩不破 | 决定“买哪只、什么时候买” |
| **执行** | 9:45-10:00 / 14:00-14:30；高开不追；第一根加一半、第二根红 K 打满；破线止损 | 决定“怎么买、买多少、错了怎么办” |

### 1.3 真假突破的判据（按他的原话）

| 判据 | 原话 | 含义 |
|---|---|---|
| 量能门槛 | “不上 3WE 的突破就是诱多”——2026-09-03；“2WE 是地量了，只要放量就没事了”——2026-08-20 | 指数攻关口，量不到 3WE 不认 |
| 放量吃挂单 | “放量突破，一口吃完上面挂单。不行分两口也可以。”——2026-02-12 | 突破要吃掉上方卖压，不能缩量过 |
| 不带量=清仓 | “不带量突破压力线，清仓。”——2025-06-05 | 假突破的极端处理 |
| 收盘位置 | “收盘站稳”“收在趋势通道上沿上方才叫确认突破”——2022-06-01 | 看收盘，不看盘中一瞬 |
| 3 天站稳 | “站稳 3 天 4006 是确认”——2025-12-19；“4006 站稳三天后量能的暴涨”——2026-01-12 | 日线级确认 |
| 3 个 15 分钟 | “站上去必须要 3 个 15 分钟 K 线确认”——2025-08-14；“先看 3 个 15 分钟”——2025-08-15 | 盘中确认，等 45 分钟 |
| 主线响应 | “真反弹还是诱多，看看主线题材动没动”——2026-01-13 | 突破必须有主线共振 |
| 避险不抢戏 | “缩量拉银行/贵金属 = 诱多”——2026-08-05 | 避险方向强、主线弱，突破不可信 |
| 放量滞涨 | “高位这些 PCB/CPO 都是放量滞涨，其实就是交换筹码了，不追高。”——2026-05-11 | 高位放量不涨 = 派发 |
| 高开不追 | “高开不追是基本常识”——2026-09-03 | 不在开盘追突破 |
| 突破后回踩 | “突破后的回踩，叫右侧。”——2025-10-27 | 回踩确认才是右侧买点 |
| 突破失败 | “这次做突破失败，损失是全场的 -2%。”——2025-06-13；“向下破线止损”——2022-06-08 | 失败要认，不能补仓 |

### 1.4 买点阶梯（他最具体的仓位规则）

> “突破下跌趋势第一根开头我加一半，突破后的第二根红 K 尾盘打满，然后之后就只等卖点，中间会有调仓，但是没有减仓。”——2026-06-15

> “我的操作是突破加仓，回踩确认加仓，中间不做大级别操作，向下破线止损。”——2022-06-08

> “要么带量突破，空翻多，50% 仓位加到 80%。”——2025-06-05

> “一个票最多买 2 笔，卖 2 笔。”——2025-02-07

这四句合起来是一个明确的阶梯：

1. **突破第一根**：加一半（或 50%→80%）；
2. **第二根红 K 尾盘**：打满；
3. **突破后回踩不破**：再加一次（独立机会，不算进“突破那 2 笔”）；
4. **向下破线**：止损；
5. 中间不做大级别减仓，只调仓。

### 1.5 失败/卖出

- 失败：跌回突破位/颈线下方，或“不带量突破压力线” → 清仓/止损。
- 高位：放量滞涨 → 减仓，不追。
- 目标：前高、0.618、整数关、板块目标位；到目标“走弱了才做减法”，不是到点就清。
- 被动止盈：跌破平台/趋势线/顶分型 → 撤。

## 2. 现有实现逐项对照

### 2.1 `confirm_chain` S1-S4

| 狼大要求 | 现有实现 | 判定 |
|---|---|---|
| 缩量止跌 | S1：价格止跌 +（量 z20<0 或净流出收窄） | ✅ 方向一致；但 `vol=None` 时 `vol_shrink` 空真放行（`WOLF_S1_VOL_REQUIRED` 默认 0）→ ❌ 数据缺失也放行 |
| 结构到位（W 底/低位横盘） | S2：双底（两低点差 5% 内、间隔 5-40 日）或 30 日箱体 <15% 且距 1 年高 <20% | 🟡 代理；参数自设，且“低位”用 80% 分位不是他的话 |
| 放量突破压力位/颈线 | S3：收盘 > 前 20 日高 ×1.005 且量 z>1.5 | 🟡 方向对；N=20、1.005、1.5 都是自设；只认“20 日高”，不认颈线/平台/均线；不检查收盘位置/上影线 |
| 站稳 3 天 | S4：突破后 3 日收盘 ≥ 突破日收盘 ×0.97 | 🟡 方向对；0.97 自设；不要求站上 MA5/通道上沿；`突破候选` 未站稳也放行 |
| 主线响应 | F3：`mainline_act <0.3` → 证伪 | ⚠️ 只在概念级 `position_class` 传入；`stock_confirm_judge` 逐票调用时**不传** → 个股级没有 F3 |
| 避险诱多 | F4：`hedge_act >0.6` → 证伪 | ⚠️ 同上，个股级没传 |
| 假突破（无量/回落颈线） | F1/F2 只写在 docstring | ❌ 未实现；跌回突破位没有独立动作 |
| 突破后回踩加仓 | 无 | ❌ 未实现 |
| 向下破线止损 | 无（只有 S1/S2 未满足时不动） | ❌ 未实现 |

**结论**：`confirm_chain` 是一个**低位埋伏确认器**，不是完整的突破确认器。它回答了“这个低位概念有没有止跌+突破”，没有回答“这个突破是不是真的、能不能加、错了怎么办”。

### 2.2 `trend_channel` T1/T2/T5

| 狼大要求 | 现有实现 | 判定 |
|---|---|---|
| 带量突破 | T1：收盘 ≥ 前 20 日最高收盘 ×1.005 且量 z≥1.5 | 🟡 方向对；N/1.005/1.5 自设；不检查收盘位置/上影线/吃挂单 |
| 站稳 3 天 | T2：突破后 ≤3 日，收盘 ≥ 突破日收盘 ×0.97 且 ≥MA10 | 🟡 方向对；他用“站稳 3 天 4006/通道上沿/5 日线”，我们换成 MA10 + 0.97 |
| 高开不追 | 无时间窗；只有 `chase_max=3%` 买腿价上限 | ⚠️ 3% 自设；没有 14:00-14:30 窗口 |
| 高位放量滞涨 | T5：pos20≥0.8 且最新量 z≥1.5 → 否证 | ⚠️ 只判“高位+放量”，没判“滞涨”（收盘位置/上影线/不创新高）；可能误杀健康突破 |
| 回踩确认加仓 | `scan_pullback`（默认关）+ `expr_pullback`（MA20±5%） | 🟡 有雏形；但默认关，且回踩不要求“不破突破位” |
| 失败/止损 | 无 | ❌ 未实现 |
| 14:00-14:30 延后 | 明确写“本版未做” | ❌ 未实现 |
| 分批 | 明确写“本版未做” | ❌ 未实现 |
| 主线响应/白线在上 | 明确写“本版未做” | ❌ 未实现 |

**结论**：`trend_channel` 是现有最接近狼大 E3 的实现，但它是一个**回测/影子通道**，不是生产闭环；而且“确认”只到“3 日不破 0.97+MA10”，没有回踩加仓/失败处理。

### 2.3 `trend_breakout_monitor`

- 口径：主力净流入 TOP-N + 今日最高 > 前 20 日高 + 量 ≥1.5×20 日均量 + MA20 转上 → 入长期池。
- 对照：这是“突破当天就进池”，**没有站稳 3 天、没有回踩、没有失败处理、没有主线/市场门**。
- 状态：`worker_main` 未注册；注释说旧 trend_break 信号回测证伪（PF~1.05，样本外不稳）→ **死代码/待回滚**。

**结论**：不符合狼大的“突破确认”，更像“放量突破初筛”。

### 2.4 `wolf_volume_gate` G10

- 口径：全市场成交额分 `地量(<2WE)` / `常态` / `突破级(≥3WE)`；指数距关键位 <1.5% 且自下而上攻关口 + 量未达突破级 → `fake_breakout_risk`；收在曾站上的关口下方 → `breakdown_risk`。
- 对照：**这是狼大“不上 3WE 的突破就是诱多”的直接实现**，方向最正。
- 问题：只判指数，不判个股/主题；`WOLF_VOLUME_GATE` 默认 0；`data/wolf_volume_gate.json` 的 `as_of=20260915`，一个半月没更新；关键位硬编码 3800/3900/4000，不跟浪型/结构走。

**结论**：符合“市场级真假突破”的一部分，但没有接进突破确认链。

### 2.5 `stock_confirm_judge` + `switch_builder`

- `stock_confirm_judge`：对主线概念成分逐票跑 `confirm_chain`，输出 `stage` 和 `confirm` 比例。
- `switch_builder`：`BASE_STAGES=("突破候选","确认")` → 布 253/254 **低吸腿**（不是突破价腿）。
- 对照：
  - ✅ 用突破确认做“选票过滤”，再等回踩低吸，方向接近“突破后回踩”。
  - ❌ `突破候选`（未站稳）与 `确认` 同等对待。
  - ❌ 254 腿是“破前一日低点+缩量”，可能远低于突破位，不保证“回踩不破突破位/MA”。
  - ❌ `stock_confirm_refresh`、`rotation_switch_arm` 已在 2026-10-29 清理中移出 `tasks.yaml`；`stock_confirm_result.json` 停在 **10-29 08:23**，10-30 未刷新。
  - ❌ 没有硬门：`p2_entry_gate` / `check_entry_filters` 不读 `confirm_chain`。

**结论**：这是“用突破确认选票、用低吸腿入场”，不是“突破确认后按突破价/回踩价分批建仓”。

### 2.6 `entry_timing`（另一条路）

- 口径：上证成交额/20 日均额 ≥1.20 + 收阳 + 收盘在日内上半区 + 收盘 <MA60 → 买宽基 ETF，持 20 日。
- 自述：“个股级单因子（突破/回踩/放量砸盘/流动性事件/结构）⇒ 全部≈0 或跑输随机；只有市场级共振有正超额。”
- 对照：这不是突破确认，是**市场级放量反转入场**；但它的结论动摇了“个股突破确认”本身的统计有效性。
- 状态：调度项不在当前 `tasks.yaml`（只在 `tasks.yaml.bak_20261029`），代码和消费方还在。

## 3. 差距的根因（按危害排序）

1. **位置/段位没有前置**。狼大反复说“同一个形态在不同位置含义相反”；现有 `confirm_chain` 用“距 1 年高 <80%”粗判低位，`trend_channel` 用 pos20≥0.8 否证，都不是“4-3/4-4/4-5/下跌 1 浪”的段位门。→ 同样的突破，在 4-3 和 4-5 会被同一套规则处理。
2. **选板块资格没接**。“量能活跃（近一周 ≥2/3 天数在 10 日量能上）+ 资金没有 5 日连续流出”是他的“选板块第一要素”，`wolf_theme_vol_fund.py` 已实现但默认关；突破确认链里完全没有这道门。
3. **市场级量能门槛没接**。3WE/2WE 是他说得最硬的数值之一；`wolf_volume_gate` 默认关、数据过期、关键位硬编码。
4. **“突破候选”=“确认”**。`confirm_ok = stage in ("确认","突破候选")`，`switch_builder` 的 `BASE_STAGES` 也包含“突破候选”。狼大明确说“放量过压力是左侧，站稳 3 天才确认”。→ 系统把左侧当右侧用。
5. **没有失败状态**。跌回突破位/颈线没有动作；`F2` 只写在 docstring。→ 假突破只能靠后续 `下跌中` 被动处理，错过最佳退出。
6. **没有时间窗/不追高**。狼大用 9:45-10:00 / 14:00-14:30，高开不追；系统用日线信号+次日低吸腿，`T3` 未做，`chase_max=3%` 是自设。
7. **没有加仓阶梯**。狼大“第一根加一半、第二根红 K 打满、回踩确认加仓、破线止损”；系统只有“布一条低吸腿”。
8. **三套口径不统一**。`confirm_chain`（收盘>20 日高×1.005，量 z>1.5）、`trend_channel`（收盘≥20 日最高收盘×1.005，量 z≥1.5）、`trend_breakout_monitor`（最高>20 日高，量≥1.5×均量，MA20 上）各写一套。
9. **自设参数没有逐条过判例**。N=20、1.005、z=1.5、0.97、pos=0.8、chase=3% 都是自设；台账要求“每加一条规则，先拿专家已知判例过一遍”，现有测试没有这条。
10. **生产未接线/被清理**。`stock_confirm_refresh`/`position_judge`/`rotation_switch_arm` 已移出 `tasks.yaml`；`trend_channel` 默认关；`trend_breakout_monitor` 未启动；`wolf_volume_gate` 默认关。→ 现在没有任何一条“突破确认→下单”的生产链路。
11. **PIT/时态不完整**。日线信号 vs 14:30 决策；`today_low` 没有 cutoff；`mode`（盘中/盘后/回放）没有统一；`stock_confirm_result.json` 是不带日期的覆盖文件，容易过期。
12. **卖出没有联动**。突破确认只管买；止盈/被动止盈/破位是另一套，没有共享“突破位/颈线”这个失效锚点。

## 4. 新方案：分层状态机 + 硬门 + 影子

### 4.1 架构

```
L0 市场/段位（能不能做）
  wave_op ∈ {build, side} ∧ index_confirm ∧ market_amount ≥ 门槛 ∧ 非事件窗口
        ↓
L1 主题/板块（做哪个方向）
  theme_volfund_ok ∧ theme_qualify_struct ∧ mainline_act ≥0.3 ∧ hedge_act ≤0.6 ∧ 非拥挤
        ↓
L2 个股/ETF（买哪只、什么状态）
  detect_breakout → stand → retest → confirm / fail / fake
        ↓
L3 执行（怎么买、买多少、错了怎么办）
  时间窗 → 价格上限 → 分批 → 止损 → 止盈
```

**原则**（来自 agent lessons）：
- **段位前置**：L0 不通过，L2 再漂亮也不做。
- **事实与判断分离**：程序算 L0-L2 的事实和状态；agent 只判“段位/主线/真假”中数据不能唯一决定的部分。
- **判据可执行**：每条规则都要能算出数字；不能写“他引用过”这种查不到的判据。
- **描述 ≠ 筛选器**：不把“W 底+红三兵+颈线”直接当全历史筛选器；先用段位/窗口剪枝，再在窗口内找突破。
- **PIT 秒级**：14:30 的决策不能用 14:35 的低点；盘中不能用全天 bar；每个事实带 `as_of` + `mode`。
- **失败要响**：数据缺失 → 不发信号；不要输出“看起来正常”的过期结论。

### 4.4 L2 个股：统一突破状态机

用一个纯函数 `breakout_state(bars, vols, amount, ctx)` 输出状态，三套旧实现全部改为调用它。

**状态定义**：

| 状态 | 条件 | 动作 |
|---|---|---|
| `S0 观察` | 未突破；或段位/主题/市场门不通过 | 不做 |
| `S1 突破日` | 收盘 ≥ 前 N 日高 ×(1+buffer) ∧ 量 z≥1.5 ∧ 收盘在日内上半区 | 试仓 1/3~1/2（仅当 L0/L1 通过） |
| `S2 站稳中` | 突破后 1-2 日，收盘 ≥ 突破日收盘 ×0.97 | 持有，不加 |
| `S3 确认` | 突破后 3 日收盘 ≥ 突破日收盘 ×0.97（或 ≥MA5 连续 3 日）∧ L0/L1 仍通过 | 加到 2/3 |
| `S4 回踩确认` | 突破后回踩至突破位/MA20 ±3%，收盘不破突破位×0.97 | 加满/独立一次加仓 |
| `F1 假突破` | 突破日量不足/收盘在下半区/长上影；或次日跌回突破位×0.97 | 不买/撤销；已买则减 |
| `F2 失败` | 突破后 3 日内收盘 < 突破位×0.97 | 止损/清仓，不补 |
| `F3 高位放量滞涨` | 位置分位 ≥0.8 ∧ 量 z≥1.5 ∧ 收盘 < 当日高×0.995 ∧ 上影 > 实体 | 不追/减 |
| `F4 主线不响应/避险抢戏` | `mainline_act <0.3` 或 `hedge_act >0.6` | 不买/降级 |
| `F5 市场量能不足` | 攻关键位 ∧ 市场额 <3WE | 不买/只做 T |

**关键修正**：
- `突破候选` 不再等于“可执行”；只有 `S3` 及以后才允许新开/加仓。
- `S1` 只允许“试仓”，且必须有 L0/L1 通过；`S1` 不允许满仓。
- `F2` 必须有独立动作：跌回突破位×0.97 → 撤销/止损；不能等 `confirm_chain` 变成“下跌中”。
- `F3` 要判“滞涨”，不只是“高位+放量”：加收盘位置/上影线/是否创新高。
- `F4/F5` 在个股级也要传，不能只在概念级。

**统一突破口径**（旧版建议，含自设参数，已废弃；请用 [v2](wolf-breakout-rules-v2.md)）：

```
level = max(close[-N-1:-1])            # N 默认 20，标注“自设代理”
break = close[-1] >= level * (1+buf)   # buf 默认 0.005，标注“自设代理”
vol_ok = z20(vol) >= 1.5               # 1.5 自设代理；或 amount >= 1.5*MA20(amount)
close_ok = (close-low)/(high-low) >= 0.5 and upper_shadow <= 0.5*range
stand = all(close[t] >= breakout_close*0.97 for t in breakout+1..breakout+3)
retest = low[t] <= level*1.03 and close[t] >= level*0.97
fail = close[t] < level*0.97 within 3 days
```

> 参数纪律：N/buf/z/0.97 都是**自设代理**，必须在参数台账标 🟡，并用判例回归验证；不能冒充“他的话”。他的话只给了“放量/站稳 3 天/不追高/3WE/2WE/14:00-14:30/第一根一半/第二根打满/破线止损”。

### 4.6 Agent 的位置与输出契约

**agent 只做三件事**：
1. 判段位（4-3/4-4/4-5/下跌 1 浪）——数据不能唯一决定；
2. 判主线响应/避险抢戏的“语义”（数字之外的叙事）；
3. 在硬门冲突时判“看不清”，而不是硬选。

**agent 不做**：
- 不写/不读自己的锚点；状态由程序维护；
- 不打分、不给胜率、不用“量比≥1.3 就买”这类阈值结论；
- 不覆盖硬失败（F2/F5）。

**输出契约**：

```
段位：4-3 / 4-4 / 4-5 / 下跌1浪 / 看不清
突破状态：S0/S1/S2/S3/S4/F1/F2/F3/F4/F5
证据：日期 + 价位/比例（至少 3 条，带数字）
失效：收盘跌破 X / 量能跌破 Y / 主线转弱
动作：none / probe / add / reduce / exit
窗口：now / 14:00-14:30 / next-day 9:45-10:00 / wait
不确定：no_confident
```

程序校验：状态必须在允许集合；动作必须与状态一致；价格必须在当日高低区间；`F2/F5` 时动作不能是 `add`。

## 5. 数据、PIT 与工程

### 5.1 事实底稿字段

| 层 | 字段 |
|---|---|
| 市场 | `as_of`、`mode`、上证收盘/涨跌、成交额（亿元）、2WE/3WE 档、距关键位、`side`、MA5/10/60、wave_op |
| 主题 | 主题名、成员数、近 5 日量能活跃天数、5 日净流入、`mainline_act`、`hedge_act`、拥挤度、阶段 |
| 个股 | 代码、收盘、前 N 日高、突破位、突破日、量 z、收盘位置、上影、MA5/10/20/60、距突破位、stage、事件标记、板块权限 |
| 执行 | 窗口、现价、可买上限、已买笔数、底仓、T 仓、止损位、目标位 |

### 5.2 PIT 纪律

- 每个事实带 `as_of`（精确到分钟）和 `mode`（`intraday`/`postclose`/`replay`）。
- 14:30 决策只能用 14:30 前的数据；`today_low/high` 必须 cutoff。
- 盘中量能同刻对比（14:30 累计量 ÷ 前 20 日 14:30 累计量均值），不能用全天量比。
- 数据缺失 → `no_signal` + 告警；不能 `ok: true` + 过期数据。
- `stock_confirm_result.json` 加 `as_of`/`trade_date`；读取方校验时效（>1 交易日 → 拒绝）。

### 5.3 单位/口径

- 成交额：`index_daily.amount` 千元 → 亿元（÷1e5）；腾讯 `v[37]` 万元 → 千元（×10）。
- 量比：个股成交量（手）vs 20 日均量（手）；ETF 注意 100 份/手。
- 报告中每个数字带标的和单位。

### 5.4 工程

- 纯函数 `apps/main_line/breakout_confirm.py`，无 IO；输入 bars/vols/amount/ctx，输出状态。
- `stock_confirm_judge` 调它，写 `stock_confirm_result.json`（带 `as_of`/`trade_date`/`breakout` 字段）。
- `switch_builder` 只接受 `S3/S4` 新开；`S1/S2` 只进观察池。
- `p2_entry_gate` 增加硬门：`breakout_state ∈ {S3,S4}` ∧ L0/L1 通过 ∧ 非 F2/F5。
- `trend_channel` 改为调用同一函数，保留 T1/T2/T5 作为参数化分支。
- `wolf_volume_gate` 接 L0；`WOLF_VOLUME_GATE` 默认改为 1（或明确保持关，但在 breakthrough 里内联计算，不依赖过期文件）。
- 幂等：`on conflict do nothing`；唯一键 = 标的+交易日+状态。
- 开关：`WOLF_BREAKOUT_CONFIRM=0/1`、`WOLF_BREAKOUT_SHADOW=1`、`WOLF_BREAKOUT_ARM=0/1`；默认影子。
- 回滚：一个开关关掉，回到现有 `confirm_chain`/`switch_builder` 行为。

### 6.2 留出与盲测

- 留出年份：2022（不同年份）、2025 H2（趋势）、2026 Q1（主升）、2026 Q3（4-4/4-5）。
- 留出品种：个股 vs ETF；主板 vs 创业板/科创。
- 盲测：把事实底稿给新会话，不给日期/真值，只给判据，看它能否独立判出状态。
- 失败样例优先：每次规则修正必须来自一个具体失败，不是“想得更周全”。

### 6.3 指标（不要只看胜率）

| 指标 | 定义 | 用途 |
|---|---|---|
| 专家判例召回 | 他做过的突破买点中，系统允许的比例 | 防止“指标好看但误杀他” |
| 假突破率 | `S3` 后 3 日内收盘 <突破位×0.97 的比例 | 核心质量 |
| T+5/T+20 | 确认后 5/20 日收益（均值/中位/胜率） | 有效性 |
| MAE | 确认后最大不利偏移 | 风控 |
| 入场滑点 | 成交价 vs 突破位 | 执行 |
| 门挡原因分布 | 每条门挡下多少候选 | 防止某条门过严 |
| 消融 | 每条门单独关掉后的变化 | 证明门有用 |

### 6.4 影子与上线

- **影子 4 周**：`WOLF_BREAKOUT_SHADOW=1`，只记录候选/状态/假设成交，不下单。
- 对比：影子 vs 现有 `switch_builder`；按判例库、T+5/T+20、假突破率、专家召回。
- 通过后：`WOLF_BREAKOUT_ARM=1`，小仓（试仓档）；再 2 周。
- 全量：`WOLF_BREAKOUT_CONFIRM=1`，硬门接入 `p2_entry_gate`。
- 回滚：关开关，恢复现有行为；保留影子日志。
