# wolf 标的级「不做T门」方案（no-T gate）

> 背景：2026-09-07 复盘发现系统自动做T与狼大实际行为错位。
> 狼大当天(09-07)本人无做T动作：对科技"谨慎卖(诱空≤3次后买不回)"、持仓等 4000-4020 突破，
> 主攻方向/启动中的持仓拿着不动；他只在"磨人/低波/调整"标的上做T(上周在券商里低吸高抛)。
> 而系统在 wave∈t_only 时对全部持仓自动 T(588170 也于 11:11 在反弹中段 T出 16700@0.926，
> 午后放量拉至 0.941)。执行本身是狼大 7-29 规则正常命中(非bug/非他类规则)，
> 差距在"自动对所有持仓做T" vs "狼大按标的状态决定做不做T"的模式差异。

## 目标
给自动做T加**标的级过滤**：当标的正处于狼大会"拿着不动"的状态时，本次自动 T出不执行/降级，
避免把启动仓/主升仓在反弹中段 T飞；磨人/回调/低吸仓维持做T降成本。

## 不做T门判定（满足其一 → 跳过本次自动 T出，T仓保留）
> 方向锚修正(2026-09-07)：G1 不能只绑 fusion TOP1——09-07 系统 fusion 判 TOP1=消费/内需(5日平滑把
> 消费顶到0.8)，而狼大实际持有/谨慎卖的是**科技(TOP2)**；fusion 相对狼大有"滞后一档"风险，
> 故门的方向集取 **TOP1∪TOP2(candidates 前2)**，否则 588170(科技)这类狼大实际主攻方向会被漏掉。

| # | 条件 | 狼大依据 | 数据字段 |
|---|---|---|---|
| G1 进攻方向强势日 | 标的属 fusion **TOP1∪TOP2** 方向 且 当日涨幅 ≥ +2.5% | 09-07 09:39"谨慎卖科技，诱空≤3次后买不回"(588170=科技TOP2今日+3.55%→命中) | main_line_state.fusion 前2 + quote.change_pct |
| G2 量价齐升/启动 | 当日涨幅 ≥ +2.5% 且 vol ≥ 1.2×5日均量（不依赖主题归属的普适启动判据；588170 今日午后放量即属此类） | "突破站稳/放量主升前不卖" | quote.change_pct/vol + 5日均量 |
| G3 进攻链洗盘收敛期 | 标的属 **TOP1∪TOP2/TMT 等进攻链** 且 缩量收敛(近20日振幅中位<3% 且 5日量≤60日量中位×0.8 且 近5日振幅<前15日)——狼大:"主力在洗TMT降成交额波动率, 洗干净才有下一波" | 09-07 14:37 824楼 | 20/60日振幅、量能、主题归属 |
| G3b 防御低波(不拦) | 券商/银行等非进攻链低波标的 → **G3 不生效, 照常可T**(狼大上周就在券商低吸高抛) | 09-02"在券商里低吸高抛搞了5天" | 主题/行业归属 |

- 范围：只拦**存量 T仓的自动 T出(sell)**；**当日低吸所得 T仓**仍按狼大"当天低吸当天T出"节奏放行(不受门限制，G1/G2 同日低吸+冲高可T)。
- buy(低吸)/254 建仓不受门影响。

## 边界与例外
- 尾盘 14:45+：G1/G2 失效(日结减T例外) — 若当日低吸 T仓未 T 出,尾盘仍按 wolf_day_end 处理。
- wave=exit/defense(大盘转向)：不做T门失效(降仓优先, 该走就走)。
- G3(洗盘收敛期) 与"磨人标的正做T"的边界(2026-09-07 展开)：
  狼大对两类"低波动"标的态度不同——
  ① 永久低波/防御型(券商/银行/保险)：没有主升预期 → **可以做T降成本**(狼大上周在券商低吸高抛5天)；
  ② 进攻方向洗盘收敛期(如 TMT/半导体，狼大 824楼"主力洗TMT降成交额波动率, 洗干净才有下一波")：
     洗完后要主升 → **不该在缩量收敛里反复 T出交筹码/磨损**，该低吸埋伏+拿住。
  → G3 只对②启用(方向∈fusion TOP1∪TOP2/TMT等进攻链 且 明确缩量收敛)，对①(防御低波)不生效。
  G3 与 G1/G2 互补覆盖不同阶段：G3=缩量收敛期别乱T；G1/G2=放量强势日别T飞；中间"有波动做T日"照常T。

## 实现落点
- 新增 apps/main_line/no_t_gate.py：
  ```
  def no_t_sell_gate(symbol, quote, wave_op, main_top1, day_bars) -> (skip:bool, reason:str)
  ```
- 接入点：TMonitor 触发 high_sell/wolf T出写 trigger 前(_write_trigger 或自动执行段, 约 t_monitor.py _check_conditions 的 sell 分支)加门：
  命中门 → 不写自动卖 trigger(或 mode=observe, 只记录不执行)。
- 开关 env：WOLF_NO_T_GATE=1(默认1)；DRY 记录 data/no_t_gate_log.jsonl 供离线评估。

## 离线验证（先于上线）
- 样本：588170/药明/512480 等持仓 近2月(60交易日) + 各历史 T出触发点；
- 指标：门命中后"跳过卖出"的次日~5日收益分布(若跳过后续大涨→门有效避免卖飞; 若继续回落→误伤)；
- 对比：开/关门 的 T仓卖出收益与回撤差异(沿用 wave-tuned 回测思路: 卖出日收益=次日 close/卖价-1)。
- 通过标准：门避免的"卖飞损失"显著>误伤(跳过导致的少赚)，且不增加回撤。

## 风险
- G1/G2 太宽会把狼大认可的"正T者冲高位T出"也拦住(09-07 13:57 他认可做T者高位T出) →
  G1/G2 是"强势日不主动清存量T仓"，不是禁止高位T出：若触发时价格接近当日高(≥0.995×当日high)仍放行。
- G1 用 TOP1∪TOP2 是基于"系统 fusion 可能滞后一档(09-07 案例：系统判消费TOP1、狼大实际攻科技TOP2)"的折中——
  若未来 fusion 与狼大一致度提高可收紧回 TOP1，或改按"当日量价齐升(G2)"独立判（不依赖主题归属，更稳）。
- 单点加规则易顾此失彼(v7教训) → 必须先离线验证再上线，默认 G1/G2/G3 全开但 **DRY 记录**；
  离线确认无重大误伤后置 WOLF_NO_T_GATE=1。G3 参数(振幅<3%/量比0.8)先用 588170+半导体/TMT 池标定。
