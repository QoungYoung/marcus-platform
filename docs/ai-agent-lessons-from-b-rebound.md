# 让 agent 替人做判断：一次开发的错误清单与方法

> 背景：把「狼大 B反 框架」从论坛发言变成每日 14:50 的 agent 判断（读盘）+ 15:40 的 agent 标注（结构点/段位），推 QQ。
> 本文只记**可迁移的东西**：我犯的错、发现的问题、抽象出来的原则。具体业务细节见 `docs/b-rebound-case-journal.md`。
> 给其他会话看——**如果你也要做「让 agent 像专家一样判断」，先看第 2 节的反面清单**。

---

## 0. 一句话结论

**能用机械判据解决的问题，不要交给 agent；需要判断的问题，不要用机械判据糊弄。**
这条界线的位置决定成败，而它极难找——我整场都在越界，两个方向都越过。

---

## 1. 走对的路径（可以照抄的骨架）

```
事实底稿（程序算，只给事实，不给结论）
      ↓
判据（人类专家的原话/框架，转成可执行的条件）
      ↓
agent（自己下结论，允许"看不清"）
      ↓
结构化输出（固定分块 + 反证条件）
      ↓
变更检测（稳定键）→ 推送
```

每一环都有独立的失败模式，下面逐条记录。

---

## 2. 反面清单：我实际犯过的错（按危害排序）

### 2.1 用「形态」代替「位置」——最致命

同一个形态在不同位置含义**完全相反**，我一开始只按形态写判据。

- 现象：`放量 + 收最低` 我写成「派发 ⇒ 走」。但专家在**下跌末段**看到同一个形态说的是「割肉盘出清了，敢啃」。
- 后果：他全年最好的一次买入（2026-08-03，+12.6%）被我判成「不做」。
- 正解：任何形态判据前面必须加一道**位置/段位**前置，段位没定，不许选判据分支。
- 抽象：**「这个信号是什么意思」取决于「现在在哪一段」，而段位通常不能由价格形态推出。**

### 2.2 把「描述」当「筛选器」

专家总结的相位表（起点：市场缩量 0.80–0.83×、局部放量…）是对**已知两个案例**的描述。我拿它当筛选器全历史扫，得到 **86 个「起点」**（24 个月）。

- 现象：一年几十个"起点"，等于没有。
- 原因：描述是**必要条件的集合**，不是**充分的识别器**；而且它是从 n=2 归纳的。
- 正解：先用段位剪枝（把不该有该现象的区间整个排除），再在窗口内用量价找当天。**顺序错了，结论必错。**

### 2.3 自设规则，把专家的判例挡在门外

为了让统计好看，我加了一条「距 60 日高 ≤−15% 才是候选位置」。回测数字确实变好了（+25pp 超额），但**专家自己唯一明确说过的"弱B反"那天（2025-08-01，距高仅 −5%）被这条规则排除了**。

- 抽象：**任何"为了指标好看"而加的规则，都要先问「它会不会把专家认可的样本排掉」**。会排掉，就说明它测的不是专家的东西。
- 检验法：把你加的每条规则，逐条套到专家的**已知判例**上，看有没有被误杀。

### 2.4 判据写了但查不到 → 空转的判据

提示词里写着「只有被他引用过、或与更大结构位重合的点，才配叫结构点」。但 agent 手上**没有任何语料**，它查不到"引用过"。

- 后果：这条判据永远不生效，agent 实际用的是"是不是显著拐点" → 开始滥标（一天 1–2 个，一年几百个）。
- 危害等级：**比不写更糟**——写的人以为有闸，实际没有。
- 正解：判据必须可执行。要么给它数据（语料/索引），要么换成可计算的规则。
- 我最后选了后者：`与上一个同类点价差 ≥8% ∧ 之后 4 日不破 ∧ 之后 20 日反向 ≥10%`，回测把 23–29 个/年压到 1–7 个/年。

### 2.5 让 agent 自己写锚点、又自己读锚点 → 自我强化的漂移

第一版设计里，同一个 agent 每天确认结构点、又用结构点判段位。

- 风险：**它把自己上一轮的判断当成事实**，错误会被固化，而且没人能发现。
- 现实对照：项目的生产 `wave_state` 就是这个病——同一个字段 4 月是 3174、8 月是 3674，一路漂，因为程序自己写自己。
- 正解：**程序判"够不够格"，agent 判"这是什么"，人保留否决权**。并且写入时校验（我只写"程序判够格"的点，agent 的 confirm 也要过这道闸）。
- 实测抓到一个：dry-run 时 agent 想确认**当天**的新低（距今 0 日，程序判不够格），被闸挡下。

### 2.6 用未来数据做"确认"

我第一版的日级判据用了「次日有没有做上去」。回测看着合理，**实盘跑不了**——收盘前你不知道次日。

- 正解：改成「昨日 → 今日」两日状态机（只看已经发生的）。
- 抽象：**任何判据都要问「这个数据在决策时刻存在吗」**。不存在就是偷看未来，回测再好也是假的。

### 2.7 时间口径错配（这一类最容易漏）

| 错法 | 后果 |
|---|---|
| 用全天量比去比「截至 14:50 的累计量」 | 系统性低估 ~5.7%，临界日翻转判断 |
| 用 14:50 的实时快照当收盘数据 | 结论时态错（"今天可以建"，其实已收盘） |
| 盘后手动触发还用 16:14 的价算"盘中" | 量比是假的 |

- 正解：**同刻对比**（14:50 累计量 ÷ 前 20 日 14:50 累计量均值），并给底稿加 **`mode`** 字段（盘中/盘后/回放），让 agent 按 mode 决定时态。
- 我最初的辩解「拿 14:50 量比全天均值必然缩量」是**错的**——实测尾盘 10 分钟只占 5.7%（P10 4.0 / P90 7.7），偏差是浮动的、不是必然的。**先量一下，再下结论。**

### 2.8 数据源假设没验证

- 我以为分钟数据盘中可取。实测 `stk_mins` 是**收盘后才发布**（`minute_data_pending`），14:50 根本拿不到。
- 正解：盘中用实时接口（腾讯 `qt.gtimg.cn`），历史回放才用分钟；并且**三级降级 + 拿不到就不算**（宁可报错，不要拿昨日数据冒充今日 —— 我原来会输出 `ok: true` + 警告，等于让 agent 分析过期底稿）。

### 2.9 单位/口径混用

- 万元 vs 千元（沪市成交额差了 10 倍，一度算出"市场 0.11×"）
- 股 vs 手（ETF 成交量 100 倍）
- 指数收位 vs ETF 收位写在同一句里（报告出现"量 5.53 亿手、收位 87%"，一个是指数、一个是 ETF）
- 正解：底稿字段带单位注释（`note_unit`），并要求 agent 引用数字时带标的。

### 2.10 命名/键名类 bug（低级但会静默出错）

`px` vs `price` 的 KeyError；`3674.40`(seed) 与 `3674.405`(agent) 被当成两个点插进库；唯一键含价格导致同点双份。
- 正解：**唯一键用语义键**（标的+日期+高低），不用浮点价格；`on conflict do nothing` + 幂等。

### 2.11 用自然语言做变更检测

段位那串文字每次重新生成措辞都不同 → 每天都判成"改判"→ 每天推 QQ。
- 正解：让模型额外输出一个**稳定短标签**（`level_key`：4-5下跌/下跌1浪/…），只比这一列；措辞变化照常入库但不推送。

## 3. 事实底稿的五条原则（踩坑换来的）

1. **同构**：所有板块一行、字段一致，不点名、不加权重、不标"重点关注"。
   —— 我曾想给"银行"单列一栏（因为专家某天提过），但那是一次性观察被固化成常设条件，会诱导 agent 过度解读。
2. **给演变，不给切片**：B反 起点是"从死到活的过程"（地量 → 单点异动 → 市场转放量），单日切片看不见。
3. **区分"已出现/目标/待确认"**：结构点只有数值没有语义时，agent 会把它当"待破的支撑"，判断方向直接反掉。
   —— 我第一版只给 `4-3低 3764.15`，agent 判成"还在下跌段"；加上"已出现 ⇒ A 段结束，其后是 4-4 反弹"后，同一个 agent 判对了。
4. **能算的都给，但别给结论**：回撤位（38.2/50/61.8）一给，目标位立刻从"最近的摆动点"变成"1.146"（和他说的 1.15 对上）。**缺数据时 agent 不会说缺，它会用次优数据填。**
5. **口径守卫**：数据不能代表当下时，明说（`data_warning` + `mode`），并禁止 agent 用"今天"的语气。

## 4. 怎么验证"agent 判得对不对"（别问胜率）

### 4.1 盲测：不给真值、不给日期身份

把事实底稿喂给一个**全新会话**（看不到你的推理），只给材料 + 判据，不给"这是不是 B反"。

### 4.2 必须包含留出日

规则是看着失败案例改的，所以那些案例已经"拟合"了。要用**设计时没看过的日期**做留出检验。
我用了 2026-06-30（主升末段，之后 −44%）——它靠浪型直接判对，没用到我新加的启发式规则，这才说明规则不是纯拟合。

### 4.3 换品种、换年份

只在单一品种上验证，等于没验证。我用 2022-04-27（新能车 ETF，不同年份、不同板块）——
**这一次暴露了账本的一个空档**：起点那栏写的「市场缩量 0.80–0.83×、收位 1%」，只覆盖"缓跌磨底型"，遇到 V 型反转（收位 98%、市场 1.05×）就判成"中段"。

### 4.4 失败样例 > 成功样例

- 判对的：3/30、8/18（顶）、6/30（末段）、7/22（反弹受阻）
- 判错的：7/08 被误判成起点 → 逼出「起点窗口」这条判据
- 判"看不清"的：2022-04-27 → 逼出「两段式（级别待定 + 两套预案）」

**每一次修正都来自一个具体失败，而不是来自更好的指标。**

### 4.5 最后看它能不能自己发现矛盾

最好的一次输出不是结论，而是它主动报告：

> 「存在一处冲突：anchors_etf 把 08-18 标为 B反高点，此后递减，按这个口径已经属于 B 之后…」

**agent 报告数据矛盾，比它给出正确答案更有价值**——说明它在真读数据，不是套模板。

## 5. 输出契约（模板，可直接抄）

```
**段位** B 之前 / 之中 / 之后（级别）
- 已完成：点 → 点 → 点
- 今日：收 X，距关键位 Y 点，站上没有 ⇒ 一句话

**判据** 同一形态在本段读成什么 + 关键数字
**相位** 起点候选 / 中段 / 顶 / 结束 / 没有相位
**起点** 是/否 ｜ 能不能建、建多少（≤1/3）；盘后就写"明日若 X → Y"
**级别** 待定 · 升级条件 ｜ 降级条件

**四行**
- 级别 / 长度 / 目标 / 失效

**预案**
1..3  条件句
4. 都不出现 → 不做

**反证** 什么情况说明这次读错了
```

要点：
- **禁止**打分、胜率、阈值触发式结论（"量比 ≥1.3 就买"）
- **允许**"看不清"、"现在不该做" —— 而且这常常是正确的产出
- 每条判断带**可核对数字**（日期 + 价位/比例）
- 反证条件必须**可观测**（"收盘跌破 X"，不是"感觉不对"）

## 6. 两段式：级别当天下不了结论

专家原话：「B反 是大级别的，持续至少 2 个月交易日以上」「先看底部结构能不能完成，然后看结构的力度决定下一阶段是什么级别」。

⇒ 级别是**事后函数**，起点当天判不出来。所以输出必须两段：

```
起点当天：起点候选 + 级别待定 + 两条触发
  升级（→ 大级别）：结构突破 + 市场额连续 ≥1.03×
  降级（→ 只做反抽）：市场额始终 <1.0×，或承接次日就散
结构走完：再给级别 + 切换 playbook
```

**两套 playbook 不能混**：小级别（1–2 周，目标 38.2–50% 回撤就走，卖点前置） vs 大级别（≥2 个月，分批走，顶看缩量新高／放量收最低）。
用错一栏：当大级别做 → 套在 C 杀里；当小级别做 → 少赚 44 个点。

## 7. 工程侧清单

- **append-only + as-of 时间戳**：结构点和段位都要 `confirmed_at`，回测用 `where confirmed_at <= 回测日`，否则偷看未来。
- **幂等**：`on conflict do nothing`；唯一键用语义键。
- **dry-run 默认**：写库的脚本 `--apply` 才写。
- **dry-run 也要跑真实链路**：我 3 次 dry-run 各抓到一个 bug（KeyError、重复点、agent 越权确认当天低点）。
- **部署**：`git pull` → `docker restart marcus-worker`（调度器和提示词都是启动时加载的）。
- **失败要响**：数据没取到 → 非零退出（推 ❌），不要输出"看起来正常"的过期报告。
- **无变化要静默**：变更检测用稳定键，否则每天推一样的东西，人就把它屏蔽了。

## 8. 什么情况下这套会失效（提前说清）

1. **专家判例和可计算量冲突**：他说的点位/阶段依赖他看到的盘口（谁在买、GJD 托不托），这些我们拿不到 → 只能近似。
2. **语料会过期**：他只会说当下和过去，未来的新结构他没说过 → 判据不能依赖"他引用过"。
3. **样本极少**：四个相位表来自 2 个完整案例；"级别 ≥2 个月"来自一句话。**所有区间都是描述，不是统计结论。**
4. **数据源单点**：实时行情靠腾讯一个接口，挂了就当天无读数（已改成非零退出而不是硬凑）。
5. **agent 会自证**：只要它同时写数据和读数据，就迟早会自我强化。必须有人/程序的一致性闸。

## 9. 我给下一个会话的三条建议

1. **先写"事实底稿"，再写"判据"，最后才写提示词。** 顺序反了，你会在提示词里堆一堆无法执行的空话。
2. **每加一条规则，先拿专家的已知判例过一遍**，看有没有误杀。误杀就是最强的信号：你测的不是他的东西。
3. **把"判错"当成主产物。** 我一个下午改了 10 轮，每一轮都是被一个具体错误逼出来的（8/3 误判→位置前置；7/8 误判→起点窗口；2022-04-27 看不清→两段式；盘后时态错→mode）。**没有一个修正是来自"想得更周全"。**
