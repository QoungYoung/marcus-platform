# 让 agent 替人做判断：一次开发的错误清单与方法

> 背景：把「狼大 B反 框架」从论坛发言变成每日 14:50 的 agent 判断（读盘）+ 15:40 的 agent 标注（结构点/段位），推 QQ。
> 本文只记**可迁移的东西**：我犯的错、发现的问题、抽象出来的原则。具体业务细节见 `docs/b-rebound-case-journal.md`。
> 给其他会话看——**如果你也要做「让 agent 像专家一样判断」，先看第 2 节的反面清单**。

---

## 0. 一句话结论

**能用机械判据解决的问题，不要交给 agent；需要判断的问题，不要用机械判据糊弄。**
这条界线的位置决定成败，而它极难找——我整场都在越界，两个方向都越过。

---

## 1. 走对的路径（可以照抄的骨架）

```
事实底稿（程序算，只给事实，不给结论）
      ↓
判据（人类专家的原话/框架，转成可执行的条件）
      ↓
agent（自己下结论，允许"看不清"）
      ↓
结构化输出（固定分块 + 反证条件）
      ↓
变更检测（稳定键）→ 推送
```

每一环都有独立的失败模式，下面逐条记录。

---

## 2. 反面清单：我实际犯过的错（按危害排序）

### 2.1 用「形态」代替「位置」——最致命

同一个形态在不同位置含义**完全相反**，我一开始只按形态写判据。

- 现象：`放量 + 收最低` 我写成「派发 ⇒ 走」。但专家在**下跌末段**看到同一个形态说的是「割肉盘出清了，敢啃」。
- 后果：他全年最好的一次买入（2026-08-03，+12.6%）被我判成「不做」。
- 正解：任何形态判据前面必须加一道**位置/段位**前置，段位没定，不许选判据分支。
- 抽象：**「这个信号是什么意思」取决于「现在在哪一段」，而段位通常不能由价格形态推出。**

### 2.2 把「描述」当「筛选器」

专家总结的相位表（起点：市场缩量 0.80–0.83×、局部放量…）是对**已知两个案例**的描述。我拿它当筛选器全历史扫，得到 **86 个「起点」**（24 个月）。

- 现象：一年几十个"起点"，等于没有。
- 原因：描述是**必要条件的集合**，不是**充分的识别器**；而且它是从 n=2 归纳的。
- 正解：先用段位剪枝（把不该有该现象的区间整个排除），再在窗口内用量价找当天。**顺序错了，结论必错。**

### 2.3 自设规则，把专家的判例挡在门外

为了让统计好看，我加了一条「距 60 日高 ≤−15% 才是候选位置」。回测数字确实变好了（+25pp 超额），但**专家自己唯一明确说过的"弱B反"那天（2025-08-01，距高仅 −5%）被这条规则排除了**。

- 抽象：**任何"为了指标好看"而加的规则，都要先问「它会不会把专家认可的样本排掉」**。会排掉，就说明它测的不是专家的东西。
- 检验法：把你加的每条规则，逐条套到专家的**已知判例**上，看有没有被误杀。

### 2.4 判据写了但查不到 → 空转的判据

提示词里写着「只有被他引用过、或与更大结构位重合的点，才配叫结构点」。但 agent 手上**没有任何语料**，它查不到"引用过"。

- 后果：这条判据永远不生效，agent 实际用的是"是不是显著拐点" → 开始滥标（一天 1–2 个，一年几百个）。
- 危害等级：**比不写更糟**——写的人以为有闸，实际没有。
- 正解：判据必须可执行。要么给它数据（语料/索引），要么换成可计算的规则。
- 我最后选了后者：`与上一个同类点价差 ≥8% ∧ 之后 4 日不破 ∧ 之后 20 日反向 ≥10%`，回测把 23–29 个/年压到 1–7 个/年。

### 2.5 让 agent 自己写锚点、又自己读锚点 → 自我强化的漂移

第一版设计里，同一个 agent 每天确认结构点、又用结构点判段位。

- 风险：**它把自己上一轮的判断当成事实**，错误会被固化，而且没人能发现。
- 现实对照：项目的生产 `wave_state` 就是这个病——同一个字段 4 月是 3174、8 月是 3674，一路漂，因为程序自己写自己。
- 正解：**程序判"够不够格"，agent 判"这是什么"，人保留否决权**。并且写入时校验（我只写"程序判够格"的点，agent 的 confirm 也要过这道闸）。
- 实测抓到一个：dry-run 时 agent 想确认**当天**的新低（距今 0 日，程序判不够格），被闸挡下。

### 2.6 用未来数据做"确认"

我第一版的日级判据用了「次日有没有做上去」。回测看着合理，**实盘跑不了**——收盘前你不知道次日。

- 正解：改成「昨日 → 今日」两日状态机（只看已经发生的）。
- 抽象：**任何判据都要问「这个数据在决策时刻存在吗」**。不存在就是偷看未来，回测再好也是假的。

### 2.7 时间口径错配（这一类最容易漏）

| 错法 | 后果 |
|---|---|
| 用全天量比去比「截至 14:50 的累计量」 | 系统性低估 ~5.7%，临界日翻转判断 |
| 用 14:50 的实时快照当收盘数据 | 结论时态错（"今天可以建"，其实已收盘） |
| 盘后手动触发还用 16:14 的价算"盘中" | 量比是假的 |

- 正解：**同刻对比**（14:50 累计量 ÷ 前 20 日 14:50 累计量均值），并给底稿加 **`mode`** 字段（盘中/盘后/回放），让 agent 按 mode 决定时态。
- 我最初的辩解「拿 14:50 量比全天均值必然缩量」是**错的**——实测尾盘 10 分钟只占 5.7%（P10 4.0 / P90 7.7），偏差是浮动的、不是必然的。**先量一下，再下结论。**

### 2.8 数据源假设没验证

- 我以为分钟数据盘中可取。实测 `stk_mins` 是**收盘后才发布**（`minute_data_pending`），14:50 根本拿不到。
- 正解：盘中用实时接口（腾讯 `qt.gtimg.cn`），历史回放才用分钟；并且**三级降级 + 拿不到就不算**（宁可报错，不要拿昨日数据冒充今日 —— 我原来会输出 `ok: true` + 警告，等于让 agent 分析过期底稿）。

### 2.9 单位/口径混用

- 万元 vs 千元（沪市成交额差了 10 倍，一度算出"市场 0.11×"）
- 股 vs 手（ETF 成交量 100 倍）
- 指数收位 vs ETF 收位写在同一句里（报告出现"量 5.53 亿手、收位 87%"，一个是指数、一个是 ETF）
- 正解：底稿字段带单位注释（`note_unit`），并要求 agent 引用数字时带标的。

### 2.10 命名/键名类 bug（低级但会静默出错）

`px` vs `price` 的 KeyError；`3674.40`(seed) 与 `3674.405`(agent) 被当成两个点插进库；唯一键含价格导致同点双份。
- 正解：**唯一键用语义键**（标的+日期+高低），不用浮点价格；`on conflict do nothing` + 幂等。

### 2.11 用自然语言做变更检测

段位那串文字每次重新生成措辞都不同 → 每天都判成"改判"→ 每天推 QQ。
- 正解：让模型额外输出一个**稳定短标签**（`level_key`：4-5下跌/下跌1浪/…），只比这一列；措辞变化照常入库但不推送。

## 3. 事实底稿的五条原则（踩坑换来的）

1. **同构**：所有板块一行、字段一致，不点名、不加权重、不标"重点关注"。
   —— 我曾想给"银行"单列一栏（因为专家某天提过），但那是一次性观察被固化成常设条件，会诱导 agent 过度解读。
2. **给演变，不给切片**：B反 起点是"从死到活的过程"（地量 → 单点异动 → 市场转放量），单日切片看不见。
3. **区分"已出现/目标/待确认"**：结构点只有数值没有语义时，agent 会把它当"待破的支撑"，判断方向直接反掉。
   —— 我第一版只给 `4-3低 3764.15`，agent 判成"还在下跌段"；加上"已出现 ⇒ A 段结束，其后是 4-4 反弹"后，同一个 agent 判对了。
4. **能算的都给，但别给结论**：回撤位（38.2/50/61.8）一给，目标位立刻从"最近的摆动点"变成"1.146"（和他说的 1.15 对上）。**缺数据时 agent 不会说缺，它会用次优数据填。**
5. **口径守卫**：数据不能代表当下时，明说（`data_warning` + `mode`），并禁止 agent 用"今天"的语气。

## 4. 怎么验证"agent 判得对不对"（别问胜率）

### 4.1 盲测：不给真值、不给日期身份

把事实底稿喂给一个**全新会话**（看不到你的推理），只给材料 + 判据，不给"这是不是 B反"。

### 4.2 必须包含留出日

规则是看着失败案例改的，所以那些案例已经"拟合"了。要用**设计时没看过的日期**做留出检验。
我用了 2026-06-30（主升末段，之后 −44%）——它靠浪型直接判对，没用到我新加的启发式规则，这才说明规则不是纯拟合。

### 4.3 换品种、换年份

只在单一品种上验证，等于没验证。我用 2022-04-27（新能车 ETF，不同年份、不同板块）——
**这一次暴露了账本的一个空档**：起点那栏写的「市场缩量 0.80–0.83×、收位 1%」，只覆盖"缓跌磨底型"，遇到 V 型反转（收位 98%、市场 1.05×）就判成"中段"。

### 4.4 失败样例 > 成功样例

- 判对的：3/30、8/18（顶）、6/30（末段）、7/22（反弹受阻）
- 判错的：7/08 被误判成起点 → 逼出「起点窗口」这条判据
- 判"看不清"的：2022-04-27 → 逼出「两段式（级别待定 + 两套预案）」

**每一次修正都来自一个具体失败，而不是来自更好的指标。**

### 4.5 最后看它能不能自己发现矛盾

最好的一次输出不是结论，而是它主动报告：

> 「存在一处冲突：anchors_etf 把 08-18 标为 B反高点，此后递减，按这个口径已经属于 B 之后…」

**agent 报告数据矛盾，比它给出正确答案更有价值**——说明它在真读数据，不是套模板。

## 5. 输出契约（模板，可直接抄）

```
**段位** B 之前 / 之中 / 之后（级别）
- 已完成：点 → 点 → 点
- 今日：收 X，距关键位 Y 点，站上没有 ⇒ 一句话

**判据** 同一形态在本段读成什么 + 关键数字
**相位** 起点候选 / 中段 / 顶 / 结束 / 没有相位
**起点** 是/否 ｜ 能不能建、建多少（≤1/3）；盘后就写"明日若 X → Y"
**级别** 待定 · 升级条件 ｜ 降级条件

**四行**
- 级别 / 长度 / 目标 / 失效

**预案**
1..3  条件句
4. 都不出现 → 不做

**反证** 什么情况说明这次读错了
```

要点：
- **禁止**打分、胜率、阈值触发式结论（"量比 ≥1.3 就买"）
- **允许**"看不清"、"现在不该做" —— 而且这常常是正确的产出
- 每条判断带**可核对数字**（日期 + 价位/比例）
- 反证条件必须**可观测**（"收盘跌破 X"，不是"感觉不对"）

---

## 6. 两段式：级别当天下不了结论

专家原话：「B反 是大级别的，持续至少 2 个月交易日以上」「先看底部结构能不能完成，然后看结构的力度决定下一阶段是什么级别」。

⇒ 级别是**事后函数**，起点当天判不出来。所以输出必须两段：

```
起点当天：起点候选 + 级别待定 + 两条触发
  升级（→ 大级别）：结构突破 + 市场额连续 ≥1.03×
  降级（→ 只做反抽）：市场额始终 <1.0×，或承接次日就散
结构走完：再给级别 + 切换 playbook
```

**两套 playbook 不能混**：小级别（1–2 周，目标 38.2–50% 回撤就走，卖点前置） vs 大级别（≥2 个月，分批走，顶看缩量新高／放量收最低）。
用错一栏：当大级别做 → 套在 C 杀里；当小级别做 → 少赚 44 个点。

## 7. 工程侧清单

- **append-only + as-of 时间戳**：结构点和段位都要 `confirmed_at`，回测用 `where confirmed_at <= 回测日`，否则偷看未来。
- **幂等**：`on conflict do nothing`；唯一键用语义键。
- **dry-run 默认**：写库的脚本 `--apply` 才写。
- **dry-run 也要跑真实链路**：我 3 次 dry-run 各抓到一个 bug（KeyError、重复点、agent 越权确认当天低点）。
- **部署**：`git pull` → `docker restart marcus-worker`（调度器和提示词都是启动时加载的）。
- **失败要响**：数据没取到 → 非零退出（推 ❌），不要输出"看起来正常"的过期报告。
- **无变化要静默**：变更检测用稳定键，否则每天推一样的东西，人就把它屏蔽了。

## 8. 什么情况下这套会失效（提前说清）

1. **专家判例和可计算量冲突**：他说的点位/阶段依赖他看到的盘口（谁在买、GJD 托不托），这些我们拿不到 → 只能近似。
2. **语料会过期**：他只会说当下和过去，未来的新结构他没说过 → 判据不能依赖"他引用过"。
3. **样本极少**：四个相位表来自 2 个完整案例；"级别 ≥2 个月"来自一句话。**所有区间都是描述，不是统计结论。**
4. **数据源单点**：实时行情靠腾讯一个接口，挂了就当天无读数（已改成非零退出而不是硬凑）。
5. **agent 会自证**：只要它同时写数据和读数据，就迟早会自我强化。必须有人/程序的一致性闸。

## 9. 我给下一个会话的三条建议

1. **先写"事实底稿"，再写"判据"，最后才写提示词。** 顺序反了，你会在提示词里堆一堆无法执行的空话。
2. **每加一条规则，先拿专家的已知判例过一遍**，看有没有误杀。误杀就是最强的信号：你测的不是他的东西。
3. **把"判错"当成主产物。** 我一个下午改了 10 轮，每一轮都是被一个具体错误逼出来的（8/3 误判→位置前置；7/8 误判→起点窗口；2022-04-27 看不清→两段式；盘后时态错→mode）。**没有一个修正是来自"想得更周全"。**

## 10. 怎么读专家发言（语料方法）

> 这一节单独写，因为**读错语料是比写错代码更隐蔽的错误**——代码错了会报错，语料读错了会得到一份"看起来很有依据"的错误结论。

### 10.1 先搞清楚语料的形状和盲区

本次实际分布：

| 来源 | 覆盖 | 规模 | 盲区 |
|---|---|---|---|
| `狼大回复汇总 xlsx`（2025 / 2026 两个 sheet） | 至 **2026-08-14** | 9,534 条，其中含点位/ETF价 **717 条** | 8/14 之后的发言全没有 |
| NGA 帖子（tid=47288722，只看楼主） | 8/14 之后 | 约 1,400 层 | 楼层号会变、混大量闲聊 |

**第一课：先确认覆盖边界再检索。** 我曾在 xlsx 里 grep `2026-08-03` 得到 0 条，误以为"那天他没说话"——实际是那份导出只到 8/14 之后的往期，8/3 的内容只在 NGA。

### 10.2 楼层号不可靠，靠日期定位

帖子的"只看楼主"层号会随新帖增加而后移。我早期记的 `1251/1267/1281 = 8/3`，几小时后同一层号已经变成 10/19 的发言。

**做法**：
1. 先读几个已知层号校准（例如读 320 层得 8/17、读 460 层得 8/24）
2. 按日期间隔推算目标区间，再小范围精读
3. **永远用日期锚定，不用层号复述**

### 10.3 必须剥掉 `[quote]…[/quote]`

引用块里是**别人的话**。不剥掉会把自己的提问当成他的观点。

本次实例：有一层写着「等右侧第一根黑 k」——那是一位用户的说法，他在回复里并没有采用。如果当成他的判据，整条 B反 入场逻辑都会跑偏。

**做法**：正则 `\[quote\].*?\[/quote\]` 全部剔除后再检索。剔除后仍要判断：这条是**他的陈述**，还是**他在回答别人的问题**（见 10.6）。

### 10.4 他会重复讲同一件事，取最新/最完整的一版

同一个判断常在不同日期反复出现（"延伸浪的终结一定是一个明确的结构"至少三次）。
**做法**：按日期排序，取**最后一次**的表述作为当前口径；早期版本只用于看演化（例如 4/20 的「有量不是高点，缩量容易出高点」到 10/23 才变成明确的级别门槛）。

### 10.5 他的口径和我们的数据口径不同，对性质不对数字

- 他说「市场缩量 5500E」，我们的沪市成交额是 **9,523 亿**，差 **1.73 倍**。
- 这不代表谁错——他的"5500E"是另一种口径/估算。
- **可以对齐的是性质**（缩量/放量/地量），不能对齐的是绝对数字。

**做法**：引用他的数字时注明口径不明；判断只用"缩量/放量"这类相对描述，并用我们的数据算比值。

### 10.6 短回复脱离上下文会误读

他的很多楼层是对提问的一句话回应。单独看会被当成判断，实际是**在回答特定问题**。

实例：
- 「这里没出底部结构」——单看是一句判断；实际是回答"要不要开始数 3"（数 3 是底部确认之后的事）。
- 「不，还是延伸浪」——单看是浪型定性；实际是回答"现在是 b 反了吗"。

**做法**：读楼层时**连同被回复的那句话一起读**。我最终找到 8/3 的关键原文，是靠**连续读 18–65 楼**（把提问和回答放在一起），而不是关键词检索。

### 10.7 看似矛盾的两句话，先找段位差异

- 8/3：「全场只有半导体尾盘放量，这不是纯割肉是什么。**我这都不敢啃，那还玩什么**」→ 割肉盘出来＝可以试
- 10/22：「**没有人承接的恐慌盘不值得抄**」→ 同样是割肉，不做

**一句话结论**：不是他改口，是**段位不同**（8/3 在 4-3 筑底、下方有 3800 支撑；10/22 在下跌 1 浪延伸、3674 已破）。

**做法**：遇到矛盾先查两天的段位/结构点，再决定是"改了"还是"位置不同"。**新手最容易在这里判他"前后不一致"。**

### 10.8 抓"改判的触发句"，不要抓结论

他明确说过改判是有条件的：

> 「收盘后如果没有收回跳空跌幅，整波浪型从主升 4 浪调整转为主跌 1 浪」

**这句话比"现在是主跌 1 浪"有用得多**——前者是可以每天检验的条件，后者是某一时刻的结论。

**做法**：整理语料时，专门抽一类"如果 X 就 Y"的句子，它们是系统的规则来源。

### 10.9 让他的点位校验我们的结构标注

他给的点位往往精确命中结构点：

| 他的话 | 结构点 | 误差 |
|---|---|---|
| 「下跌 1 浪的最低点，当时也就判断到 **3674**」 | 1 浪顶 3674.40 | **0 点** |
| 「收盘正式破了 **3764**，是不是就确认要开始走下跌 1 浪」 | 4-3 低 3764.15 | **0.15 点** |

**做法**：把"他引用的点位"当成**标注质量的外部校验**。如果我们的算法标出的结构点和他念的差很远，先怀疑算法，不要怀疑他。

### 10.10 术语要统计，不要臆造

全语料里只有四种说法：`B反 38 次 / ABC的B 7 次 / 二段 4 次 / B段 3 次`。**没有"B反中期""B反尾声"**。

我早期自造了"B反中期/尾声"这类词做阶段划分，等于在给一个不存在的概念建模型。

**做法**：写判据前先统计他的用词频次，用他的词，不用更"专业"的同义词。

### 10.11 情绪和闲聊占比很高，别指望关键词检索

楼里大量内容在聊电视剧、八卦、骂人。关键词检索会同时漏掉关键句（用词和你猜的不一样）和误命中（骂人时也提"半导体"）。

**做法**：
- **定位阶段**用关键词（快，找大致范围）
- **取证据阶段必须连续读**（慢，但能拿到上下文和语气）
- 摘录时**带日期 + 原文**，不要转述。转述会失真：我早期把「缩量 2200E 了，没有钱途的」写成"缩量没前途"，漏掉了"2200E"这个他当时的口径线索。

### 10.12 读语料的产出应该是什么

不是"他说过什么"，而是三类结构化东西：

```
① 判据（可执行的条件句）      例：收盘收回不收回跳空 → 级别改判
② 词汇表（他真实用的词）      例：起点/中段/顶/结束，无"中期/尾声"
③ 判例（日期 + 他的动作 + 当时的数据）  例：8/3 10:19 买 0.839，市场 0.80×、ETF 收位 1%
```

**判例是最值钱的**——它是唯一能用来检验我们自己判据的东西。本次所有规则修正，都是拿判例打出来的（见 §4.4）。

## 11. 从“自设因子回测”转向“agent 开发”：本次会话的复盘

> 这一节只写这次会话真正发生的事：我怎样从“写因子 + 回测 + 调参”转到“先定事实/窗口、再让 agent 判断、最后接执行”。
> 结论先放前面：**自设因子在样本内可以做到 4/4，但换两个留出案例就 0/2；不是因子不够好，是问题类型选错了。**

### 11.1 我一开始做的三件错事

#### 错事一：把“他的点位”当成“我要拟合的目标”

我最初的做法是：

1. 从账本里取他的点位（3922、3888、3370、3856…）；
2. 在候选里手工挑几个“像”的；
3. 写 `structure_rank`（颈线/前低=3、均线/整数=2、缺口=1）；
4. 加“排除 rank=1”“rank > confluence > distance”；
5. 回测 A-F，得到 4/4。

看起来很好。**但这是 in-sample 拟合**：规则是看着 A-F 的失败案例改的，4/4 只说明“规则能记住这 4 个答案”。

#### 错事二：把“描述”当成“筛选器”

我把他的“合流、前低、缺口、颈线、整数”写成了硬排序。
问题是：**这些是描述，不是优先级**。

- B/C 的 3922 和 3835 都是 broken；
- E 的 3856.25 和 3844.13 都是 broken；
- I 的 3761 和 3750 都是 broken；
- 数据里都合理，只有**他的叙事**能决定哪条是第一档。

我加一条“优先更高的已破结构”，B/C 修好了，G/H 又坏了；再加“优先当前段起点”，G/H 好了，I/J 又坏了。
**每加一条规则，都在另一批案例上过拟合。**

#### 错事三：用“全天 bar”做盘中决策

I 案例里 agent 选了 3732.84。
我一开始以为它“判断错了”，后来查 5min：

- 他的动作时点是 **14:30**；
- 3732.84 出现在 **14:35**；
- 14:30 时只能知道 3733.34。

**这不是 agent 错，是我把收盘后的低点喂给了它。**
同理，E 的 3856.25 是 8/27 13:55 的 5min 反抽高点，不是 MA5 3844.13；H 的 4141 是前一日 15min 首低，不是日线 4126.23。
**数据粒度错了，agent 再聪明也只能选错层级的线。**

### 11.2 转折点：从“调因子”改成“定问题”

真正的转折不是想到一个更好的因子，而是承认：

> **“他的第一档是哪条”不是价格数据能唯一决定的问题。**

于是开发顺序反过来：

```
先定：这次是什么动作模式（结构破位/盘中确认/反抽卖出/收盘阈值）
再定：这个动作在哪个窗口（14:30 / 14:55 / 15:00 / 3×15）
再定：PIT 数据到哪一秒（不能用收盘后 bar）
再定：agent 只判断“状态/模式/候选”，不判断“他的第一档”
最后：执行层用窗口、幂等、上限、兜底
```

### 11.3 正确的 agent 开发顺序（这次真正跑通的）

1. **事实底稿**：候选、state（broken/holding/resistance）、价格、confluence、5m/15m、窗口、PIT cutoff。
2. **判据**：什么算跌破、什么算确认、什么算反抽、什么算拉回。
3. **agent 输出契约**：
   - `action_mode`；
   - `break_trigger`（可以已破、可以在现价上方）；
   - `next_support`（下方未破）；
   - `rebound_zone`（反抽卖出带）；
   - `window_check`；
   - `no_confident_level`。
4. **程序校验**：候选 id 必须存在、价格必须匹配、`risk_trigger` 必须是 `break_trigger`、`next_support` 必须在现价下方。
5. **执行层**：窗口门控、13:00-14:30 禁区、PG 幂等、单日/单票上限、反抽 watcher、持续下跌尾盘兜底。
6. **留出验证**：G/H、I/J 不参与规则修改；如果 0/2，就承认规则过拟合，不继续加规则。

### 11.4 本次最值钱的 12 条

1. **样本内 4/4 不是成功，是过拟合的典型信号。**
   必须用没参与规则设计的案例做留出；G/H 0/2、I/J 0/2 就是判决。

2. **“他的点位”不能当训练目标直接拟合。**
   拟合出来的是“这 4 个案例的答案”，不是“他的方法”。

3. **描述 ≠ 筛选器。**
   “前低+缺口+颈线”是描述；把它变成 `rank=3` 硬排序，就会在另一批案例上错。

4. **agent 知道 broken，不等于知道第一档。**
   它会选“最近 broken”；他的第一档可能是“更高/更早/当前段起点”。这是优先级问题，不是状态识别问题。

5. **不要把 next_support 当 break_trigger。**
   已破位就在现价上方，不能说“它已破就不能当触发线”；触发线可以已破。

6. **PIT 不是“日期对”就行，要“秒对”。**
   14:30 的决策不能用 14:35 的低点；盘中不能用全天 bar；`today_low` 只能到 cutoff。

7. **数据粒度决定选点层级。**
   E 的 3856.25 是 5min 反抽高点，MA5 3844.13 是日线；H 的 4141 是 15min 首低，日线 4126.23 是另一层。**候选里没有这一层，agent 只能退到下一层。**

8. **窗口是策略的一部分。**
   14:50 只预览、14:55 尾盘代理可当天走、15:00 官方收盘只能次日；13:00-14:30 不执行；3×15 要 45 分钟；2:30 是定点。

9. **Case 库按日期查表在生产没用。**
   生产是未来推测，不可能匹配；Case 只能当评估标签/排序特征，不能当实时点位源。**存“他为什么选 3922”，不能存“以后都选 3922”。**

10. **“更强/更近”不是他的优先级。**
    B/C 的 3835 更近，但他的第一档是 3922；E 的 3844 更近，但他的门槛是 3856.25；I 的 3750 更近，但他的触发是 3761。**数据上的“最近”经常是错的。**

11. **反抽和拉回要用状态机，不是看价格。**
    确认前收回 = 假破/拉回；确认后进 zone = 反抽卖；确认后站回 invalidation = 修复；持续下跌 = 尾盘兜底。**顺序不同，动作相反。**

12. **生产不是“每 30 秒问 agent”。**
    轮询负责检测，窗口负责决定何时问 agent，缓存负责 14:50 预计算，PG 负责幂等，gateway 负责执行。agent 只在事件/窗口被调用。

### 11.5 我这次真正改掉的开发习惯

| 旧习惯 | 新习惯 |
|---|---|
| 先写因子，再看回测曲线 | 先定问题类型/窗口/PIT，再决定用规则还是 agent |
| 用已知案例调规则，调到全对 | 留出案例不参与调参；0/2 就停手 |
| 把专家点位写进候选短名单 | 给全量候选，不手工过滤 |
| 让 agent 决定“第一档是谁” | agent 只给候选/状态/角色；第一档由 case 库/人/分档执行处理 |
| 用“更强/更近”排序 | 用“动作模式 + 窗口 + 确认状态”排序 |
| 破了就卖 | 先分类：结构破位/盘中确认/反抽卖出/收盘阈值 |
| 盘中破位立刻走 | 13:00-14:30 不执行；3×15 等 45min；反抽等 zone；持续下跌尾盘兜底 |
| 回测只看收益 | 先看 PIT、窗口、数据粒度、是否误杀专家判例 |

### 11.6 给下一个会话的最短建议

如果你也要“让 agent 像专家一样选点/卖出”：

1. **先问：这是不是数据能唯一决定的问题？**
   不是，就别让 agent 硬选第一档；让它输出候选/状态/不确定性。
2. **先定窗口和 PIT，再写 prompt。**
   14:30 的数据不能含 14:35 的低点；14:55 不是 15:00 收盘。
3. **先留出，再宣布成功。**
   样本内 4/4 没有意义；G/H 0/2 才是有效信息。
4. **把“已破位/拉回/反抽/持续下跌”写成状态机。**
   不要用一句“破了就卖”糊过去。
5. **生产接执行前，先补幂等、上限、兜底、告警。**
   agent 可以错，执行层不能重复卖、不能卖超、不能漏掉持续下跌。

一句话：**这次不是“找到了更好的因子”，而是承认“第一档不是数据唯一决定的”，然后把 agent 放回它该在的位置——判断状态和候选，不替代专家的叙事优先级。**
