## 0. 先立五条规矩（来自 lessons，违反必错）

1. **位置/段位前置**：同一个“放量收最低”，在下跌末段是割肉盘出清（买），在高位是派发（卖）。段位没定，不许选防御分支。
2. **程序判“够不够格”，agent 判“这是什么”**：硬触发、仓位上限、可卖数量由程序算；agent 只判断“4-3 / 4-4 / 4-5 / 下跌 1 浪 / 看不清”和“洗盘还是破位”。
3. **两段式**：级别当天可能判不出 → 输出“候选档位 + 升级条件 + 降级条件 + 反证”，允许“看不清”。禁止为了给结论而硬判。
4. **PIT 与窗口**：14:40 的决策不能用 14:55 的低点；两融是 T-1 数据，只能做确认，不能当“今天盘中”触发；13:00-14:30 不执行止损。
5. **失败要响**：数据没取到 → 明确 `data_status=missing`，不默认 G0，不输出“看起来正常”的过期结论。

## 2. 狼大关于防御/空仓的原始规则

### 2.1 四档仓位（总纲）

> **2026-01-17**：「主升趋势就 75% 以上，然后盘中满仓滚动啊；调整就 50%，有风险就 30%，下跌趋势就不做。」

| 行情状态 | 总仓位 | 对应本系统 |
|---|---|---|
| 主升 | ≥75%，盘中可满仓滚动 | build |
| 调整 | 50% | side / t_only |
| 有风险 | 30% | defense |
| 下跌趋势 | 不做（0-20% 底仓/ETF） | exit / cash |

这是防御体系的**唯一总仓位口径**。其他所有规则（p2 gate、position_tier、weekend）都应服从它，不能各写一套。

### 2.2 什么情况“不做”

| 日期 | 原话 | 规则 |
|---|---|---|
| 2026-03-20 | 「**最好的防守就是不做熊市和下跌浪**」 | 下跌浪/熊市 → 不参与，不是“轻仓参与” |
| 2022-04-15 | 「这段我从来不敢做……充斥着太多临时割肉盘、止损盘，你想做一个票，本来好好的可能瞬间被一个出货打懵逼，没有征兆的」 | 4 浪末尾/主跌段 → 不做题材、不做主线、不做趋势 |
| 2022-04-21 | 「**4 的末尾我不做的**……因为有可能触发量化卖盘」 | 段位在 4 末尾 → 不做，等 5 出结构 |
| 2022-04-25 | 「**有 4 必有 5**……一旦确认是 4，技术上就要先卖，因为一定有更低点」 | 确认 4 → 先卖，不等反弹 |
| 2022-04-25 | 「今天刚出 5，我这里的策略**肯定只有空仓**」 | 5 浪初段 → 空仓/极低 |
| 2026-05-11 | 「一旦不好，然后配合指数高位跳水，这个时候不要想着抄底或者做防御或者高切低或者抗一抗，**第一个想法应该是，保命**」 | 高位 + 管控/平仓线/外部恶化 → 保命优先 |

| 2026-09-29 | 「长假那么大个不确定性，**我不赌**」 | 长假/事件前 → 降仓或不做 |

### 2.4 执行时序（他反复强调）

| 规则 | 原话/出处 | 落地 |
|---|---|---|
| 不在 13:00-14:30 止损 | 2026-03-23「每天的止损绝对不应该是下午 1 点到 2 点半这个时间……要么早上卖，要么尾盘卖」 | 执行窗口：09:35-10:30 / 14:30-14:55 |
| 急跌不割，反抽再走 | 2026-01-30「急跌不割肉，等反弹不行、重新下跌再考虑割」 | 先判“反抽失败”，再减 |

| 尾盘减仓 | 2026-08-21「2 点半，如果还是缩量、还是不拉升，先出来一半」 | 周五/事件前 14:30 减 T |
| 反抽失败降仓 | 2026-01-30「反抽上不了 4126 就把仓位减到 40% 以内」 | 反抽压力位不过 → 降档 |

### 2.5 低仓/空仓的心态（决定系统怎么提示）

> 2022-04-11：「现在不亏就是赚……你这次不亏的钱，在下一次机会来的时候就是你的本金。」

> 2022-04-12：「小级别服从大级别。我每次抄的时候都是大级别已经确认了的，就是安全的时候。」

> 2026-06-08：「上涨趋势，我买错了最多不涨；下跌阶段，我要做到全对才能赢。不划算。」

> 2026-08-11：「60% 仓位持仓。发呆。」

> 2026-08-17：「不加，目前 70%。」

结论：防御期的正确产出经常是**“今天不做”**，而不是“找到一个可以做的东西”。系统必须允许并主动输出“不做”。

## 3. 防御状态机（四档）

### 3.1 档位定义

| 档位 | 名称 | 总仓位目标 | 允许 | 禁止 | 解除/降级 |
|---|---|---|---|---|---|
| **G0** | 正常 | build 75 / 调整 50 | 按原策略建仓、加仓、做 T | — | 出现 G1 条件 |
| **G1** | 警戒 | ≤50% | 持有底仓；T 仓减半；不新开底仓；只做确定性 T | 追高、加仓、开新方向 | 放量修复 + 主线龙头恢复 → G0；恶化 → G2 |
| **G2** | 防御 | ≤30% | 保留主线核心底仓；T 仓只减不加；反抽减仓；**禁止加仓**（人工例外仅限 4-3 支撑+无硬触发） | 新开仓、加仓、补仓、杠杆、做题材 | 站回关键位 3 日 + 主线修复 → G1；破位 → G3 |
| **G3** | 空仓/极低 | **15%**（底仓 10 + T 5） | 只留核心 ETF/底仓（≤10）；T 仓 ≤5%；反抽继续减 | 一切新开、加仓、补仓、逆势 T、抄底 | 放量阳线 + 结构底 + 3 日站稳 → G2（不直接 G0） |

> G2 的 30% 对应「有风险就 30%」；G3 的 **15%** 对应「下跌趋势就不做」的底仓+T 仓口径。**G1 的 50% 对应「调整就 50%」**。
> 现有配置里 `exit=50` / `trade_graph` 的 `exit=70` 是**语义错误**（详见 §6.7），必须统一改成 **15%**。

### 3.2 触发条件（硬触发 = 程序判，软触发 = agent 判）

#### G1 警戒（满足任意 2 条）

|---|---|---|---|
| 1 | 指数距 60 日高 ≤3%，量能 <0.85×20 日均量，主线龙头滞涨 | 指数日线/ETF | 收盘或 14:50 |
| 2 | 两融余额 ≥ 近 3 年 90% 分位，且 5 日融资净额为负 | tushare margin | T-1（只做确认） |
| 3 | 银行 ETF 涨 >1.5% 而科技 ETF 跌 >1%，连续 2 日（跷跷板） | 512800 / 科创50 | 收盘 |
| 4 | 事件窗口 T-2（议息/非农/CPI/关税/谈判/长假） | 宏观日历 | 当日 |
| 5 | 账户回撤 ≥5%，或连续 3 笔亏损 | 账户 | 实时 |
| 6 | 顶部信号 ≥2 条（`wolf_top_signals`） | 指数/银行/券商 | 收盘 |

| 3 | `systemic_risk.level ≥1`（银行双头 + 科技不反） | systemic_risk.json | 15:05 |

| 6 | 顶部信号 ≥3 条 + 主线龙头破位 | wolf_top_signals | 收盘 |

| 3 | 关键长期位（3764 / 3674 / 年线）收盘跌破后，3 个交易日内未收回（as-of 今日已满足） | 指数 | 收盘 |

| 6 | 账户回撤 ≥12% | 账户 | 实时 |

> **段位闸门（程序执行）**：若 `wave_state` 判定为 4-3 筑底，且没有 G3 硬触发 → 防御档位**封顶 G1**，不允许仅凭价格弱升 G2。若 `wave_state` 缺失/陈旧 → 封顶 G1，输出两段式，等结构确认。agent 可以对“洗盘/破位”给意见，但不能推翻硬触发或段位闸门。

#### 软触发（agent 只判这些）

- 段位：4-3 筑底 / 4-4 反弹 / 4-5 下跌 / 下跌 1 浪 / 看不清。
- 性质：洗盘/诱空 vs 趋势破坏；割肉盘出清 vs 无承接。
- 龙头：主线龙头活着/死了；板块是退潮还是轮动。
- 保留清单：哪些是核心底仓、哪些是 T 仓/高位/拥挤/海外链。
- 对硬触发做“确认/证伪”：是一日噪音还是连续确认。

### 3.3 升级/降级路径

```
G0 ──(G1×2)──> G1 ──(G2硬触发 + 段位非4-3底)──> G2 ──(G3硬触发)──> G3
 ^              |                |                 |
 |              |(修复)          |(修复)           |(结构底+3日站稳)
 └──────────────┴────────────────┴─────────────────┘
        G3 只能降回 G2；G2 只能降回 G1；不跳级恢复
```

**关键闸门：段位前置。**

- 段位 = 4-3 筑底（缩量、割肉盘、下方有支撑）→ 防御档位**封顶 G1**；价格弱不等于 G2。
- 段位 = 4-4 反弹高位（滞涨、缩量、龙头不创新高）→ 可升 G1/G2。
- 段位 = 4-5 / 下跌 1 浪 → 可升 G2/G3。
- 段位 = 看不清 → **封顶 G1**，输出两段式（升级/降级条件）。

这条闸门直接来自 lessons §2.1 和 §10.7：**8/3 的“放量收最低”是割肉盘出清（买点），10/22 的“无承接恐慌盘”才是不能抄。** 防御系统如果把 8/3 判成 G2，就是根本性错误。

## 4. 仓位与减仓执行

### 4.0 防御的统一模型（2026-10-25 修正）

**破位减仓不是防御的同级兄弟，它本身就是防御的一条执行腿。**

正确的层级是：

```
防御（状态/目标：G0-G3，总仓上限）
  ├─ 硬止损/指数止损（最高 urgency，可把单票目标压到 0/50%）
  ├─ 破位减仓（platform/trend/neckline 破位，按 B1-B4 分级）
  ├─ T 仓减仓（防御性减 T / 去弱留强）
  ├─ 组合残余减仓（把总仓从当前压到 G 级目标）
  └─ 入场拦截（p2 gate / position_tier）
```

- **G 级**回答“总仓最多多少”；
- **破位/止损**回答“哪只票必须马上卖、卖多少”，是 **symbol override**；
- 两者组合：**先执行 symbol override，再算组合残余**；破位可以把目标压得比 G 级更严（例如 G2 30% 但某票破位 → 该票 0%）。
- 所以不存在“防御减仓 vs 破位减仓”的优先级之争；只有**同一防御政策下的多个执行腿**，要防的是**重复下单**，不是“谁听谁”。

### 4.1 桶级结构

按他 2026-04-14 的原话：

> 「50% 的底仓，30% 左右做日内或者一天到两天的 T，剩下 20% 左右应对黑天鹅的抄底。」

| 档位 | 底仓 | T 仓 | 现金 |
|---|---|---|---|
| G0 | 50% | 30% | 20% |
| G1 | 40% | 10% | 50% |
| G2 | 25% | 5% | 70% |
| G3 | **10%**（仅核心/ETF） | **5%** | **85%** |

> 这是**桶级上限**，不是单笔上限。单笔上限仍由现有 P3 档位（3%-10%）控制，不能把 50% 塞进一笔。

### 4.2 减仓顺序（从快到慢）

1. **撤买单 / 关自动加仓**（先停止失血）。
2. **T 仓**：先减 T，保护底仓；T+1 不能卖的记入明日计划。
3. **高位/拥挤/海外链**：先卖流动性好的、公募重仓的、海外映射的。
4. **弱势/杂毛/无量**：反弹到压力位减。
5. **核心底仓**：最后减，G2 保留主线核心，G3 只留 ETF/核心 ≤20%。
6. **保护 100 股底仓**：需要保留 T 资格时，底仓不低于 100 股。

> 依据：2026-09-04「高位方向卖强的、留弱的，拉升后都走；低位方向找辨识度最高老龙头，强的留、弱的丢。」
> 注意：高位方向“卖强留弱”是为了**先卖出流动性**；低位方向“去弱留强”是为了**留主升**。两者不矛盾，方向不同。

### 4.3 时间窗口

| 时点 | 动作 |
|---|---|
| 09:25-09:35 | 读取隔夜 defense_state；若 G2/G3，禁止新开，挂减仓条件单 |
| 09:35-10:30 | 反抽减仓窗口（他说的“早上卖”） |
| 13:00-14:30 | **不执行止损/不减仓**（他的硬规则）；只观察 |
| 14:30-14:40 | 尾盘决策：量能、黄白线、龙头 |
| 14:40-14:50 | 事实底稿 + agent 预览；G2/G3 执行减仓 |
| 14:50-14:55 | 尾盘代理确认（可当天走） |
| 15:00-15:10 | 收盘确认；写 `defense_state`；生成明日计划 |
| 周五 14:30 | 周末避险：G1+ 时 T 仓减半，目标 ≤65% |

### 4.4 品种差异

- **个股**：T+1，减仓按“可卖数量”；当日买入不可卖。
- **ETF**：部分 T+0（跨境/商品），但 A 股股票 ETF 多数 T+1；仍按可卖数量。
- **期货**：独立账户，不纳入股票防御减仓；但 G3 时禁止新开多单。
- **长线账户**：不参与 G1/G2 减仓；只在 G3 且逻辑破坏时减。

### 4.5 禁止动作（防御期）

- 补仓摊低成本；
- 用红利/银行“假防守”（他明确说拿 5 年红利也挣不回科技亏的钱）；
- 在下跌浪做正 T；
- 反抽追高；
- 用杠杆；
- 一天切三个方向（“亏损最大化”）。

## 5. Agent 设计（严格按 lessons）

### 5.1 事实底稿（程序算，只给事实）

```json
{
  "asof": "2026-10-16",
  "cutoff": "14:50",
  "mode": "intraday|after_hours|replay",
  "data_status": "ok|partial|missing",
  "index": {
    "sh_close": 0, "pct": 0, "ma5": 0, "ma13": 0, "ma20": 0, "ma60": 0,
    "vol_ratio_20d": 0, "off_60d_high_pct": 0, "pos_in_day_range_pct": 0,
    "key_levels": [{"price": 3764, "role": "4-3低", "state": "broken|holding|above"}]
  },
  "sectors": [{"name": "半导体", "pct": 0, "vol_ratio": 0, "leader_state": "alive|dead"}],
  "leaders": [{"code": "300308.SZ", "pct": 0, "broke_ma20": true, "big_black": false}],
  "margin": {"balance_yi": 0, "pct_3y": 0, "net_1d_yi": 0, "net_5d_yi": 0, "asof": "T-1"},
  "systemic_risk": {"level": 0, "alerts": []},
  "top_signals": {"count": 0, "hits": []},
  "wave": {"level": "", "sub_level": "", "operation": "", "stale": false},
  "account": {"exposure_pct": 0, "base_pct": 0, "t_pct": 0, "cash_pct": 0,
               "drawdown_pct": 0, "positions": []},
  "events": [{"name": "FOMC", "date": "", "days_to": 2}],
  "data_warnings": []
}
```

**原则**：同构（所有板块一行）、给演变不给切片、区分已出现/目标/待确认、能算的都给但不给结论、带单位。

### 5.2 判据（原话 → 条件）

给 agent 的判据不是“你觉得危险吗”，而是：

- 段位判据：4-3 筑底 = 缩量止跌 + 不破前低 + 割肉盘出清；4-5 = 破关键位 + 反抽不过 + 龙头死。
- 性质判据：洗盘 = 缩量、下影、龙头未死；破位 = 放量、收最低、龙头破位。
- 确认判据：一日噪音 vs 连续 2-3 日确认；收盘 vs 盘中。
- 反证条件：什么情况说明“这次判错了”（必须可观测）。

### 5.3 输出契约

```yaml
defense_level: G0|G1|G2|G3|undecided
level_pending: true|false
segment: 4-3|4-4|4-5|down1|undecided
nature: washout|breakdown|capitulation|no_bid|undecided
position_target_pct: 0-75
bucket_targets: {base: 0, t: 0, cash: 0}
action: observe|reduce_t|reduce_risk|reduce_all|hold
reduce_order: [symbol, ...]
keep: [symbol, ...]
hard_triggers: [...]
soft_triggers: [...]
upgrade_if: "条件句"
downgrade_if: "条件句"
invalidation: "条件句"
mode: intraday|after_hours|replay
data_warnings: [...]
```

**禁止**：打分、胜率、阈值触发式结论（“量比 ≥1.3 就清仓”）、让 agent 自选“第一档点位”。

### 5.4 程序校验（agent 之后）

- G0 不允许存在 G2/G3 硬触发；G3 必须至少 1 条 G3 硬触发（不能只凭 agent 感觉）。
- `position_target_pct` 必须等于档位表，或更保守；不能更激进。
- `reduce_order` 标的必须存在、可卖数量 >0、T+1 可卖。
- `keep` 不能包含已破位的 T 仓。
- 所有事实的 `asof` 必须 ≤ cutoff；两融必须标 T-1。
- 幂等键：`date + level + symbol + reason_hash`，重复不执行。
- 不通过 → 拒绝执行 + 告警，不静默降级。

### 5.5 提示词骨架（不是全文）

```
你是防御档位判断器。只判“段位/性质/档位建议”，不选点位、不打分。
硬触发由程序给出，你不得推翻；你只能在硬触发允许的范围内选择更保守的档位。
若段位无法确定，输出 undecided + 升级/降级条件 + 反证，不要硬判。
防御期的正确产出可以是“今天不做”。
```

### 5.6 Agent 的失败模式（提前写清）

| 失败 | 表现 | 防法 |
|---|---|---|
| 把 4-3 底部判成破位 | 8/3 割肉盘出清被误杀 | 段位前置 + 判例回归 |
| 把一日噪音当趋势 | 频繁 G1/G2 切换 | 连续 2 日确认 + 变更静默 |
| 用未来数据 | 用次日反包确认今天 | PIT + 两日状态机 |
| 自证 | agent 写状态又读状态 | 程序写、agent 只读；人可否决 |
| 过度解释 | 每天一篇长文 | 稳定键 + 只在档位变化时推送 |
| 数据缺失硬凑 | 用昨日数据冒充今日 | `data_status=missing` + 非零退出 |

### 7.2 盲测与留出

- **盲测**：把事实底稿给全新会话，不给日期/标签，只给判据；看它是否判出档位与反证。
- **留出**：2022 训练、2025 验证、2026 测试（或反过来）；留出期不参与阈值调整。
- **换品种**：上证、沪深300、科创50、半导体 ETF、创业板各跑一遍；不能只在单一品种上成立。
- **失败样例优先**：每次修正必须来自一个具体误判，而不是“想得更周全”。

### 7.3 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 最大回撤规避 | 防御期组合回撤 vs 不止损 | 显著低 |
| 误杀率 | 把买点判成 G2/G3 的比例 | 0（8/3、8/12 必须过） |
| 空仓时间 | G3 天数占比 | 只在真下跌浪，不长期空转 |
| 切换频率 | G1/G2/G3 往返次数 | 低（避免打脸式降仓） |
| 执行滑点 | 计划价 vs 成交价 | 可接受 |
| 告警准确率 | 推送中“真需要动作”的比例 | 高（避免每天推一样） |

### 7.4 反证条件（每条判断都要带）

- “如果次日放量站回 X，则本次 G2 判错。”
- “如果 4-3 低点未破且缩量止跌，则不得升 G2。”
- “如果两融未连续流出、龙头未破位，则 G3 不成立。”
- “如果数据缺失，则本次结论作废，不执行。”

## 8. 风险与不做的事

### 不做

- 不预测顶/底；只做“已发生 + 确认”。
- 不让 agent 选“第一档点位”；程序给候选，人保留否决。
- 不自动清长线账户。
- 不在 13:00-14:30 执行减仓。
- 不用单日形态直接 G3；必须段位 + 确认。
- 不把“红利/银行”当防御方向（他明确反对）。
- 不把期货纳入股票防御减仓（独立账户）。

### 风险

1. **误杀底部**：4-3 筑底的价格弱、放量收最低，最容易被判成 G2。段位闸门是命门。
2. **数据时滞**：两融 T-1、北向缺失、ETF 份额不实时 → 只能做确认，不能做日内扳机。
3. **反复打脸**：G1/G2 频繁切换会让人屏蔽通知；用连续 2 日确认 + 稳定键。
4. **执行滑点**：跌停/流动性差时卖不出；减仓计划要分档、留第二天。
5. **规则膨胀**：现有防御模块已经很多，再堆规则会互相打架；`defense_cash` 只做仲裁，不重复实现。

## 11. 一句话总结

**防御不是“清仓”一个动作，而是“先定段位，再定档位，再定减谁”。**
程序负责“够不够格”（硬触发、仓位上限、可卖数量），agent 负责“这是什么”（段位、性质、保留清单），人保留否决权。
**最重要的不是多聪明，而是别把 4-3 底部的割肉盘，当成高位派发。**
