## 结论

- **32 次里 0 次完全符合账本**：没有一次同时满足“同日 + 同点位 + 同目标 + 同时点”。
- **约 8 次方向或位置相近**（05-15、06-13、08-27、09-04、11-18、11-21、12-11、03-20），但点位/目标/方法至少一项不符。
- **其余 24 次账本没有对应指数止损条件**，其中 5 次账本当天/邻日明确是“不卖/买/不用慌”（04-07、10-17、03-19、04-02、07-02 等）。
- 根因不是“回测算错”，是 **v3_break 本来就不是账本规则**：它用 PointEngine 的关键位 + `tier_target_pct(side)=50%`，账本用的是具体点位（3922/3900/3888/3850/3731/3950…）和条件式仓位（40/20/35/30/60）。
- 所以 **不能用这次 v3_break 回测证明或否证狼大的止损规则**；它只能说明“另一套 50% 减仓机制”在这段数据上的表现。

## 方法论复盘：这轮又犯了 `ai-agent-lessons-from-b-rebound.md` 里的错

| 教训 | 这轮的实际行为 |
|---|---|
| §2.1 用「形态」代替「位置」 | 只要收盘破 PointEngine 关键位就减 50%，不看 wave 段位；同一形态在下跌末段/主升中段含义相反 |
| §2.2 把「描述」当「筛选器」 | 把“关键位”当成通用筛选器，全历史扫出 32 个事件；其中 24 个账本根本没有对应条件 |
| §2.3 自设规则，把专家判例挡在门外 | 为了让回测能跑，把目标固定成 `tier_target_pct(side)=50%`；账本的 40/20/35/30/60 全被替换掉，0/32 符合 |
| §4.4 失败样例 > 成功样例 | 没有先拿账本判例做“误杀测试”；2025-04-07（他在买）、2025-10-17（他说不用慌）、2026-03-19（他说不在低点割）都被 v3 卖了 |
| §9.2 每加一条规则，先过专家已知判例 | 先写 v3、再回测，顺序反了；应该是“账本判例 → 规则 → 回测” |
| §10.8 抓「改判的触发句」，不要抓结论 | 用了泛化的“破关键位”，没抓账本里的条件句：收盘/放量/3×15min/前低/时点门 |
| §10.9 让他的点位校验我们的结构标注 | 只校验了 PointEngine 能否算出附近点位，没校验“这个点位是否是他当天真正会操作的点” |

**更严格的 D 组判例对照**：[ledger-stop-cases-vs-v3.md](ledger-stop-cases-vs-v3.md)。17 条里 7 条未触发；8 条本人触发动作中 **0 条完全符合**（5 漏 / 1 反 / 2 部分）；事件研究见 [ledger-event-study.md](ledger-event-study.md)。

**结论**：这轮回测的方法论是错的，不只是参数不对。`v3_break` 的收益/回撤数字**不能用于评价狼大**；它测的是另一套“关键位 + 固定 50%”的机制。
