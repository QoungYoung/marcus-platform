# `data/wave_state_history` 缺陷报告（待修）

> 提出方：B反 研究会话（2026-10-23）
> 复现环境：`/home/fengx/marcus-platform`，样本 `data/wave_state_history/*.json` **433 份**，`20250102 → 20261020`
> 影响面：任何消费 `level / sub_level / features.{origin,wave1_top,prior_peak,sub_legs}` 的地方（研究回测、日报、决策对象）

---

## 0. 一句话

**浪型的「腿」（`sub_legs` 的数值）是可信的；出问题的是「锚点」和「标签」。**
腿的数值 2,009 条无一越界（全部落在当日指数高低区间内），但 `origin / wave1_top` 会**换含义**，`level / sub_level` 会在**腿已陈旧**的情况下继续外推。

---

## 1. 五个具体缺陷

### A. 锚点会换（最严重）

`features.origin` 与 `features.wave1_top` 在 2026-06-05 整体切换，2026-10-20 又切回：

```
20250102 – 20260604   origin=2702.18   wave1_top=3174.27   （343 份）
20260605 – 20261019   origin=2704.09   wave1_top=3674.40   （ 90 份）
20261020              origin=2702.18   wave1_top=3174.27   （  1 份，又退回）
```

同一个字段（`wave1_top`）在两个数值间切换，含义是「1 浪顶」。**跨期使用这个字段的任何逻辑都会得到互相矛盾的结论**：
- 以 3174 为 1 浪顶 ⇒ 2702→3174→4243 的划分；
- 以 3674 为 1 浪顶 ⇒ 2704→3674→4259 的划分（这个是和狼大原话一致的：他说「下跌 1 浪最低点判断到 3674」）。

复现：
```bash
python - <<'PY'
import json,glob,os
prev=None
for f in sorted(glob.glob('data/wave_state_history/*.json')):
    j=json.load(open(f)); ft=j['features']
    k=(round(ft['origin'],2),round(ft['wave1_top'],2))
    if k!=prev: print(os.path.basename(f)[:8],k); prev=k
PY
```

### B. 腿陈旧，但标签照旧外推

```
最后一腿距快照 > 200 天：230 / 433 份（53%）
最后一腿距快照 > 400 天： 98 / 433 份（23%）
```

典型例子 `20260615.json`：

```
level=down  sub_level=下跌1浪  operation=defense  confidence=0.8
sub_legs: 4-1d 3169.38(20241017) · 4-2u 3509.82(20241108) · 4-3d 3259.76(20241126)
          · 4-4u 3464.12(20241212) · 4-5d 3160.76(20250113)
```

**腿结束于 2025-01-13（距今 518 天），却给出「下跌 1 浪、防御」的结论。** 而当天指数 4096、距高点仅 −3.8%。直接采信会得出荒谬判断。

### C. `1 浪顶 == 前高`，自相矛盾（29 份）

```
20260605  wave1_top=3674.4048  prior_peak=3674.4048
20260608 … 20260611 同上
```

同一份快照里「1 浪顶」与「前一轮顶」是同一个价格，意味着浪型划分为「1 浪顶就是全轮最高点」，逻辑上不成立（且当时前高明明是 4259）。

### D. `sub_level` 混入非层级取值（枚举不封闭）

```
'4-2→4-3'  ：20260720–20260723 共 4 份（过渡方向被当成档位）
'末段'      ：20250814、0827、0918、1114、20260114、0303、0514 等 7 份
'C杀'       ：20250407
```

`sub_level` 的合法取值应是档位（`4-1/4-3/4-5/失败5/下跌1浪/3-3…`）。写进「过渡串」或「状态词」后，**任何按 sub_level 分类/统计的消费方都会静默错分**。

### E. `sub_level` 日间翻转 62 / 433（14%）

其中 `4-3 ↔ 4-5` 的抖动最影响下游（`4-3` 往往被读成"筑底可接"，`4-5` 被读成"等失败 5"）。

---

## 2. 根因假设（供修复方验证，不是结论）

1. **A 的直接原因**：`origin` 的选法依赖「哪一段算整轮起点」。2024-02-05 的 2635 与 2024-09-13 的 2704 都能自圆其说（后者才是 924 政策底）。2026-06-05 的切换像是**改了起点判定规则或数据窗口**，2026-10-20 又回退了一次。
2. **B 的原因**：`sub_legs` 只在「确认新的转折」时追加；当行情没有确认转折时腿不更新，但 `level/sub_level` 仍按当前价格外推 ⇒ **标签与腿脱钩**。
3. **C 的原因**：重建锚点时把「本轮的 1 浪顶」与「历史最高」混用（可能在同一函数里复用了变量）。
4. **D 的原因**：某个分支把"迁移描述"直接写进了 `sub_level`，而不是写进 `transition` 之类的独立字段。

---

## 3. 修复的验收标准（建议）

| # | 要求 | 检查方式 |
|---|---|---|
| 1 | **锚点单调**：同一轮行情内 `origin / wave1_top` 不得变化；确需修订时写 `anchor_revision`（含旧值、生效日、原因），并保留旧值 | 复现脚本 A 的输出里不得出现回切 |
| 2 | **陈旧即降级**：最后一腿距快照 > N 天（建议 120）时，置 `stale=true`，且**不再输出** `level/sub_level`（或标 `undetermined`） | 扫 433 份，`stale` 与 `sub_level` 不得同时为真 |
| 3 | **`wave1_top != prior_peak`** | 断言 `abs(diff) > 1` |
| 4 | **`sub_level` 枚举封闭**：只允许档位值；过渡/状态写入新字段（如 `transition`、`phase_note`） | 白名单校验，非法值报错而非静默写入 |
| 5 | **保留 `sub_legs` 数值** | 现状 2009 条腿 0 越界，是全份数据里最可信的部分，重建时不要丢 |
| 6 | **as-of 与 latest 双视图** | 每次重算写 `revision`，历史快照不可被覆盖（现在按日期一文件，重算会覆盖当日文件） |

---

## 4. 对下游的具体影响（修复方需要知道的后果）

1. **任何拿 `sub_level` 当特征的回测都是噪声**。我实测过：把它加分进打分卡，效果不升反降；全连乘时反而更差。原因就是上面的 A/B/E。
2. **不能在历史日期上读"级别"**：`20260615` 这类快照会给出与当时行情完全不符的结论。
3. **狼大的 3674 与快照的 3674 不是同源**：他说「下跌 1 浪最低点 3674」是**他的判断**；快照直到 2026-06-05 才对齐到 3674，之前的 343 份都是 3174。**不要把"快照对齐了"误当成"快照预测对了"。**
4. 目前研究脚本（`scripts/brebound_read.py`）已经加了三条自洽检查作为临时护栏（陈旧 / 1浪顶==前高 / 腿<2），**自洽检查不过就退回价格摆动，不用快照标签**。修复后可移除。
