# PointResolver 盲测（4 个 case / 10 个点位）

> 目的：验证 agent 能否从**候选结构表**里判断“他说的点是哪类结构、什么角色”，而不是直接采用数字。
> 盲测：只给候选表 + 他的原话 + 当日/前 5 根日线 + 均线；不给手工溯源结论。
> 注意：候选表已带 `type` 标签，所以这次测的是**选择/角色/术语判断**，不是“从裸 K 线发现结构”。

## 2. 通过的点

1. **10/10 都找到了对应候选**，没有编造候选表以外的价格。
2. **R11 的“趋势线”被标成 `not_supported`**：agent 明确说“候选表里没有 3922 附近的 trendline，数据上更像 11/5 前低 + 10/24 缺口”。这是本次最关键的一项。
3. **R10 的 3900 被识别为四重合流**：趋势线 3901.2 + 整数 3900 + MA60 3898.66 + 前高 3899.96；不是单因子。
4. **R12 的 3850 没有被硬说成强结构**：agent 标为 `round`，并指出下方只有 3839.97 缺口；符合“整数为主”。
5. **R12 的 3816 精确命中平台低点 3816.58**。
6. **R04 的 3370/3375 被还原成 3365-3377 的合流带**，不是两个精确点。

## 3. 没通过/要修的点

1. **PIT 违规**：R10 的 3900 case 日期是 11/21，但候选 `c10 trendline` 的 date 写的是 **11/24**（我们准备数据时按 11/24 投影）。agent 直接用了，没有检查“候选日期不能晚于 case 日期”。这是输入/校验的错，不是 agent 的推理错，但必须加校验。
2. **role 口径不统一**：R10 3900 标 `support`，R11 3922 标 `reclaim`，R12 3888/3922/3930 标 `reclaim`。同样是“已跌破的位”，角色命名不一致；需要固定枚举和定义。
3. **R04 3375 的 role=unclear**：他的原话里 3375 没被明确命名，agent 保守标 unclear，这是对的；但落地时需要人确认它是否算“同一带”。
4. **它依赖候选表的 type 标签**：这次不是“从裸 K 线发现结构”，而是“在已标注候选里选”。下一步要做**去标签盲测**（只给 id/value/date，让 agent 自己判断类型），才算真正验证。

## 4. 结论

**这次可以下结论：agent 适合做“选点/角色/术语”的判断层，不适合做“算价格”的计算层。**

- 算候选：程序；
- 选哪个/叫什么/什么角色：agent（本次 10/10 找到合流，1 条术语不一致被抓出）；
- 校验：程序（ID 存在、日期不晚于 case、zone 包含 quoted、type/role 白名单）；
- 最终确认：人。

## 5. 下一步

1. 加 **CandidateValidator**：候选日期 ≤ case 日期；ID 必须存在；zone 必须包含 quoted；禁止候选表外价格。
2. 固定 **role 枚举**：`support_holding | support_broken | resistance | reclaim_threshold | invalidation`。
3. 做 **无标签盲测**：只给 `id/value/date`，让 agent 判类型；如果还能识别 3900 是趋势线+前高+MA60、3922 是前低+缺口，才算真能“找点位”。
4. 通过后再接 case engine；仍然只读，不下单。

## 6. 测试有效性审计（必须看）

这次 10/10 **不能当成“agent 能找到他的点位”的证据**，因为候选表本身是我手工构造的：

1. **不是全部由 `point_engine` 生成**
   候选表里混入了我用诊断脚本另算的 MA20/MA34/摆动低点/缺口/整数（R04 的 MA20/MA34/摆动低点、R10 的 3922 前低/缺口、R12 的 3888 前低/缺口等）。完整 `point_engine` 在这些日期并没有输出这些结构。

2. **按答案 ±0.6% 筛过**
   生成候选时用了 `abs(value - quoted)/quoted <= 0.006` 的过滤——等于先把答案周围的选项挑出来再让 agent 选。这是典型的“把描述当筛选器”。

3. **有未来数据**
   R10 的 3900 用了 11/24 投影的趋势线 3901.2，而 case 日期是 11/21；agent 没检查日期，我也没在输入里拦住。

4. **R11 的“趋势线不成立”有一半是构造出来的**
   R11 候选表里我**没有放任何 trendline 候选**，agent 当然会说“没有 trendline”。这不等于它独立发现了“3922 不是趋势线”。

5. **引擎的真实覆盖更差**
   同日完整 `point_engine`：
   - R04：12 个点，3370 附近只有 neckline 3361.74/3388.78；
   - R10：29 个点，3922 附近只有 neckline 3936.58/3899.96；
   - R11：30 个点，3922 附近只有 gap 3912.01/neckline 3936.58；
   - R12：30 个点，3888 附近只有 neckline 3885.31；3816 倒是有平台低点 3816.58。

   说明真正的短板首先是**候选生成不全**，不是 agent 选不出来。

**修正结论**：这次只证明了“agent 能在一张手工短名单里做选择/描述”，没有证明“它能从引擎候选/裸 K 线里找到他的点”。要重做：
- 用完整 `point_engine` 输出，不按 quoted 过滤；
- 不给 type 标签（或至少做无标签组）；
- 加 PIT 校验；
- 先量引擎召回：他的点位在不在候选里；不在，先修引擎，不让 agent 背锅。
